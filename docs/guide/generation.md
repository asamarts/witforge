# Generation

## Commands

```sh
witforge rust wit --out generated/rust
witforge proto wit --out generated/proto
witforge schema wit --out generated/schema
witforge glue wit --out generated/glue \
  --plain-root crate::plain \
  --proto-root crate::proto
```

`--plain-root` and `--proto-root` are absolute Rust module paths used by generated glue (not filesystem paths). Accepted forms are `crate`, `crate::...`, `::crate_name::...`, or an external crate name (`other::...`). Relative paths starting with `self` or `super` are refused because glue references the roots from nested modules at multiple depths; write `crate::...` for modules inside your own crate, and prefix an external crate with `::` if its name matches a generated module. The same rules apply to `plain-root` and `proto-root` in `witforge.toml`.

## Configuration

```toml
version = 1

[project.example]
root = "wit"

[project.example.rust]
out = "generated/rust"
serde = true

[project.example.proto]
out = "generated/proto"

[project.example.schema]
out = "generated/schema"

[project.example.glue]
out = "generated/glue"
plain-root = "crate::plain"
proto-root = "crate::proto"
```

Then run:

```sh
witforge rust --config witforge.toml
witforge proto --config witforge.toml
witforge schema --config witforge.toml
witforge glue --config witforge.toml
```

Paths inside `witforge.toml` (`root`, `released`, and every `out`) are resolved relative to the
configuration file (or used as given when absolute, including `..` components) and are never
shell-expanded: a path starting with `~` or containing `$` or `%VAR%` is refused with exit `2`.
Save `witforge.toml` as UTF-8 without a byte-order mark (BOM); `wit/released` is accepted with or
without a leading UTF-8 BOM.

Under a WIT root, every entry whose name starts with `v` or `V` followed by a digit must be a
valid `v<major>.<minor>` directory (for example `v0.1`, `v1.0`). Near-miss directories or files
such as `v0.2.0`, `V0.2`, `v0.2-rc1`, `v00.2`, `v1`, or overflowing version numbers are refused
rather than silently skipped; unrelated entries such as `vendor`, `versions.md`, `released`, and
hidden files are ignored.

## Output ownership

Each emitter and project needs its own non-overlapping output directory. Every generated file starts with an ownership header naming both the generator and the contract (`// @generated by witforge (rust, example:plugin); do not edit.`, or the matching JSON Schema `$comment` prefix). A generator only overwrites or removes files that carry its own header (or the legacy pre-0.6.0 shared header, which is adopted and rewritten when you regenerate).

- An output directory that already holds files from another generator or another contract is refused with exit `2` before anything is written.
- A `witforge.toml` configuration whose `out` paths coincide or nest (including across projects or through symlinks) is refused as a usage error (exit `2`).
- Symlinks, directories, and unowned files at expected output paths are refused; unowned files at other paths are left untouched.
- Every generator supports `--check`, which writes nothing and fails on missing, changed, or extra generated files (and exits `2` if a foreign generator's or contract's file is present).
