# witforge plan

This directory is the source of truth for task-level planning, dependencies, and
evidence. The narrative sequence stays in [`../ROADMAP.md`](../ROADMAP.md); the
plan here says what can start, what is blocked, and what proof closes a task.

- Task files: `aplan/tasks/*.md` (Markdown + YAML frontmatter).
- Policy: [`../.aplan.yml`](../.aplan.yml).
- Agent contract: [`../AGENTS.md`](../AGENTS.md), generated by
  `aplan export-agents-md --write AGENTS.md`.
- Pilot/dogfooding notes: [`../docs/aplan-pilot.md`](../docs/aplan-pilot.md).

## Conventions

- Task IDs: `W<phase>-<nnn>` (`W1-003`).
- Phase/cut milestones: `M-p<N>` with the cut label `p<N>` (`M-p1`, `p1`).
- Every non-milestone task belongs to exactly one cut.
- Code tasks close on a named `cargo test`; `untestable` is a claim that no test
  could fail if the work were reverted, and the body says why.
- `deny_warnings` is on: every finding blocks.

## Commands

```sh
aplan check                    # validate the plan
aplan verify                   # resolve evidence against this repository
aplan ready                    # what can start now
aplan show W1-001              # one task, its edges and findings
aplan why W1-001               # what is blocking it
aplan roadmap                  # cut rollups and critical path
aplan summary                  # effort/readiness by phase
aplan export-agents-md --check AGENTS.md
```

`aplan` is a local tool and CI must not assume it is present on the self-hosted
runner yet. Run `aplan check` and `aplan verify` before committing plan changes;
the CI gate is tracked as a task.
