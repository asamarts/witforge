## Why

W11-036 covers required removal, direct defaultable removal, rename, and multiple affected
types. Three cases remain unproved: a removed required field whose type is a named alias or
named structural `option`/`list` (no note), multiple missing required members in one record
(the first target member is named deterministically), and a non-adjacent version pair (the
documented contract-level consequence). The canonical-form boundary also deserves a test so
`diff` and `check` do not drift.

## Acceptance criteria

- [x] a named alias or named structural defaultable removal emits no conversion-impact note
- [x] a record with multiple missing required members emits one deterministic note naming the
      first member in the older type's declaration order
- [x] a non-adjacent version pair follows the documented behavior
- [x] a non-canonical but current lockfile remains accepted by a direct `diff` endpoint, and
      the boundary is documented
- [x] `cargo test -p witforge-cli --test diff` and the full workspace suite pass

## Verification

Close on the new edge-case tests.

- `compare_with_impacts_matches_compare_on_the_versions_fixture` covers the additive library
  API.
- `diff_does_not_note_named_defaultable_removals`, `diff_notes_the_first_missing_required_member`,
  `diff_notes_contract_level_failures_for_non_adjacent_versions`, and
  `diff_accepts_a_non_canonical_but_current_lockfile` cover the CLI edge cases.
