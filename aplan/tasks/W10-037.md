## Why

The Action uses `fetch` for the latest release and asset downloads without an abort timeout,
so a stalled network can hang until the job timeout. Local repository tests and CI helpers use
`std::env::temp_dir()`/`${TMPDIR:-/tmp}`, which on this shared host can consume the shared
tmpfs unless `TMPDIR=~/.tmp` is set.

## Acceptance criteria

- [x] Action latest-release and download requests have a bounded timeout/abort path
- [x] a unit test or existing Action smoke covers the timeout helper or records why only the
      hosted Action run can prove it
- [x] `ci/README.md` documents `TMPDIR=~/.tmp` for local test runs or a test scratch helper
      removes the need
- [x] action tests, actionlint, shellcheck, and the full suite pass

## Why it is untestable

This is CI-only JavaScript and documentation. The timeout helper has `node:test` cases and the
hosted Action smoke covers the installed path, but the configured aplan runners are the Rust
`witforge` and `witforge-cli` test suites; no configured cargo test changes when only the Action
or its documentation changes.

## Verification

- `requests carry a bounded abort signal and authorization` and
  `requests abort when the timeout expires` in `action/test.js`.
- `node --test action/test.js`, `actionlint`, `shellcheck`, the full workspace suite, generated
  output, release checks, security, and aplan gates pass.
