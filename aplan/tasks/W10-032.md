## Why

`docs/guide/generated-output.md` says its excerpts are exact, and the README copies
emitter output, but no test compares those snippets with committed example files. Separately
`ci/check-release.sh` verifies Cargo metadata, changelog, and tag but not README/docs/Action
version references, so a missed current-version update is caught only by manual review.

## Acceptance criteria

- [x] exact generated-output snippets in the docs/README are checked against the committed
      example output, or the copies are replaced by links with a link check
- [x] `ci/check-release.sh` (or a tested companion script) rejects a README/docs/Action
      current-version reference that disagrees with the workspace version
- [x] the new check has a regression test and runs in CI
- [x] the full suite and release-check script pass

## Verification

- `generated_output_guide_snippets_are_current` checks the generated-output guide's Rust,
  protobuf, JSON Schema, glue, and conversion excerpts against `examples/single` and
  `examples/evolved`.
- `readme_output_snippets_are_current` generates from the README's WIT block and checks its Rust
  and protobuf excerpts.
- `bash ci/test-release-version.sh` exercises every current-version pattern and rejects a
  mismatch in each.
- `ci/check-release.sh` runs the version-reference checker; the main CI `generated` job runs it
  without a tag, and the `workflows` job runs the regression test.
- `cargo test --workspace --locked` (229 tests), MSRV 1.88, Clippy, rustdoc, generated output,
  release freeze, security, semver, fuzz manifest checks, the release scripts, and aplan gates
  pass.
