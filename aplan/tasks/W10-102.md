## Why

Audit findings F-01 and F-13:
1. In 0.7.0, `action/index.js` runs `gh attestation verify` whenever `version >= 0.7.0`, but `action.yml` defaults `github-token` to `''`. On GitHub-hosted runners `gh` is preinstalled without `GH_TOKEN`, so workflows omitting `github-token` (including README and action.md examples) fail install with exit 4.
2. `action.yml` and `docs/design/action.md` claim `config` supports `check`, but `buildCommands` never passes `--config` to `witforge check`. Multi-project configs without `project:` also fail in `generators` because per-emitter commands require `--project` while `witforge generate --check` handles all projects.

## Decision

- Default `github-token` in `action.yml` to `${{ github.token }}` while keeping release-asset downloads unauthenticated, improve the error if `gh` is unauthenticated, and add a CI smoke step omitting `github-token:`.
- Add `check: "true"` (`witforge check --config ...`) and `generators: "all"` (`witforge generate --config ... --check`), preserving `generators` default `'rust'` for backward compatibility.

- [x] `action/test.js` covers default token handling, `check: "true"`, and `generators: "all"`
- [x] `.github/workflows/ci.yml` includes a local Action smoke step that omits `github-token:`
