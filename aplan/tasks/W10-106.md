## Why

Audit findings F-05, F-12, F-14, F-17, and F-18:
1. `witforge release` only runs single-directory `check`, permanently recording root-invalid versions (mismatched package name or invalid `@since` history) into `released`, and falls back to default `released` when a non-existent explicit `--released` path is passed.
2. `workflow::check` compares `--against` dependency graphs in reversed order (`&model, &baseline`), and `workflow::check_root` double-loads every version and emits duplicate contradictory `WF1033` diagnostics.
3. `witforge new-version`'s `rewrite_package_version` fails silently on nested WIT block comments and multi-line `package` headers.
4. Relative SARIF `artifactLocation.uri` values do not percent-encode spaces, and `action/index.js` passes raw `file:///` SARIF URIs into workflow annotations.
5. `check_command`'s `CheckTargetKind::Neither` branch contains unreachable dead code.

## Decision

- Validate root package identity, `@since` history, and retirement order in `witforge release` before appending, and avoid falling back to the default manifest when an explicit `--released` path does not exist yet.
- Fix argument order in `workflow::check`, reuse loaded models in `workflow::check_root`, and emit one `WF1033` per mismatch.
- Upgrade `rewrite_package_version` to track nested block comments and multi-line `package` headers, failing if no header was updated.
- Percent-encode relative SARIF URIs and normalize `file://` URIs in Action SARIF annotations.
- Clean up dead code in `check_command`.

## Acceptance criteria

- [ ] `witforge release` rejects mismatched package names and invalid `@since` history before writing `released`
- [ ] `workflow::check` reports dependency graph diffs in `baseline -> current` order; `check_root` emits one `WF1033` per mismatch without double-loading
- [ ] `witforge new-version` rewrites headers after nested block comments and across multi-line `package` declarations
- [ ] Relative SARIF URIs percent-encode spaces and Action annotations handle `file:///` URIs cleanly
