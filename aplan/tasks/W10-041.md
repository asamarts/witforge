## Why

Audit finding E4 (medium). `ci.yml:210` and `release.yml:86` run
`cargo semver-checks … --baseline-version 0.4.1`, and the buf loops (`ci.yml:329-334`,
`release.yml:106-111`, `ci/check-buf.sh:17`) stop at `v0.4.1`, although 0.4.2, 0.4.3, 0.4.4,
and 0.5.0 have shipped. The public `diff` API added in 0.5.0 is not protected by the semver
gate, and generated protobuf output of the four later releases is not in the compatibility
comparison. `docs/design/release-1.0.md` and `docs/design/conformance.md` name the same stale
baseline.

## Acceptance criteria

- [x] the semver baseline is the latest published release. No baseline is named any more:
      cargo-semver-checks picks the newest release on crates.io that is not newer than the
      workspace version, so there is no step to forget. The checklist says so.
- [x] the buf comparison includes every published release: `ci/check-buf-history.sh` walks every
      `vX.Y.Z` tag and every fixture WIT root
- [x] `release-1.0.md` and `conformance.md` agree with the workflows

## Verification

Run locally on 2026-11-18 with the CI-pinned tools (cargo-semver-checks 0.51.0, buf 1.74.0):

- `cargo semver-checks check-release -p witforge --release-type minor` selected 0.5.0 as the
  baseline and passed 202 checks;
- `BUF_REQUIRED=1 ci/check-buf-history.sh` passed for 6 fixture roots against 11 releases
  (`v0.1.0` to `v0.5.0`); a fixture that did not exist at a release is skipped.

The hosted `buf` job runs on workflow dispatch and in the release workflow; it has not run on a
hosted runner with this change.

## Why it is untestable

These are workflow and script parameters; no cargo test fails if they are reverted.
