## Why

Audit findings C10 and C11 (low to medium).

- Re-run 2026-11-18: regenerating over a file with mode 0600 leaves it 0644 with a new
  inode, although the content is identical. Every run rewrites every file, which defeats
  build caches keyed on modification time.
- Reviewer-run: an unreadable, unrelated file in the output root aborts the run; two
  concurrent runs into one root may remove each other's temporary files (suspected, not
  demonstrated).
- Re-run in the first audit pass: `--check` prints only "changed generated file" for a stale
  file, with no diff and no command to fix it.

## Edge cases

- Unchanged content: no write, and the modification time and inode stay.
- Changed content: the replacement keeps the permission bits of the file it
  replaces. A new file gets the default mode under the process umask.
- A read-only file whose content must change. Replacing by rename works when the
  directory is writable; decide whether to replace it or to stop, and test it.
- Things in the output root that are not regular files: a directory, a dangling
  symlink, and a FIFO, which must not be opened, because reading one blocks.
- An unreadable file without a header is skipped. An unreadable file that the plan
  needs to replace is an error that names it.
- The header probe reads a bounded prefix, not the file.
- Temporary names are unique per process and are removed when a run fails. A
  temporary file left by a killed run is recognised by its name and removed by
  the next run, or left; state which.
- Two runs into one root at once: each file ends complete from one of them, and
  neither removes the other's temporary files.
- `--check` output for a changed file: the path, the first differing line with
  both versions of it, and the command that regenerates, with the configuration
  and project that were used. For a missing and for an extra file it says which.
- A file that differs only in line endings, as after a checkout with
  `core.autocrlf`, is reported as changed, with a hint about line endings.
- `--diff` prints a unified diff and does not change the exit status.

## Acceptance criteria

- [x] a file whose content is already correct is not rewritten
- [x] a replaced file keeps its mode
- [x] files without the generator's header are never read beyond the header probe, and an
      unreadable one is not an error
- [x] temporary names are unique per process
- [x] `--check` names the generating command and, for a changed file, the first differing
      line; a `--diff` option prints a unified diff
