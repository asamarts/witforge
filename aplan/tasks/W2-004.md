## Why

Development versions need draft semantics; released versions must be frozen. The
current conservative lock cannot distinguish the two.

## Acceptance criteria

- [ ] `--first` treats entries as drafts
- [ ] `--against` classifies current entries by the previous lockfile
- [ ] draft renames/removals/retypes update or drop entries
- [ ] released type/kind changes, renumbering, and reintroduction fail
- [ ] `wit/released` is validated and `lock` refuses a released directory
- [ ] a two-version fixture proves the lifecycle
