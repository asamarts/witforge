## Why

Development versions need draft semantics; released versions must be frozen. The
current conservative lock cannot distinguish the two.

## Acceptance criteria

- [x] `--first` treats entries as drafts
- [x] `--against` classifies current entries by the previous lockfile
- [x] draft renames/removals/retypes update or drop entries
- [x] released type/kind changes, renumbering, and reintroduction fail
- [x] `wit/released` is validated and `lock` refuses a released directory
- [x] unit scenarios prove the draft/release lifecycle; the committed two-version fixture is added by W2-006
