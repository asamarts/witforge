## Why

Consumers running both native/out-of-process transports (witforge plain Rust + protobuf) and Wasm Component Model plugins (`wit-bindgen` / `wasmtime::component::bindgen!`) currently hand-write field-by-field conversions between the two distinct Rust type hierarchies generated from the same WIT.

## Acceptance criteria

- [ ] Measure conversion boilerplate in a real hybrid native + Component Model consumer
- [ ] Decide whether an opt-in bridge emitter (`--bindgen-root`) reduces maintenance without fragile coupling to upstream `wit-bindgen` naming, or record a decline with revisit trigger
