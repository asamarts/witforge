## Why

TypeScript teams consuming WIT contracts currently depend on `jco` (coupled to WebAssembly Component Model runtimes) or raw protobuf classes. A built-in `witforge ts` emitter produces clean, zero-dependency strict ESM TypeScript interfaces, discriminated unions, and per-version modules directly from WIT.

## Acceptance criteria

- [x] Implement additive `witforge::emit::typescript` (`#[non_exhaustive]` `TypeScriptOptions`, no `Copy`), `witforge ts` CLI, and `[project.<name>.typescript]` config wired into `ensure_distinct_output_roots` and `witforge generate`, emitting strict ESM TypeScript (`TS 5.0+` / `6.0+`) with zero runtime dependencies
- [x] Map every supported WIT construct (`record`, `variant`, `enum`, `flags`, `option`, `result`, `char`, `list<T>`, `list<T, N>`, `map<K, V>`, aliases, interfaces, worlds, `deps/` including cross-major `DepLayout` disambiguation, docs, `@deprecated`) per `docs/design/polyglot-emitters.md`
- [x] Enforce deterministic LF-only nested output via `output.rs`, ownership headers, and `--check` drift detection without altering default `0.9.0` outputs
- [x] Prove emitted TypeScript with offline golden/unit tests in `cargo test --workspace --locked`, verify compilation with `tsc --noEmit --strict`, update `docs/design/public-api-inventory.txt`, and document all new CLI/config surfaces in `docs/guide/reference.md`
