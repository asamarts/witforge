## Why

The benchmark covers loading, modeling, lockfile reconciliation, and the four emitters, but
not `diff` or version-conversion generation. A large diff currently takes about 30 ms locally;
there is no regression budget.

## Acceptance criteria

- [x] a two-version fixture measures `diff::compare_with_impacts` and `rust` conversion planning
- [x] the budget is a catastrophic-regression ceiling, runs in the release benchmark job, and
      prints representative timings
- [x] the full suite and benchmark pass

## Verification

- `two_version_diff_and_conversion_stay_within_budget` measures the generated two-version
  fixture, asserts `diff::compare_with_impacts` reports changes, and asserts Rust planning emits
  `convert.rs`.
- Release run: small 1.22 ms, large 306.85 ms, two-version diff 31.35 ms, conversion plan
  51.21 ms; debug run: 5.14 ms, 858.94 ms, 153.84 ms, and 250.43 ms.
- Budgets are 5 s small, 15 s large, and 5 s each for the two-version diff and conversion plan.
- The full workspace suite and `cargo test -p witforge --test bench --locked` pass; the release
  benchmark job runs the same test with `--release`.
