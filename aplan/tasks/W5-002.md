## Why

A plan and generated output that are not gated drift. Released directories must
not change; shared proto/glue output must remain append-only.

## Acceptance criteria

- [x] CI runs `aplan check`, `aplan verify`, and `aplan export-agents-md --check` with a pinned aplan
- [x] released WIT/lockfile/per-version Rust modules are frozen
- [x] shared proto/glue output is checked append-only
- [x] `wit/released` is append-only and validated
- [x] generated `--check` runs for every emitter
- [x] `buf breaking` is documented and exposed as an optional extra check

## Why it is untestable

This is CI orchestration and a pinned tool installation. The checks themselves
are shell and workflow behavior; the plan's own `aplan check` is the local gate,
and the workflow is reviewed rather than unit-tested.
