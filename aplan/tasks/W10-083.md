## Why

Audit finding C12 (high for adopters). The append-only guarantee depends on released
directories never changing. That is enforced only by `ci/check-release-freeze.sh`, a script
in this repository that is in no crate, release archive, or Action. An adopter who follows
the guides has `wit/released` and nothing that stops an edit to `wit/v0.1/wire.lock` plus a
matching regeneration from passing every `witforge` command.

Reviewer-read: this repository's own CI runs the freeze check on the test fixtures and not on
`examples/evolved/wit/released`.

## Decision

Defaults chosen while documenting the task on 2026-11-19, not owner decisions.

- The command keeps the rule of `ci/check-release-freeze.sh`: it reads the whole
  history of the `released` file, not the difference from one base revision. A
  change that landed in a push whose CI run was cancelled is then still caught by
  the next run, which a base-revision comparison would miss. A base revision can
  be an option that bounds the work; it is not the default.
- The command runs `git`. A Git library would be a large dependency for one
  check, and the script's behaviour is defined in terms of `git log --follow`.
- Its name is settled together with the commands of `W10-084`, because the CLI
  surface freezes at 1.0.
- `ci/check-release-freeze.sh` stays, as a call of the command, so the workflows
  and documents that name it keep working.

## Edge cases

The script's header lists what the check has to keep doing:

- An entry that any committed version of the manifest listed must still be
  listed. Deleting the manifest removes every entry.
- A listed directory must exist, must not be or contain a symlink, must hold a
  `wire.lock` tracked under the entry's exact spelling (a case-insensitive file
  system must not match `V0.1` to `v0.1`), and must have no untracked file,
  ignored ones included.
- A listed directory must be unchanged in the working tree since every commit
  whose manifest listed it: a changed, added, deleted, or renamed file, and a
  changed mode.
- A WIT root that was moved with `git mv`: the manifest's history at the earlier
  path is read too. A copy is not followed.
- Paths with `*`, `?`, `[`, or non-ASCII characters are taken literally.

New with the command:

- A shallow clone, which is what `actions/checkout` produces by default, cannot
  be checked. The command exits 2 and names `fetch-depth: 0`; it never passes.
- No `git` on `PATH`, or a directory that is not in a repository: exit 2.
- Line endings: compare what Git stores, not the bytes of a checkout that
  `core.autocrlf` rewrote.
- Several WIT roots in one repository, taken from the configuration's projects.
- A violation is exit 1 and lists every path, not the first.
- Windows path separators in Git's output.
- Generated per-version modules are frozen by the consumer's committed copies and
  `--check`, not by this command. Say so in the guide.
- A retired version (`W10-093`) changes its state in the manifest once. The check
  has to accept exactly that change.

## Acceptance criteria

- [x] a `witforge` command applies the rule of `ci/check-release-freeze.sh`, read from the
      history of `released`, and exits 1 when a released file changed, a released entry
      disappeared, or a symlink was introduced; it exits 2 in a shallow clone
- [x] the Action exposes it and the CI guide's snippet uses it
- [x] the shell script is reduced to a call of the command, and the cases of
      `ci/test-release-freeze.sh` run against the command
- [x] this repository's CI runs it on the fixtures and on `examples/evolved`
