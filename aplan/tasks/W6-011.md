## Why

A third independent review, of `main` after W6-010, found that a released
version directory reached through a symlink escaped the freeze check (git
compares a link by its target string) and could be rewritten by `lock` on the
link's target or by generation into the link; that `lock --lock` from another
WIT root, or with an explicit `--released` that omitted the directory, rewrote
a released lockfile; that a contract with no members accepted a lockfile of
another package; that emitters reported internal errors as contract
violations; that `--check` hung on a FIFO, exited `2` for a directory, and
called a hand-written file changed output; that `check` accepted a lockfile in
a form `lock` never writes; that a move of the WIT root, a case-insensitive
file system, or an ignored file got past the freeze check; and that `check`'s
hints were not shell-quoted and, for a released version, named a command
`lock` refuses. alint's consumer review found that a nested `package` block
passed every check while nothing in it was locked or generated.

W6-010 had made the generators follow a symlinked version directory. This
task reverses that: no command follows one.

## Acceptance criteria

- [x] every command, the released manifest, and the freeze check refuse a
  version directory that is a symlink, and the freeze check refuses symlinks
  inside a released directory
- [x] `lock` refuses a released lockfile whatever `--released` names and from
  any WIT root
- [x] lockfile entries of another package are refused for a contract with no
  members, by `check`, `lock`, and the generators
- [x] emitters mark contract violations where they find them
- [x] `--check` reports every expected path generation refuses, reading only
  regular files
- [x] `check` requires the canonical lockfile rendering (W6-013 narrows this to
  an unreleased version and reads CRLF as LF: `lock` cannot rewrite a released
  lockfile, which the freeze check guards instead)
- [x] the subset refuses another package in a version directory
- [x] the freeze check follows moves of the WIT root, requires an exact-case
  tracked `wire.lock`, and counts ignored files
- [x] `check` hints are shell-quoted and tell a released version to restore
