## Why

Every Rust consumer currently hand-writes ~25 lines of `build.rs` wiring (`protox` + `prost-build`), switches between single-file `include!` and `include_file("prost_include.rs")` when adding `deps/`, and risks missing per-file `cargo:rerun-if-changed` directives.

## Decision

- Add a workspace library crate `crates/witforge-build` exposing `Config` and `compile_protos(proto_dir)` (deterministic sorted `.proto` discovery, per-file `cargo:rerun-if-changed`, `protox` + `prost-build`, optional `pbjson` feature for `pbjson-build`, and consistent `include_file` generation).
- Wire `witforge-build` into workspace version checks, packaging/publish scripts, release digests, CI, and `.aplan.yml`.

## Acceptance criteria

- [x] `witforge-build` compiles standalone and `deps/` generated `.proto` trees in a scratch crate (both default and `pbjson` feature)
- [x] `witforge-build` emits per-file `cargo:rerun-if-changed` directives and passes `clippy -D warnings`, `rustfmt --check`, and `cargo doc -D warnings`
- [x] `ci/check-release.sh`, `ci/publish.sh`, `ci/test-publish.sh`, `.github/workflows/release.yml`, and `docs/guide/wiring.md` cover `witforge-build`
