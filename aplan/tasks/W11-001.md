## Why

`witforge` already emits a deterministic, versioned JSON Contract IR (`witforge inspect --json`, `IR_VERSION = 1`). Providing a standardized process-based emitter plugin protocol (modeled after `protoc-gen-*`) lets external and community emitters target additional languages or frameworks (Kotlin, Swift, C++, Zig, Pydantic, internal SDKs) without forking `witforge`, while reusing `witforge`'s contract validation, lockfile enforcement, atomic nested-tree writes (`W13-001`), symlink guards, ownership headers, and `--check` drift checks.

## Decision

Owner decision recorded on 2026-11-26 (unblocked ahead of `W10-002` as Stage 1 of the staged hybrid polyglot strategy; runs after `W13-001` so plugin output reuses the single canonical nested-tree writer in `crates/witforge/src/emit/output.rs`):

- Standardize a versioned JSON-over-stdio process protocol (`protocol_version: 1`):
  - **Stdin request:** `protocol_version`, `ir_version`, validated `witforge inspect --json` multi-version root IR payload (requiring valid lockfiles, matching `rust`/`proto`/`schema`/`glue`/`doc`), normalized `options` map, and `contract_id` / ownership header metadata. Do **not** include host-specific absolute `output_root` paths in stdin JSON so plugin outputs stay machine-independent.
  - **Stdout response:** `protocol_version`, ordered list of emitted `{ path, content }` files (relative POSIX paths validated strictly inside `--out`, LF-normalized) and optional structured diagnostics.
- Keep `crates/witforge` dependency-free (`wit-parser` + `anyhow` only): keep plugin JSON request/response parsing and subprocess orchestration in `crates/witforge-cli` (where `serde`/`serde_json` already live) over `witforge`'s public IR + nested `output.rs` APIs.
- Invoke plugins strictly via explicit opt-in: `witforge plugin <name>` (resolving `witforge-gen-<name>` strictly along `PATH`, never searching CWD on Windows, or via CLI-only `--plugin-bin <PATH>` with `value_name = "PATH"` for shell completions). `[project.<name>.plugins.<name>]` in `witforge.toml` may declare plugin names, output roots, and key-value options, but **never** arbitrary executable paths, and `witforge generate` never executes plugins unless explicitly passed `--allow-plugins`.
- Enforce concrete safety bounds in `witforge`: strict plugin `<name>` regex (`^[a-z0-9][a-z0-9-]*$`), concurrent stdin/stdout/stderr piping (avoiding pipe deadlocks), execution timeout with process termination, bounded stdout/stderr/file-count/file-size limits, atomic nested-tree writes via `output.rs`, contract-scoped ownership headers, symlink refusal, and `--check` drift detection.
- Reuse existing structured diagnostic codes (`WF9001`/`WF9003`/`WF9004` for CLI/config/plugin operational failures, `WF2001` for contract/output violations) or update `diagnostic.rs` + `docs/design/diagnostics.md` + `docs/guide/diagnostics.md` together if new codes are added.

## Edge cases

- Path traversal (`../`), absolute paths, Windows separators, NUL/control characters, duplicate paths, case-insensitive path collisions (`Foo.ts`/`foo.ts`), file-vs-directory prefix collisions (`a/b` vs `a/b/c`), Windows reserved device names (`CON`, `NUL`, `AUX`, `PRN`, `COM1..9`, `LPT1..9`), and symlink targets in a plugin response must all be refused before any file is written.
- Windows `PATH` lookup must resolve `.exe`/`.cmd`/`.bat` via `PATHEXT` strictly from `PATH` entries and never from the current working directory.
- Non-zero exit codes, timeout kills, oversized outputs, invalid JSON responses, or mismatched `protocol_version` must surface as clear structured diagnostics with exit code `2` (operational error) or `1` (plugin contract violation).
- Integration tests must build and execute a pure-Rust cross-platform helper test plugin (never POSIX shell scripts or external interpreters) so Linux, macOS, Windows, and MSRV 1.88 CI all pass.
