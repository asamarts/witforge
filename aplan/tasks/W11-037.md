## Why

`diff` with a WIT root validates each version's lockfile through `load_versions`, but a
direct version-directory endpoint goes through `load_version`, which only checks the package
and that live members have non-reserved numbers. A stale kind, canonical type, or draft entry
can therefore produce `result: COMPATIBLE` for a contract that `check` rejects. The normative
`docs/design/diff.md` text already promises a current lockfile and says the command fails
rather than guessing.

## Acceptance criteria

- [x] a direct version-directory endpoint validates live member kind/type and stale draft
      entries the way the generators' lockfile drift does, while still permitting the
      declaration-order changes `diff` exists to report
- [x] a stale kind, canonical type, or draft entry fails with a contract error and exit `1`
      instead of a false `COMPATIBLE`
- [x] root endpoints and direct version-directory endpoints agree for the same stale tree
- [x] valid lockfiles keep their current behavior and output, including pure reorders and
      function-parameter reorders
- [x] a CLI regression covers the stale-type case, the stale-draft case, and root/direct parity
