## Why

Plain TypeScript types need deterministic, checked conversions to and from `@bufbuild/protobuf` (`protobuf-es` v2) messages so TypeScript hosts and plugins enforce the exact same 13-row WIT decode profile as Rust glue without hand-written validation.

## Acceptance criteria

- [ ] Implement additive opt-in TypeScript checked protobuf glue (`witforge ts-glue` / `[project.<name>.typescript-glue]` wired into `ensure_distinct_output_roots` and `witforge generate`) targeting `@bufbuild/protobuf` (`toProto` / `fromProto`, per-function request/response helpers, `METHOD` constants, and structured `WitforgeGlueError`)
- [ ] Enforce all 13 rows of the WIT decode profile (including encode-side bounds checks for narrow ints, `bigint` 64-bit ints, supplementary-plane Unicode scalar `char`, required `optional` presence, closed enums, exact `list<T, N>` length, `map<K, V>` key validation, and unset `oneof` / wrapper rejection)
- [ ] Add offline golden/unit tests in `cargo test --workspace --locked`, add a SHA-pinned TypeScript conformance CI job in `.github/workflows/ci.yml` compiling emitted TS + `@bufbuild/protobuf` and passing every `W11-034` binary + proto3-JSON vector, update `docs/design/public-api-inventory.txt`, and document CLI/config keys in `docs/guide/reference.md`
