## Why

Audit findings A12 and A13 (medium to low).

- Re-run 2026-11-18: a dependency declared `package ex:shared@0.1.3;` makes
  `witforge check` exit 2 with "dependency versions must be `<major>.<minor>.0`" and no
  package name, file, or diagnostic code, even when the root never refers to the dependency
  (`model.rs:543-553`). An unversioned dependency behaves the same (reviewer-run). This is a
  contract violation and should be exit 1 with a located diagnostic.
- Re-run 2026-11-18: `world w { import foo: types; }` is reported as "inline interfaces are
  not supported" (`subset.rs:134-139`); it is a named import of an existing interface.
- Reviewer-run: `@external-id("foo")` is accepted and dropped; adding a world makes a whole
  dependency interface required without the diagnostic mentioning the implicit import; a
  member reintroduced in another letter case (`foo-bar`, then `FOO-bar`) passes `lock` and
  `check` and then fails in `proto`.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
Each item is one branch of an "or" in the criteria:

- The dependency-version rule applies to every package under `deps/`, referenced
  or not, because every one of them contributes to the generated surface
  (`dependencies.md`, "Cross-version invariant"). The specification says so.
- A named import is refused, under a message of its own.
- An annotation other than `@since`, `@unstable`, and `@deprecated` is refused,
  following the subset checker's refuse-unknown rule. What the three known ones
  produce is `W10-094`.
- Two names in one scope that differ only in letter case are refused by `check`,
  with the reserved names of the scope included.

## Edge cases

- Dependency versions: a patch version (`0.1.3`), a pre-release, build metadata,
  and no version, each for a dependency the root refers to and for one it does
  not.
- The diagnostic names the package, its version, and its `deps/` directory. It is
  exit 1 with a code (`W10-079`); today it is exit 2 without one.
- `import foo: types;` and `export foo: types;` get the new message. An inline
  `import foo: interface { … }` keeps the inline-interface message, and a
  world-level function import keeps its own.
- An unknown annotation on an interface, a type, a function, and a world item.
- A world that reaches a dependency interface makes every item of that interface
  required. The diagnostic for an unsupported item there names the world item
  that pulled it in.
- Letter case: two live members of one parent, a live member against a reserved
  one (`foo-bar` removed, `FOO-bar` added), two types of one interface, two
  interfaces of one package, and two functions. The comparison is ASCII
  case-insensitive. Names in different scopes do not collide.
- The case rule and the identifier collisions of `W10-059` are reported through
  one diagnostic code, since both say that two names map to one generated
  identifier.

## Acceptance criteria

- [x] dependency version violations are subset diagnostics (exit 1) naming the package, for
      every package under `deps/`, and the specification states that scope
- [x] a named import is refused under its own message
- [x] an annotation other than `@since`, `@unstable`, and `@deprecated` is refused
- [x] a diagnostic caused by a world's implicit import says so
- [x] two names in one scope that differ only in letter case are refused by `check`
