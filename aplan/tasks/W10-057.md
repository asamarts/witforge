## Why

Audit finding A16 (high). `diff` and `check --against` compare resolved types; the conversion
generator compares the spelled Rust types. A change the first two call "no contract changes"
makes `witforge rust` refuse to generate.

Re-run 2026-11-18: with `type id = u32`, changing `record r { a: id }` in v0.1 to
`record r { a: u32 }` in v0.2 passes `check --against` and `diff --check`
("no contract changes", exit 0), and `witforge rust wit` exits 1. Reviewer-run: introducing
`type id = u32` in v0.2 and using it for an existing `u32` field does the same.

`W10-036` added `conversion_blockers` to `diff`, but only for required additions
(`diff.rs:278-328`); the alias cases are in `convert.rs:346`, `659-660`, `730-735`.

## Edge cases

- An alias replaced by its target and a target replaced by an alias, in both
  conversion directions.
- One alias replaced by another alias of the same target.
- A named structural type against its expansion: `ids` with
  `type ids = list<u32>` against `list<u32>`.
- The alias exists in only one of the two versions, because it was introduced or
  removed with the change.
- Nested positions: `list<id>` against `list<u32>`, `option<id>`, a `result` side,
  and a variant payload.
- A foreign alias, and a `use … as` rename that differs between the versions.
- A changed alias target is a real type change. It stays refused, and it is in the
  table as a row where `diff --check` fails.
- Parameters and results: no conversion is generated for functions, and two
  spellings of one type are one Rust type, so the generated-API view reports no
  change.
- The table states one direction only: `diff --check` passing implies that
  `witforge rust` succeeds. The reverse does not hold, since a source-breaking
  change that converts fails `diff --check`.

## Acceptance criteria

- [ ] conversion between two spellings of one resolved type is generated (identity or `into`)
- [ ] where generation still refuses, `diff` lists the refusal under `conversion_blockers`
      and `diff --check` fails
- [ ] a test asserts, for a table of evolutions, that `diff --check` passing implies
      `witforge rust` succeeds
