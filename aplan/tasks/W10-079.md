## Why

Audit finding C5 (medium). Re-run 2026-11-18 on a contract with a tuple field and a `char`
field:

```text
witforge --format json check wit/v0.1   two diagnostics, WF1001, paths ex:h/types/r.a and r.b
witforge --format json rust wit         one diagnostic, WF9000 (internal), no path, both
                                        messages joined with "; "; exit 1
witforge --format json check            (usage error) stdout empty, clap text on stderr
```

Every generator error is mapped to `WF9000` (`main.rs:424-434`), so a consumer of the JSON or
SARIF report cannot tell a contract violation from a tool failure. All subset violations
share `WF1001`. Reviewer-run: `lock --against` a lockfile of another package gives `WF9000`
where `check` gives `WF1002`; the `WF1002` path names the wrong file;
`diff … --json --format sarif` prints SARIF although the specification says `--json` wins.

## Edge cases

- One violation reported by `check`, `lock`, `diff`, and each generator: one code,
  one path, one message.
- Several violations stay several diagnostics. Today a generator joins them with
  "; " into one.
- Splitting `WF1001` into one code per rule changes what a consumer of the JSON or
  SARIF report filters on. `diagnostics.md` lists the old code beside each new
  one, and the changelog says so.
- A usage error with `--format json` or `sarif`: the argument parser fails before
  the option is read, so the format is taken from the raw arguments. The exit
  status stays 2.
- `diff --json --format sarif` prints JSON, as the specification says.
- `WF9000` is for internal errors only. A missing file, a permission error, and a
  malformed lockfile or manifest are exit 2 with codes of their own.
- `lock --against` a lockfile of another package gets the code `check` gives
  (`WF1002`), and the path of `WF1002` names the file that holds the foreign key.
- A test lists every code the tool can emit and compares the list with
  `diagnostics.md` (shared with `explain` in `W10-085`).
- The refusals that `W10-067` moves into `check` get codes here.

## Acceptance criteria

- [ ] a contract violation has the same code and path whichever command reports it
- [ ] `WF9000` is produced only for internal errors
- [ ] subset violations have one code per rule, listed in `diagnostics.md`
- [ ] with `--format json` or `sarif`, a usage error produces a report on stdout
- [ ] `--json` and `--format` precedence matches the specification
