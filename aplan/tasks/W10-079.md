## Why

Audit finding C5 (medium). Re-run 2026-11-18 on a contract with a tuple field and a `char`
field:

```text
witforge --format json check wit/v0.1   two diagnostics, WF1001, paths ex:h/types/r.a and r.b
witforge --format json rust wit         one diagnostic, WF9000 (internal), no path, both
                                        messages joined with "; "; exit 1
witforge --format json check            (usage error) stdout empty, clap text on stderr
```

Every generator error is mapped to `WF9000` (`main.rs:424-434`), so a consumer of the JSON or
SARIF report cannot tell a contract violation from a tool failure. All subset violations
share `WF1001`. Reviewer-run: `lock --against` a lockfile of another package gives `WF9000`
where `check` gives `WF1002`; the `WF1002` path names the wrong file;
`diff … --json --format sarif` prints SARIF although the specification says `--json` wins.

## Acceptance criteria

- [ ] a contract violation has the same code and path whichever command reports it
- [ ] `WF9000` is produced only for internal errors
- [ ] subset violations have one code per rule, listed in `diagnostics.md`
- [ ] with `--format json` or `sarif`, a usage error produces a report on stdout
- [ ] `--json` and `--format` precedence matches the specification
