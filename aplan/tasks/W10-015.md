## Why

The quality audit repaired generated glue ownership behavior, added adapter error documentation, committed runnable generated examples, and published exact output documentation. External evaluation should install a release that reproduces those documented outputs rather than relying on unreleased `main`.

## Why it is untestable

Publication is proved by the exact-commit tag workflow, crates.io, release assets, docs.rs, cargo install, and hosted published-Action runs; no repository-local test can publish them.

- [x] workspace, CLI dependency, lockfile, README, site, quickstart, Action examples, and changelog agree on 0.4.4
- [x] the changelog states that wire numbers, protobuf output, and the public library API are unchanged while generated Rust glue and adapter documentation change
- [x] every local release and plan gate passes, including historical protobuf compatibility
- [x] exact-commit main CI is green before tagging
- [x] the v0.4.4 release workflow publishes both crates, four archives with checksums, the GitHub release, docs.rs documentation, and a four-target tagged Action smoke
- [x] cargo install reports witforge 0.4.4 and reproduces the committed single example output
- [ ] main CI pins the published v0.4.4 Action and passes on all four release targets
