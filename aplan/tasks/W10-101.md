## Why

The 0.7.0 exact-commit Windows CI run reproduced a sharing race in
`write_skips_unchanged_preserves_modes_handles_unreadable_and_concurrent_runs`: two writers
concurrently classified and removed the same stale owned file, and one `remove_file` received
`PermissionDenied` while the other thread still held a Windows file handle. Concurrent
generation promises both writers finish cleanly; permanent permission failures must still fail.

## Acceptance criteria

- [x] stale removal retries only Windows sharing violations for a bounded interval
- [x] missing files and a concurrent writer's successful removal remain success
- [x] persistent permission failures still report the stale path
- [ ] the concurrent-writer regression passes on Windows and the full output suite stays green
