## Why

The post-second-audit 1.0 criteria require one real consumer to take a contract through a
minor evolution and regenerate it across two witforge releases. `W10-098` records the policy,
but no live task owns the evidence and `W10-002` therefore cannot derive this gate from the
task graph. This criterion is separate from independent adoption: the same-owner alint proof
crate may satisfy evolution evidence but cannot satisfy `W10-001`.

## Why it is untestable

The task verifies two changes and their CI results in a consumer repository. Reverting this
repository's evidence record cannot make the external consumer's compiled behavior fail.

## Decision

Use alint if it has a real contract minor to ship: one change evolves the contract and
regenerates with an earlier witforge release, and a later change moves to 0.7.0 or a later release
and regenerates again. If alint has no real evolution, wait for another real consumer; a synthetic
fixture or same-commit pin change is not evidence.

## Acceptance criteria

- [ ] cite the consumer commit that introduces a real contract minor and its generated-output
      change under the first witforge release
- [ ] cite the later consumer commit that moves to 0.7.0 or a later release and regenerates the
      evolved contract
- [ ] both consumer commits have successful CI and exercise lock continuity, diff, generation,
      compiled generated code, and version conversion where the contract uses it
- [ ] record observed migration friction without generalizing beyond the exercised contract
- [ ] `release-1.0.md`, the release checklist, and the task evidence point to the same two
      consumer changes

## Investigation (2026-11-23)

- Public GitHub code search for `witforge.toml`, `witforge-cli`, and
  `asamarts/witforge@` found no consumer beyond alint (apart from the crates.io index). crates.io
  reports one reverse dependency for the library—`witforge-cli`—and none for the CLI; the
  repository has no public forks carrying a consumer.
- Alint's WIT history contains only `wit/alint-plugin/v0.1`, first added in
  [`0f6fed5bb`](https://github.com/asamarts/alint/commit/0f6fed5bb), and no `released` manifest or
  `v0.2` directory. There is therefore no earlier real minor-evolution commit to cite.
- Alint [PR #647](https://github.com/asamarts/alint/pull/647) (`188defd5a`) is a valid 0.7.0
  regeneration proof, but it changes only the witforge pin and generated stability comments:
  `wire.lock` and glue are unchanged, and the contract remains `@0.1.0`. Under this task's
  Decision, that pin-only change is explicitly not the second half of qualifying evidence.
- Alint's [ADR-0027](https://github.com/asamarts/alint/blob/188defd5aa83d4396c701627c03566f352354bae/docs/adr/0027-plugin-contract-0-1-stays-a-draft.md)
  says contract 0.1 is an unfrozen draft with no plugin host and may change in place. Its
  [ADR-0048](https://github.com/asamarts/alint/blob/188defd5aa83d4396c701627c03566f352354bae/docs/adr/0048-v024-owner-decisions.md)
  defers the first real plugin-host/fixer contract work to v0.25 at the earliest. Creating a
  `v0.2` now would contradict that owner decision and manufacture evidence.

No qualifying pair exists today. Wait for alint's real Plugin Hosts P2 contract evolution or
another real consumer minor; re-review on either event rather than creating a synthetic version.

## Parked

No qualifying two-change consumer minor exists: alint has only an unfrozen draft 0.1 contract, defers real Plugin Hosts P2 evolution to v0.25 at the earliest, and public searches found no other consumer. Revisit when P2 starts or another real consumer minor appears; never substitute a synthetic version or pin-only change.
