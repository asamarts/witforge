## Why

Plain Rust Serde, WIT-shaped JSON Schema, and proto3-JSON intentionally have different naming, presence, and 64-bit integer rules. An adopter may still need Serde and JSON Schema to describe one aligned JSON boundary. Any mode changes frozen generated behavior and must be opt-in, version-aware, and justified by a real protocol rather than guessed globally.

## Acceptance criteria

- [ ] capture one adopter's authoritative JSON profile and committed full/minimal fixtures
- [ ] compare field/case names, omission versus null, enums, bytes, and 64-bit integers across all three projections
- [ ] evaluate Serde WIT-name attributes, a Serde-shaped schema mode, and an explicit application adapter
- [ ] prove existing generated modules and default output remain byte-for-byte unchanged
- [ ] implement and test an option only if it removes a demonstrated adapter burden; otherwise record the chosen adapter and revisit trigger
