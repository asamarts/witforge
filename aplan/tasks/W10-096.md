## Why

Audit finding D3 (medium, reviewer-read). The library cannot do what the command line does:

- `diagnostic::Diagnostic` is public and the library never returns one; `emit::*::check`
  returns `Vec<String>` and the CLI recovers paths by looking for backticks
  (`diagnostics.rs:205-210`);
- `Change::element` is a free-form string the CLI matches on (`main.rs:790`);
- the logic of `check` and `lock` (mode selection, released-manifest rules, the report) and
  the `witforge.toml` parser exist only in the binary, so a `build.rs` or another tool must
  shell out;
- `load` takes a directory; there is no in-memory entry point, which also forces the fuzz
  target to write a file per input.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision:
the configuration model stays in the CLI, and `public-api.md` says so. The format
of `witforge.toml` is specified in `emitters.md` section 11. Publishing its Rust
model would freeze a second description of it at 1.0, and a `build.rs` that calls
the library passes its options as values.

## Edge cases

- The library functions take what the command line takes: the mode (default,
  first, or against a lockfile), and the released manifest. `lock` can return the
  rendered lockfile without writing it.
- Exit statuses stay in the CLI. The library returns the classification
  (`public-api.md`, Errors: `anyhow::Error` with `ContractError`).
- `emit::*::check` returns a list of strings today. It becomes a list of
  structured findings: the path, and whether the file is missing, changed, or
  extra. That is a breaking change before 1.0, in the same release as `W10-095`.
- `Change::element` becomes a type the CLI matches on, not text.
- The CLI's output is byte-identical before and after, in the human, JSON, and
  SARIF forms. The existing CLI tests are the proof.
- Loading from memory: sources as names with text, and the dependencies beside
  them. The ordering rule of `W10-077` applies to the names, and positions
  (`W10-080`) use them.
- The library does not print and does not exit.
- The fuzz target moves to the in-memory entry point (`W10-089`).
- A documented example calls the library from a `build.rs`.

## Acceptance criteria

- [ ] the library exposes `check`, `lock`, and generation as functions that return structured
      diagnostics; the CLI formats them and holds no contract logic
- [ ] no code path derives structure from message text
- [ ] a contract can be loaded from in-memory sources
- [ ] the configuration model is documented as CLI-only in `public-api.md`
