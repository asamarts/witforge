## Why

Audit finding D3 (medium, reviewer-read). The library cannot do what the command line does:

- `diagnostic::Diagnostic` is public and the library never returns one; `emit::*::check`
  returns `Vec<String>` and the CLI recovers paths by looking for backticks
  (`diagnostics.rs:205-210`);
- `Change::element` is a free-form string the CLI matches on (`main.rs:790`);
- the logic of `check` and `lock` (mode selection, released-manifest rules, the report) and
  the `witforge.toml` parser exist only in the binary, so a `build.rs` or another tool must
  shell out;
- `load` takes a directory; there is no in-memory entry point, which also forces the fuzz
  target to write a file per input.

## Acceptance criteria

- [ ] the library exposes `check`, `lock`, and generation as functions that return structured
      diagnostics; the CLI formats them and holds no contract logic
- [ ] no code path derives structure from message text
- [ ] a contract can be loaded from in-memory sources
- [ ] the configuration model is public or documented as CLI-only in `public-api.md`
