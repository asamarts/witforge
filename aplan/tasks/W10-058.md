## Why

Audit finding A17 (medium). Type expansion is recursive without a depth limit and wrapper
messages are expanded structurally without sharing, so small inputs abort the process or
produce very large files.

Re-run 2026-11-18:

```text
type a0 = u8; type a1 = a0; … type a8000 = a7999;        lock --first: exit 134, stack overflow
                                                          (depth 3000 succeeds)
type t1 = list<u16>; type tN = list<result<tN-1, tN-1>>;  16 lines of WIT (N = 12):
                                                          49 KB wire.lock, 373 KB proto, 12.9 MB glue;
                                                          each +2 in N multiplies the glue by about 4.7
```

Reviewer-run: N = 17 gives 558 MB of glue and a 1.7-million-character message name;
`type a{i} = result<a{i-1}, a{i-1}>` to i = 24 gives a 369 MB `wire.lock`; a lockfile type
token nested 200,000 deep aborts `check`; 16,000 members take 33 s in `lock --first`
(`next_number` is quadratic).

The stack overflow needs thousands of lines; the size growth needs about twenty. Both matter
because the tool runs in CI on contracts from pull requests.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
The fix is a set of limits, not a change of form. Referring to a named structural type by
name would change the canonical type strings of lockfiles that are released and
frozen, which `W10-051` decided against. Proposed values, to be confirmed against
every fixture, both examples, and alint's contract before they go into the
specification: 32 levels of type nesting, 32 links in an alias chain, and 1024
bytes for one canonical type string. Raising a limit later is compatible; lowering
one is not.

## Edge cases

- The limit is checked while a type is expanded, not afterwards, so a refusal
  costs neither the stack nor the memory it guards.
- One set of limits in `check`, `lock`, `diff`, every generator, and the lockfile
  reader, so that a contract cannot be locked and then be refused by a generator.
- Alias-chain length and nesting depth are separate counts. A chain of 3000
  aliases to `u8` nests nothing.
- The doubling contract (`tN = list<result<tN-1, tN-1>>`) stays shallow while its
  canonical string doubles per level. The length limit is what stops it.
- WIT source nested deeper than the parser's own stack allows may abort in
  `wit-parser` before witforge sees a type. Test it; if it aborts, bound the input
  before parsing or record the limit as the parser's.
- A lockfile type token nested 200,000 deep.
- A wide contract is legal: 16,000 members must lock in time linear in the member
  count and are not refused.
- The diagnostic names the type, the limit, and the measured value. It is exit 1
  from `check`; a lockfile token over the limit is a parse error (exit 2).
- A wrapper message name is derived from the canonical string, so the length limit
  bounds it. State the resulting maximum.

## Acceptance criteria

- [x] alias chains and nested types beyond a documented depth are refused with exit 1, not a
      crash; the lockfile reader has the same limit
- [x] canonical type strings and wrapper names have a documented maximum length
- [x] number assignment is not quadratic in the member count
- [x] tests cover the depth limit and a size budget for the doubling contract
