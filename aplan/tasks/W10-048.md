## Why

Audit finding A4 (high). `diff` compares field, case, and parameter numbers but not method
ids (`diff.rs:934-989`), and treats a reused reserved number as an addition
(`diff.rs:851-861`). `lock --first` is accepted in a version directory that has a predecessor,
which is how a renumbered lockfile comes to exist.

## Reproduction (re-run 2026-11-18)

```text
wit/v0.1/c.wit   package ex:t@0.1.0;  interface api { alpha: func() -> u32; beta: func(); }
wit/v0.1/wire.lock   ex:t/api.alpha = 1 method u32      ex:t/api.beta = 2 method
wit/v0.2/c.wit   the same contract at @0.2.0
wit/v0.2/wire.lock   ex:t/api.alpha = 2 method u32      ex:t/api.beta = 3 method
```

The second lockfile is what `witforge lock wit/v0.2 --first` leaves when the draft once
declared an extra leading function. `witforge diff wit/v0.1 wit/v0.2 --check` prints
`no contract changes … result: COMPATIBLE` and exits 0. `witforge proto wit` exits 1 with
"`ex:t/api.alpha` was renumbered from 1 to 2".

Reviewer-run: a new member that takes a number reserved in the old lockfile is reported as
`added … wire:compatible`; `witforge check wit/v1.0 --against wit/v0.2/wire.lock` exits 0.

## Acceptance criteria

- [ ] `diff` reports a changed method id as a wire-breaking change
- [ ] `diff` reports reuse of a number reserved in the old lockfile as wire-breaking
- [ ] `lock --first` and `check --first` exit 1 in a version directory that is not the first
      minor of its major in the root, naming the predecessor and the `--against` command
- [ ] `--against` with a lockfile of another major is refused or its meaning is specified and
      tested
- [ ] `diff` and the generators agree on every case in the new tests
