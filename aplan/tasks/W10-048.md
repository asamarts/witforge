## Why

Audit finding A4 (high). `diff` compares field, case, and parameter numbers but not method
ids (`diff.rs:934-989`), and treats a reused reserved number as an addition
(`diff.rs:851-861`). `lock --first` is accepted in a version directory that has a predecessor,
which is how a renumbered lockfile comes to exist.

## Reproduction (re-run 2026-11-18)

```text
wit/v0.1/c.wit   package ex:t@0.1.0;  interface api { alpha: func() -> u32; beta: func(); }
wit/v0.1/wire.lock   ex:t/api.alpha = 1 method u32      ex:t/api.beta = 2 method
wit/v0.2/c.wit   the same contract at @0.2.0
wit/v0.2/wire.lock   ex:t/api.alpha = 2 method u32      ex:t/api.beta = 3 method
```

The second lockfile is what `witforge lock wit/v0.2 --first` leaves when the draft once
declared an extra leading function. `witforge diff wit/v0.1 wit/v0.2 --check` prints
`no contract changes … result: COMPATIBLE` and exits 0. `witforge proto wit` exits 1 with
"`ex:t/api.alpha` was renumbered from 1 to 2".

Reviewer-run: a new member that takes a number reserved in the old lockfile is reported as
`added … wire:compatible`; `witforge check wit/v1.0 --against wit/v0.2/wire.lock` exits 0.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision:
`--against` with a lockfile of another major is refused, because `lockfile.md`
section 7 already says that a new major starts a fresh lockfile with `--first`.
A lockfile does not record its version, so the major is known only from the path:
the rule applies when the baseline is the `wire.lock` of a sibling
`v<major>.<minor>` directory. A baseline file anywhere else is accepted as given,
and the specification says so.

## Edge cases

- A method id that changes with an unchanged signature, two functions that swap
  ids, and a new function that takes the id of a removed one.
- A number reserved in the old lockfile that the new lockfile gives to a new
  member, with the reserved entry still present and with it deleted.
- A number that only an unreleased draft used is free to be reused, and `diff`
  cannot see it. That is not a finding.
- Parameter, field, and case numbers are compared today; they are in the same
  table so that `diff` and the generators are shown to agree for every kind.
- `--first` is allowed in the lowest minor of a major that the root holds: `v0.1`
  beside `v0.2`, `v1.0` beside `v0.x`, and `v0.3` when the root starts there. It
  is refused in `v0.2` beside `v0.1`.
- `--first` run again on the first minor while it is still a draft stays allowed.
- A version directory that is not inside a WIT root has no siblings to judge by,
  and `--first` is accepted.
- `check --against` with a baseline that is not the immediate predecessor (`v0.3`
  against `v0.1` while `v0.2` exists). The generators check continuity between
  neighbours, so the two must be shown to agree; the message names the
  predecessor.
- A misplaced `--first` is a contract violation (exit 1), and the message contains
  the `--against` command to run instead.

## Acceptance criteria

- [x] `diff` reports a changed method id as a wire-breaking change
- [x] `diff` reports reuse of a number reserved in the old lockfile as wire-breaking
- [x] `lock --first` and `check --first` exit 1 in a version directory that is not the first
      minor of its major in the root, naming the predecessor and the `--against` command
- [x] `--against` with the lockfile of a sibling version directory of another major is
      refused with exit 1 and the `--first` remedy; what happens for a baseline file
      outside a version directory is specified and tested
- [x] `diff` and the generators agree on every case in the new tests
