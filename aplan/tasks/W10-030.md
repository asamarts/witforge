## Why

The fuzz workspace is outside every automated gate: root `cargo fmt`/`cargo check` do not
see it, Dependabot has no `/fuzz` entry, and the security job does not scan its lockfile.
Its `wit_package` target also triggers Cargo's kebab-case warning, and the quality design
document does not mention the harness.

## Acceptance criteria

- [x] the fuzz target is renamed to kebab-case and `ci/README.md`/`fuzz/README.md` commands
      are updated
- [x] Dependabot covers `/fuzz`
- [x] stable CI checks run `cargo fmt --manifest-path fuzz/Cargo.toml --check` and
      `cargo check --manifest-path fuzz/Cargo.toml --locked`
- [x] the fuzz lockfile's advisory/license/source coverage is added to the security gate
- [x] `docs/design/quality.md` describes the fuzz harness and pinned nightly
- [x] actionlint, shellcheck, the fuzz checks, and a short smoke run pass

## Why it is untestable

The deliverable is CI configuration and a nightly fuzz workspace, outside the configured
cargo test runners. Workflow linting, stable manifest checks, and the fuzz smoke run are the
applicable evidence.

## Verification

- `cargo fmt --manifest-path fuzz/Cargo.toml --check`
- `cargo check --manifest-path fuzz/Cargo.toml --locked`
- `cargo audit --file fuzz/Cargo.lock`
- `(cd fuzz && cargo deny check --config ../ci/deny.toml advisories bans licenses sources)`
- `cargo +nightly-2026-09-11 fuzz build --target x86_64-unknown-linux-gnu`

- `cargo +nightly-2026-09-11 fuzz run lockfile --target x86_64-unknown-linux-gnu -- -runs=100`
- actionlint, shellcheck, Node Action tests, root suite, Clippy, rustdoc, generated output, and
  aplan gates pass.
