## Why

The MVP deliberately did not track declaration order; a reorder in an unreleased
version was caught only by review. This pre-golive option adds a fingerprint
without per-entry churn.

## Acceptance criteria

- [x] per-type and per-function order fingerprints are stored in an additive section
- [x] `--against` catches reorders of common members
- [x] additions/removals do not produce false reorder findings
- [x] migration from v2 without fingerprints is defined
