## Why

The post-0.4.2 audit reproduced a root `use` of a dependency record containing `char` passing
`witforge check` and every generator. Rust output then references a dependency type that was
silently omitted. The dependency design also says only root-reached packages enter the shared
graph, while the emitters generate every supported package loaded from `deps/`.

## Acceptance criteria

- [x] every dependency type reached through a root type, alias, function, or world is checked transitively
- [x] required unsupported dependency types fail `check` and all four generators as contract violations
- [x] unsupported dependency items remain skippable only when no root type or world exposes them
- [x] dependency graph comparison reports member-metadata changes accurately and performs no avoidable order-vector allocation
- [x] normative dependency and emitter documentation matches the generated graph exactly
- [x] focused regressions reproduce the accepted-invalid-output failure and pass after the fix
