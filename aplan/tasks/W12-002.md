## Why

`docs/` must remain the single source of truth for witforge's documentation so GitHub browsing, Rust doc tests (`crates/witforge-cli/tests/docs.rs`, `distribution.rs`, `diagnostics.rs`, `reference_doc_tests`), `action/test.js`, and `ci/check-version-references.sh` continue validating the exact Markdown files that power the published site. An explicit `docs/SUMMARY.md` manifest and sync script keep Starlight's sidebar, frontmatter, link rewriting, and LLM-friendly text exports strictly derived from `docs/`.

## Why it is untestable

This task adds Node build scripts (`site/scripts/*.mjs`) and Astro static endpoints (`llms*.txt.ts`) before the Rust `tooling.rs` wrapper is wired in `W12-009`. Until `W12-009` hooks Node script tests into `cargo test`, `.aplan.yml`'s Cargo runners cannot fail if these scripts are reverted. Verification runs through `node --test site/scripts/test-scripts.mjs`, `npm --prefix site run sync:docs`, `aplan check-docs`, and `cargo test -p witforge-cli --test docs`.

## Decision

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Canonical Starlight doc routes live under `/witforge/docs/`:
  - `docs/index.md` maps to `/witforge/docs/`
  - `docs/quickstart.md` maps to `/witforge/docs/quickstart/`
  - `docs/guide/<slug>.md` maps to `/witforge/docs/<slug>/` (flat, readable slugs matching `ayaml`'s `/docs/<slug>/` pattern, while `W12-007` preserves all legacy `/guide/*.html`, `/guide/`, and `/quickstart.html` URLs)
  - `docs/guide/index.md` is excluded from duplicate sidebar navigation (with `/witforge/guide/` redirecting to `/witforge/docs/` via `W12-007`) so users never hit two redundant index pages.
- Sidebar groups in `docs/SUMMARY.md`:
  1. Getting Started: Overview (`index.md`), Choosing witforge (`guide/choosing-witforge.md`), Quickstart (`quickstart.md`), Runnable examples (`guide/examples.md`)
  2. Authoring & Generating: Contract authoring (`guide/contract-authoring.md`), Configuring generation (`guide/generation.md`), Wiring & installation (`guide/wiring.md`), Real generated output (`guide/generated-output.md`)
  3. Evolution & CI: Evolving contracts (`guide/evolution.md`), CI & release freeze (`guide/ci.md`), Release migration (`guide/migration.md`)
  4. Interoperability: Non-Rust implementations (`guide/non-rust.md`), JSON projections (`guide/json-projections.md`), Component Model boundary (`guide/component-model.md`)
  5. Reference: CLI & config reference (`guide/reference.md`), Diagnostic codes (`guide/diagnostics.md`)
- Exclude `docs/design/` and `docs/aplan-pilot.md` from Starlight sync (matching current GitHub Pages exclusions; links to `docs/design/*.md` continue pointing to GitHub `blob/main/docs/design/...`).
- Temporarily add `SUMMARY.md` to `docs/_config.yml`'s `exclude:` list until `W12-009` retires Jekyll, so pushing `W12-002` before `W12-010` never exposes `/witforge/SUMMARY.html` on legacy GitHub Pages.
- Keep all scripts under `site/scripts/` strictly cross-platform (Windows path-separator normalization `\` -> `/`, scratch directories under `process.env.TMPDIR || os.tmpdir()`, and Node 20/22/24-compatible standard-library APIs with zero external npm dependencies) so `W12-009` can run `test-scripts.mjs` inside `cargo test` on Linux, macOS, and Windows CI.

## Approach

1. Author `docs/SUMMARY.md` defining the five documentation groups and page titles (using valid relative links `index.md`, `quickstart.md`, `guide/*.md` so `crates/witforge-cli/tests/docs.rs` passes cleanly) and exclude `SUMMARY.md` in `docs/_config.yml`.
2. Implement `site/scripts/markdown-utils.mjs` with pure, unit-tested helpers:
   - Parse `docs/SUMMARY.md` sections and ordered page entries.
   - Strip legacy YAML frontmatter (if any) and leading H1 heading cleanly for Starlight (which renders `title` from frontmatter), extracting an accurate page `description` from the opening prose paragraph (cleaned of Markdown syntax).
   - Rewrite relative `.md` links between published docs into canonical `/witforge/docs/.../` trailing-slash links (or absolute `https://asamarts.github.io/witforge/docs/.../` links for `llms-full.txt`) while preserving `#fragment` anchors and skipping fenced code blocks and inline code spans.
   - Generate GitHub-compatible heading slugs (verifying `### WF1015` yields `wf1015` to match `witforge::diagnostic::help_uri`).
   - Provide reusable `findEmDashesInText` and `findEmDashesInHtml` helpers for both tests and `W12-008`.
3. Implement `site/scripts/sync-docs.mjs` to wipe and regenerate `site/src/content/docs/docs/` and `site/src/data/sidebar.json` deterministically, attaching `editUrl` pointing to `https://github.com/asamarts/witforge/edit/main/docs/<rel-path>`. Wire `sync:docs` and `test:scripts` scripts into `site/package.json`.
4. Implement `site/src/pages/llms.txt.ts` (compact structured map of witforge, live version from `Cargo.toml`, key links, and per-page summaries, zero em dashes) and `site/src/pages/llms-full.txt.ts` (full concatenated plain-Markdown corpus of all published guides in `SUMMARY.md` order with legacy frontmatter stripped and relative links rewritten to absolute canonical `https://asamarts.github.io/witforge/docs/.../` URLs).
5. Write comprehensive Node unit tests in `site/scripts/test-scripts.mjs` using only `node:test` and `node:assert/strict`.

## Edge cases

- Relative links inside fenced code blocks (such as `wit`, `toml`, `sh`, or `markdown` examples) or inline backticks must never be rewritten.
- Links like `../quickstart.md#step-2` from `docs/guide/*.md` and `guide/wiring.md#prebuilt-binaries` from `docs/index.md` must resolve cleanly to `/witforge/docs/quickstart/#step-2` and `/witforge/docs/wiring/#prebuilt-binaries`.
- Links to `docs/guide/index.md` or `./` from within `docs/guide/` must rewrite cleanly to `/witforge/docs/`.
- Syncing must fail fast if a file listed in `docs/SUMMARY.md` does not exist on disk, or if a published `.md` file under `docs/` (outside `docs/design/`, `docs/aplan-pilot.md`, `docs/SUMMARY.md`, and `docs/guide/index.md`) is missing from `docs/SUMMARY.md`.
- `docs/SUMMARY.md` is scanned by `aplan check-docs` (`docs/**/*.md` in `.aplan.yml`) and by `crates/witforge-cli/tests/docs.rs`; confirm both pass with zero warnings.
- `llms-full.txt` carries existing `docs/` em dashes until `W12-006` removes them; full-corpus zero-em-dash gating on `llms-full.txt` is enforced in `W12-008`.

## Out of scope

- Rewriting or editing prose inside `docs/*.md` (`W12-006`).
- Generating legacy `.html` redirect stubs (`W12-007`).
- Full post-build link and full-corpus em-dash validation across `site/dist/` (`W12-008`).
