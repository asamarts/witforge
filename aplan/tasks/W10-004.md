## Why

The 0.4 surface adds dependency packages, foreign world interfaces,
dependency glue, and opt-in Serde. The 1.0 criteria require the
conformance matrix, public API inventory, and protobuf compatibility gates
to cover that whole surface, not only the original single-package model.

## Acceptance criteria

- [x] `tests/conformance.rs` exercises the dependency, foreign-world,
      dependency-conversion, unsupported-dependency, and Serde fixtures through every
      applicable emitter
- [x] the public API inventory documents `WorldInterface.package`,
      `Model.dependencies`, and the complete `plan` entry points for dependency-aware
      output; `cargo semver-checks` is clean against the 0.4.1 baseline
- [x] `buf breaking` is documented and run against every released tag, including the
      dependency fixtures
- [x] JSON Schema dependency behavior is either implemented self-contained or explicitly
      documented as an external-URN limitation with a recorded decision
- [x] the pre-golive leaner-glue option is evaluated and either implemented or declined
      with a recorded rationale
- [x] dependency and Serde usage examples are added to the quickstart or a linkable example
