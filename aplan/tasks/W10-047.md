## Why

Audit finding A3 (critical). Type identity for a dependency is `namespace:name/interface/type`
with no version (`model.rs:912-918`, `330-334`; `emit/versions.rs:239-247`). Two versions of
one package in a dependency graph are therefore one package to the lockfile and to every
emitter.

## Reproduction (re-run 2026-11-18)

```wit
// wit/v0.1/deps/shared-a/s.wit
package ex:shared@0.1.0;
interface types { record item { a: u32 } }
// wit/v0.1/deps/shared-b/s.wit
package ex:shared@1.0.0;
interface types { enum item { x, y } }
// wit/v0.1/c.wit
package ex:root@0.1.0;
interface api {
  use ex:shared/types@0.1.0.{item as old-item};
  use ex:shared/types@1.0.0.{item as new-item};
  record r { x: old-item, y: new-item }
}
```

`check` and `lock --first` exit 0; both lockfile entries have type `ex:shared/types/item`.
`proto` exits 0 and emits `ex.shared.v0.TypesItem y = 2` for the 1.0.0 enum. `schema` refers
only to the v0 definition. `glue` and `rust` exit 1 with "`shared` and `shared` both map to
module".

Reviewer-run: switching a released field from one dependency version to the other passes
`lock --against` and `check --against`; a root that depends on an earlier version of its own
package emits `TypesItem` twice.

## Proposed fix

Refuse the graph. Putting the version into canonical type strings would change the content of
frozen released lockfiles, and a single process cannot link two prost packages with one name.

## Acceptance criteria

- [ ] `check` exits 1 with a diagnostic that names the package and both versions when a
      dependency graph holds two versions of one `namespace:name`
- [ ] `check` exits 1 when a dependency has the root package's `namespace:name`
- [ ] tests cover both refusals for `check`, `lock`, and every generator
- [ ] `dependencies.md` states the rule and what to do instead (one version per graph; a new
      major of a dependency is adopted by all dependents at once)
