## Why

Adversarial audit found that `witforge::inspect` always emitted `wire_number: null` for dependency members (passing the root lockfile instead of deriving each dependency's deterministic lockfile), skipped `ensure_directory_version` (`WF1031`), emitted `WF9000` on wrong-package `wire.lock`, followed symlinked `wire.lock`, attached stale wire numbers on kind/type mismatch, ordered `retired` by manifest line instead of semver, and ignored `--released` on single-version CLI targets.

## Acceptance criteria

- [x] Dependency members in `inspect` JSON IR carry deterministic non-null `wire_number`s
- [x] `load_single_version` checks `ensure_directory_version` (`WF1031`), refuses symlink/non-regular `wire.lock`, emits `WF1002` with file location on wrong-package lockfiles, and refuses kind/type/reintroduction conflicts
- [x] `inspect_root_json` sorts `retired` canonically; CLI refuses explicit `--released` on single version directories and emits `WF9004` on malformed version dirs
