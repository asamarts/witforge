## Why

Audit finding A6 (high). Wrapper messages for nested lists, options, and results are named by
concatenating words, and an existing wrapper is reused by name alone (`proto.rs:1338`, `1092`,
`1408-1462`). Two different types can produce one name, and the second silently gets the
first one's schema. `emitters.md` section 4.4 says a collision is a hard error.

## Reproduction (re-run 2026-11-18)

```wit
package ex:w@0.1.0;
interface ab { record cd { a: u8 } }
interface list-of-ab { record cd { b: string } }
interface api {
  use ab.{cd as cd1};
  use list-of-ab.{cd as cd2};
  record r { first: list<list<list<cd1>>>, second: list<list<cd2>> }
}
```

`witforge proto` exits 0 and emits `repeated WitforgeListOfListOfAbCd first = 1;` and
`repeated WitforgeListOfListOfAbCd second = 2;`: `second` is encoded with the wrapper built
for `first`.

Reviewer-run: `result<cd-and-ab-cd, cd>` and `result<cd, cd-and-ab-cd>` collide the same way.

## Decision

Decided by the owner on 2026-11-19: a wrapper is looked up by the type it wraps.
Two different types that would produce one wrapper name are refused with exit 1
and a message naming both. No existing wrapper name changes, so the naming scheme
of `emitters.md` section 4.4 stays and its last rule ("a wrapper name collision
with a user type or another wrapper is a hard error") becomes true.

## Edge cases

- The two collisions of the reproduction: nested lists across interfaces whose
  names concatenate to one string, and `result` sides whose names contain `and`.
- A wrapper against a user type: interface `witforge` with a type `list-of-string`
  is `WitforgeListOfString`, which is also the wrapper of `list<string>`.
- Two spellings of one type share one wrapper and are not a collision:
  `list<list<id>>` with `type id = u32` beside `list<list<u32>>`, and the byte-list
  spellings of `W10-046`.
- A named option that takes its interface-prefixed name as its direct wrapper
  (section 4.4) against an anonymous wrapper of the same name.
- A collision that a later minor introduces against a wrapper already in the
  major's shared proto file. Refused at that minor; the remedy is to rename the
  new type.
- Root and dependency wrappers are in different proto packages and cannot collide.
  Which package defines a wrapper is `W10-061`.
- The message names both canonical types and the wrapper name. `proto` and `glue`
  give the same message, and `check` reports it (`W10-067`), so a contract cannot
  be locked and then turn out to be ungeneratable.
- Every golden proto and glue file of the existing fixtures is unchanged; that is
  the proof that no name moved.

## Acceptance criteria

- [x] the wrapper for a type is looked up by the type, not by the generated name
- [x] two types that would produce one wrapper name are refused with exit 1 naming both,
      and `emitters.md` section 4.4 describes the lookup
- [x] no wrapper name of an existing fixture or example changes
- [x] tests cover the list collision, the result collision, and a wrapper against a user
      type
