## Why

The current robustness layer is proptest, not a coverage-guided fuzzer. A fuzz harness can
explore arbitrary WIT text, lockfile text, and model shapes beyond the property generator's
distributions and catch parser or emitter panics.

## Acceptance criteria

- [x] a `cargo-fuzz` workspace with at least one target for WIT package text and one for
      `WireLock::parse` plus emitter inputs
- [x] the targets are documented in `ci/README.md` with the pinned nightly and a reproducible
      invocation
- [x] a short local smoke run (`-runs=100` or equivalent) completes without a crash
- [x] the fuzz harness does not add a blocking stable-CI job unless it is proven stable on a
      pinned nightly

## Why it is untestable

cargo-fuzz runs under a nightly toolchain and sanitizers outside the configured cargo test
runners. The smoke run and any discovered crash regression are the applicable evidence.

## Verification

- `cargo +nightly-2026-09-11 fuzz build --target x86_64-unknown-linux-gnu`
- `cargo +nightly-2026-09-11 fuzz run wit_package --target x86_64-unknown-linux-gnu -- -runs=100`
- `cargo +nightly-2026-09-11 fuzz run lockfile --target x86_64-unknown-linux-gnu -- -runs=100`
- `cargo fmt --manifest-path fuzz/Cargo.toml --check`
