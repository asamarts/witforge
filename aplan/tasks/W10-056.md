## Why

Audit findings A14 and A15 (medium).

- A record field typed by a dependency alias whose target is another named type in the
  dependency (`type alias-item = item` in the dependency, `record r { c: alias-item }` in
  the root) makes `witforge diff` exit 2 with "type `types/item` is not in the model", even
  when a version is compared with itself (re-run in the first audit pass; `model.rs:587-615`,
  `338-353`, `diff.rs:788`). Scope check re-run 2026-11-18: a dependency alias of a
  primitive, a dependency record used directly, and a dependency `list<item>` alias all work,
  so the failure is specific to an alias of a named type.
- Reviewer-run: when the root has a type with the same name, `diff` reports a wrong
  `defaulted: true` and `rust` emits `Option::None` for a record-typed field.
- Re-run 2026-11-18: `diff` does not read `wit/released`. With `wire.lock` in a released
  directory replaced by a symlink, `check` exits 2 and `diff wit/v0.1 wit/v0.2` exits 0.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
`diff` applies the released-directory checks that `check` applies. It
reads the `released` file beside an endpoint's version directory, as `check` does
by default, and gets no new option. `diff.md` and `emitters.md` section 5.1 say
today that `diff` does not read the manifest; both change.

## Edge cases

- A dependency alias of a record, an enum, a variant, and a flags type; a chain of
  two aliases; the alias inside `list`, `option`, and `result`; as a parameter and
  as a function result; and under a `use … as` rename in the root.
- A root type with the same name as the dependency type (`item` in both). Default
  detection resolves a name in the package that declares it.
- A version compared with itself: no changes, exit 0.
- Both endpoint forms: a version directory and a WIT root.
- Endpoints in two different roots, for example an old checkout beside the working
  tree. Each endpoint uses the manifest of its own root.
- An endpoint with no `released` file beside it gets no released-directory checks.
- A released endpoint whose `wire.lock`, `contract.wit`, or `deps/` entry is a
  symlink: exit 2, as `check` gives.
- A malformed `released` file beside an endpoint: exit 2, as for `check`.

## Acceptance criteria

- [x] `diff` resolves a dependency alias of a named type and a test compares such a contract
      with itself and with an evolved version
- [x] default detection resolves names in the package that declares them
- [x] `diff` applies the released-directory checks that `check` applies, and `diff.md` and
      `emitters.md` section 5.1 say so
