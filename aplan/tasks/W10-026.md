## Why

`diff` does not enforce its documented old→new argument order. Passing the newer endpoint
first silently produces a reversed report; an additive optional field becomes a
`removed`/`wire:BREAKING` change and `--check` fails where the forward comparison passes.
Separately, a direct version-directory endpoint with no `wire.lock` is classified as a WIT
root and reports “no version directories” instead of the actionable missing-lock message
`check` already prints. WIT-root endpoints also validate declaration-order fingerprints
while direct endpoints deliberately accept a stale order to report a reorder; the docs claim
they agree and must state the real boundary.

## Acceptance criteria

- [ ] `diff` rejects a second endpoint whose package version is older than the first, with an
      actionable error; same-version comparison behavior is either preserved and tested or
      explicitly rejected
- [ ] a direct version-directory endpoint missing `wire.lock` fails with the same actionable
      missing-lock guidance as `check`, not a WIT-root diagnosis
- [ ] the root/direct declaration-order asymmetry is documented and covered: root loading
      requires current order fingerprints; direct loading accepts a stale order to report a
      reorder
- [ ] regression tests cover reversed direct and root endpoints, missing locks, and the
      root/direct order case
- [ ] the full workspace suite and plan gates pass
