## Why

Zellij combines Rust plugin traits, protobuf values crossing a Wasm boundary, permissions, and explicit mismatch handling. Its event-driven lifecycle and host commands may exceed witforge's pure-value subset.

## Acceptance criteria

- [ ] pin current plugin protobuf, SDK macros/traits, Wasm ABI, permissions, event loop, compatibility checks, and historical policy
- [ ] identify whether WIT-first generation would remove a current duplicate contract or require replacing a working custom ABI
- [ ] classify maps, state, callbacks/host commands, rendering, subscriptions, and process-independent message values against witforge 0.4
- [ ] evaluate bounded metadata/event sub-contracts separately from the full lifecycle
- [ ] state objective benefits, migration cost, exact gaps, and a go/no-go recommendation
- [ ] apply the external-adoption protocol: label material claims, decide all four gates, complete the six-dimension matrix, state the falsifier, and choose contact, defer, or no-contact
- [ ] record the canonical outreach path and policy: ask in Zellij's Discord or Matrix general channel before a large proposal; use a plugin-system issue only when maintainers request durable tracking

## Why it is untestable

This task records an external plugin architecture assessment.

## Migration disposition

Detailed candidate research and outreach preparation moved to the private `asamarts/witforge-research` repository on 2026-11-11. This public research task is dropped; `W10-001` still owns witforge's independent-adoption release gate.
