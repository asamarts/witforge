## Why

Audit finding A10 (medium). The reader accepts lines the grammar in `lockfile.md` does not
allow (`lock.rs:881-929`, `1027-1052`, `844`, `847`), and the emitters then disagree about
them.

Re-run 2026-11-18: adding these three lines to a valid lockfile is accepted by `check`,
`lock`, and `proto` (all exit 0), and the proto output reserves 7 and 5 but never 9:

```text
ex:t/api#get.old = 7 enum-case reserved
ex:t/api.gone = 5 field u32 reserved
ex:t/api/r.zz = 9 method reserved
```

Reviewer-run: a type token such as `u8:foo/bar` validates; U+00A0 is accepted as a field
separator; a fingerprint written `+AB40…` parses; an order line's parent is checked only for
containing `/`.

## Decision

Corrected while documenting the task on 2026-11-19: the criteria said that a
rejected line is exit 1. A line the grammar does not allow is a parse error, which
`lockfile.md` section 8 assigns exit 2, and the reader reports parse errors that
way today, with the line number (run 2026-11-19: `invalid number` gives exit 2 and
`line 10`). The new rejections keep exit 2.

## Edge cases

- What stays accepted, because section 4 documents it: runs of spaces or tabs
  between fields, blank lines, comment lines, CRLF line endings in a released
  lockfile, and a missing final newline. The canonical-form check of an unreleased
  lockfile is a separate rule and does not change.
- Kind against key shape: the three lines of the reproduction (an `enum-case`
  under a `#` key, a `field` under an interface key, a `method` under a type key).
- Type tokens: `u8:foo/bar`, unbalanced or empty angle brackets, a `result` with
  one slot, whitespace inside a token, a foreign name with too few or too many
  components, a bare `reserved`, and a token nested deeper than the limit of
  `W10-058`.
- Separators: U+00A0, other Unicode spaces, vertical tab, and form feed are not
  separators. A byte-order mark at the start of the file is refused or skipped by
  a stated rule.
- Fingerprints are exactly sixteen lower-case hexadecimal digits. `+AB40…`, upper
  case, and fifteen or seventeen digits are refused.
- An order line's parent is parsed with the key grammar for a type, an interface,
  or a function, not checked for containing `/`.
- Numbers: a leading zero, `0`, a sign, and a number above 536870911.
- A released lockfile is frozen. One that the looser reader accepted and the
  tightened reader refuses makes its root unusable, so run the tightened reader
  over every lockfile in the fixtures, in both examples, in alint's contract, and
  in the fixtures of every release tag before the release. The migration section
  names each form that is no longer accepted.
- The fuzz invariant has to allow for input that is accepted and not canonical
  (comments, CRLF): what is accepted renders to a canonical file, that file parses
  to the same entries and order section, and rendering it again is byte-identical.

## Acceptance criteria

- [x] an entry's kind must be one its key shape allows (`#`-keys hold parameters, interface
      keys hold methods, type keys hold fields, cases, or flags)
- [x] type tokens are parsed with the canonical-type grammar
- [x] only the documented separator and fingerprint spelling are accepted
- [x] every rejection is a parse error (exit 2) that names the line number
- [x] the lockfile fuzz target asserts that anything accepted renders to a canonical file
      that parses to the same entries and re-renders byte-identically
- [x] every lockfile in the fixtures, the examples, and the fixtures of each release tag
      is still accepted
