## Why

Audit finding A10 (medium). The reader accepts lines the grammar in `lockfile.md` does not
allow (`lock.rs:881-929`, `1027-1052`, `844`, `847`), and the emitters then disagree about
them.

Re-run 2026-11-18: adding these three lines to a valid lockfile is accepted by `check`,
`lock`, and `proto` (all exit 0), and the proto output reserves 7 and 5 but never 9:

```text
ex:t/api#get.old = 7 enum-case reserved
ex:t/api.gone = 5 field u32 reserved
ex:t/api/r.zz = 9 method reserved
```

Reviewer-run: a type token such as `u8:foo/bar` validates; U+00A0 is accepted as a field
separator; a fingerprint written `+AB40…` parses; an order line's parent is checked only for
containing `/`.

## Acceptance criteria

- [ ] an entry's kind must be one its key shape allows (`#`-keys hold parameters, interface
      keys hold methods, type keys hold fields, cases, or flags)
- [ ] type tokens are parsed with the canonical-type grammar
- [ ] only the documented separator and fingerprint spelling are accepted
- [ ] every rejection is exit 1 with the line number
- [ ] the lockfile fuzz target asserts that anything accepted re-renders byte-identically
