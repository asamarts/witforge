## Why

Second-wave adversarial audit of `0.8.0` readiness and the hosted `test (windows-latest)` CI run
identified 19 concrete defects across `freeze`, `load_sources`, `workflow`, CLI lifecycle
commands, `witforge-build`, the GitHub Action, `docs`/`glue`/`convert`/`rustfmt`/`rust` emitters,
`cargo-binstall` musl target overrides, `fuzz/Cargo.lock` release validation, and documentation.

## Acceptance criteria

- [x] `freeze` refuses symlinked `--released` manifests without dereferencing and reconciles
      case-insensitive manifest spellings against both index and `HEAD`
- [x] `load_sources` and `package_location` normalize virtual `deps/` keys with `/` on Windows
- [x] `workflow::check_release` refuses symlinked manifests and surfaces corrupt/missing
      predecessor lockfile errors on already-listed versions
- [x] `release` and `retire` enforce the cross-root `--released` guard including bare filenames
- [x] `new-version` honors `project.released` and `--released`, refuses symlinked manifests, and
      propagates manifest parse/IO errors
- [x] `witforge-build` refuses trailing separators in `include_file`, drives `pbjson` generation
      incrementally via `generate(...)` without stale `.serde.rs` disk probing, and cleans up
      scratch files on error
- [x] `action/index.js` sets `failed-command` and flushes SARIF on spawn errors with 64 MiB
      `maxBuffer`
- [x] `docs.rs` handles real `wit-parser` block comments (single-line, opening/closing banners,
      col-0 and 2-space indent) while preserving Markdown bullet lists
- [x] `glue.rs`, `convert.rs`, and `rustfmt.rs` match `rustfmt` (Editions 2021 and 2024) on
      wrapped option/list expressions, `)?` boundaries, and `fmt_let_call`
- [x] `rust.rs` accounts for niche optimization in `has_large_variant_disparity`
- [x] `witforge-cli/Cargo.toml` configures Linux musl `binstall` overrides, `ci/check-release.sh`
      and `ci/release-checklist.md` validate `fuzz/Cargo.lock`, and `CHANGELOG.md` /
      `docs/design/public-api.md` / guide docs are accurate
