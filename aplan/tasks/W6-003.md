## Why

The MVP derives only Debug, Clone, and PartialEq. Consumers may need Eq/Hash for
maps and Default for fixtures or conversions; floats constrain both.

## Acceptance criteria

- [x] transitive float detection and conditional derives are rejected for 0.x/1.0
- [x] a narrow Default policy is evaluated and rejected for 0.x/1.0
- [x] the generated API remains frozen per version
- [x] the decision and implementation disposition are recorded (declined; no task until the trigger)

## Decision

Declined for 0.x and 1.0. See
[`docs/design/overview.md`](../../docs/design/overview.md#102-conditional-eqhash-and-default-evaluation-w6-003).
Conditional `Eq`/`Hash` would need transitive float detection; `Default` has no natural value for
enums, variants, or results; and adding any derive would change a frozen per-version generated
API. No implementation task is created now. A consumer request plus a new contract version
triggers one.

## Why it is untestable

This is an evaluation and decision task; implementation would follow with golden
and compile tests.
