## Why

The Action installs four platform archives, but the permanent and release smokes execute only
Linux x86_64. macOS arm64, macOS Intel, and Windows extraction, checksum, PATH, and command
behavior are unproved. The generic tag workflow also runs the checked-out Action rather than
resolving the published ref, so CI needs a pinned published-ref matrix as independent proof.

## Why it is untestable

GitHub chooses the JavaScript Action runtime and hosted runner architecture. Repository-local
tests cannot execute the Windows or macOS Action host or resolve a remote `uses:` reference.

## Acceptance criteria

- [x] CI invokes the pinned published Action on Linux x86_64, macOS arm64, macOS Intel, and Windows x86_64
- [x] the tag workflow invokes the exact checked-out tag on all four targets after assets upload
- [x] each target downloads and verifies its own archive and runs a real contract command
- [x] the tag smoke verifies configured output through all four generators on every target
- [x] workflow and release documentation state the local-tag and published-ref proof separately
- [x] actionlint, shellcheck, local Action tests, and the hosted matrix are green
