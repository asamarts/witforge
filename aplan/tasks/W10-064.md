## Why

Audit finding B7 (medium, re-run 2026-11-18). `witforge glue … --plain-root
super::super::super::super::plain` exits 0. The root is pasted into modules at different
depths (`glue.rs:235-281`, `566-576`, `955-974`), so no relative path can be right for all of
them: the build fails with four "cannot find `plain` in `super`" errors. `self::…` behaves
the same (reviewer-run).

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
A root whose first segment is `self` or `super` is refused as a usage
error (exit 2). `crate::…` and `::name::…` are accepted. A root that starts with
a plain identifier is accepted as the name of another crate, which resolves alike
at every depth, and is written as given, so no existing output changes. Rewriting
a relative root per module depth is not done: the tool would have to know where
the consumer mounts the generated modules.

`emitters.md` section 7.2 lists `self` and `super` as valid roots today; it
changes with this task.

## Edge cases

- `crate`, `crate::a::b`, `::other::proto`, `other::proto`, and a raw identifier
  segment (`crate::r#type`).
- `self::x`, `super::x`, and `super::super::x`: refused, with a message that names
  the accepted forms.
- A first segment that is not a crate but a module of the consumer's crate
  (`plain::v0`) cannot be told apart from a crate name, and fails in the
  consumer's build as it does today. The documentation says to write `crate::`.
- A first segment equal to a module the generator emits at that level (`v0`,
  `witforge_deps`, an interface module) would resolve to the generated module.
  Refuse it.
- A keyword segment that is not raw, an empty segment, a trailing `::`, generics,
  and whitespace are errors already and stay so.
- The same validation for `plain-root` and `proto-root` in `witforge.toml`, and
  for a command-line value that overrides the file.

## Acceptance criteria

- [ ] a root that starts with `self` or `super`, or with the name of a generated module,
      is refused as a usage error; `crate::…`, `::name::…`, and another crate's name are
      accepted and compile-tested
- [ ] the configuration file's roots go through the same validation
- [ ] the documentation states the accepted forms
