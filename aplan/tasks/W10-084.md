## Why

Audit finding C12 (medium). The correct sequence for an ordinary edit is five to seven
commands with hand-chosen arguments (`lock` with the right `--against`, `check` in the same
mode, then `rust`, `proto`, `schema`, `glue` with two module roots), and the mistakes this
audit reproduced come from choosing them wrongly: `lock --first` in a second minor
(`W10-048`), a skipped version bump (`W10-042`), generators sharing an output root
(`W10-073`).

Missing today:

- `witforge.toml` is used only when `--config` names it;
- no command runs every configured generator;
- `check` takes one version directory; nothing checks a whole root, choosing `--first` or
  `--against` per directory;
- starting a minor is manual (`mkdir`, copy WIT and lockfile, edit the package version);
- recording a release is a manual edit of `wit/released`;
- no `init`.

The CLI surface freezes at 1.0 (`public-api.md`), so its shape should be decided before then.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision:
the commands are additions. Every invocation that works today keeps its meaning,
including `check <version-directory>` and the generators with an explicit root
and `--out`. The names in the criteria (`generate`, `new-version`, a command that
records a release) are proposals; the owner fixes them when the task starts,
because `public-api.md` freezes the CLI surface at 1.0. `init` is named in the
finding and is not in the criteria: it is left out unless the owner adds it.

## Edge cases

- `check` gets a version directory today. A WIT root is told apart as `diff` does
  it: it holds `v<major>.<minor>` directories. A directory that is both, or
  neither, is an error that says what was expected.
- The mode per directory: a released directory is checked in default mode, the
  lowest minor of a major as a first version, and every other directory against
  its predecessor. Cover a gap (`v0.1`, `v0.3`), two unreleased drafts at once,
  and a new major (`W10-093`).
- Discovery: the nearest `witforge.toml` from the working directory upwards. Say
  where the search stops. `--config` wins, and a flag turns discovery off.
- A discovered file must not break a command that does not need it: a stray or
  malformed `witforge.toml` further up the tree, or one with several projects and
  no `--project`, while every value is given on the command line.
- Section 11 of `emitters.md` says that `check` and `lock` do not read
  configuration files. That changes.
- `generate` runs the generators of the selected project, or of every project.
  One failing generator does not stop the others from reporting, and the exit
  status is 1 if any failed.
- `new-version`: the next minor, or a major on request. It copies every `.wit`
  file and `deps/`, and for a minor the lockfile; it rewrites the version in each
  file that has a `package` header; it refuses a target that exists. A new major
  gets no copied lockfile.
- Recording a release: validates the version first, appends one line, keeps LF
  and the final newline, refuses a version whose predecessor is unreleased, and
  does nothing for a version that is already listed.
- A root with no version directory.
- The quickstart keeps the explicit sequence as the long form, and its test
  (`W10-042`) runs the new commands as well.
- `public-api.md` lists the new commands and options.

## Acceptance criteria

- [x] `witforge.toml` is discovered from the working directory upwards, with a flag to
      disable discovery
- [x] `witforge check <root>` validates every version directory against its predecessor and
      the released manifest
- [x] `witforge generate` runs every generator the configuration names, with `--check`
- [x] `witforge new-version` creates the next minor or major from the latest version
- [x] a command appends a version to `released` after validating it
- [x] the quickstart uses these commands and its test (`W10-042`) runs them
