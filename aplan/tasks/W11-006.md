## Why

Language Check exposes closely related checker values through Extism JSON, external stdio JSON, Rust engine types, and a separate protobuf editor protocol. Its bounded checker call is the strongest current 0.4 adoption hypothesis.

## Acceptance criteria

- [ ] pin the reviewed upstream commit/release and cite its plugin, provider, Rust engine, and protobuf sources
- [ ] map every current source of truth and conversion path for checker requests, diagnostics, severities, defaults, and errors
- [ ] identify concrete duplicated maintenance, drift, compatibility, or schema problems; label unsupported claims as hypotheses
- [ ] model the smallest WIT-owned checker/provider slice and exercise it with witforge 0.4 check and relevant emitters in disposable scratch space
- [ ] prove which current JSON behavior generated Serde types/schema can preserve and identify any numeric-enum, optional-field, map, or naming mismatch
- [ ] separate benefits available without replacing Extism from any optional Component Model migration
- [ ] list upstream changes, witforge gaps, runtime non-goals, migration cost, and a go/no-go recommendation
- [ ] apply the external-adoption protocol: label material claims, decide all four gates, complete the six-dimension matrix, state the falsifier, and choose contact, defer, or no-contact
- [ ] record the canonical outreach path: a GitHub issue under Language Check's contribution policy

## Why it is untestable

The task records external-project research and disposable compatibility observations; it changes no witforge runtime behavior.
