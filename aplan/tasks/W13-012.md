## Why

Rust consumers receive generated bidirectional `convert.rs` adapters across adjacent live contract versions (defaulting added `option`/`list`/`map` fields on minor upgrades, returning structured errors on removed required members or unknown cases, and omitting non-convertible types across major boundaries). Extracting the language-neutral convertibility analysis from `crates/witforge/src/emit/convert.rs` once guarantees identical evolution rules across Rust and Wave 1 languages (TypeScript, Python, Go), while keeping existing Rust `convert.rs` output byte-for-byte unchanged.

## Acceptance criteria

- [ ] Extract a shared language-neutral version-pair convertibility analysis from `crates/witforge/src/emit/convert.rs` (including cross-major `DepLayout` pinned dependency equivalence) while proving existing Rust `convert.rs` output stays byte-for-byte unchanged
- [ ] Emit deterministic bidirectional conversion modules for adjacent live version pairs in TypeScript, Python, and Go, including explicit omission notes across major boundaries
- [ ] Cover minor additions (defaulted `option`/`list`/`map`), removed required members, unknown enum/variant cases, pinned `deps/` across majors, and cross-major omission with offline golden tests and Wave 1 CI round-trip evolution tests
- [ ] Keep all existing `0.7.0+` public library APIs strictly additive and update `docs/design/public-api-inventory.txt` if new public items are added
