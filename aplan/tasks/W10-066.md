## Why

Audit finding B11 (medium). WIT doc comments are copied verbatim into `///`
(`emit/rust.rs:684-693`). Re-run in the first audit pass:

- an indented example in a WIT comment becomes a Rust doctest in the consumer's crate and
  fails `cargo test`;
- `list<string>` and `[tags]` in a comment fail the consumer's
  `RUSTDOCFLAGS='-D warnings' cargo doc` (unclosed HTML tag, unresolved intra-doc link).

Reviewer-run: a bare carriage return in a comment makes rustc reject the generated file;
world, package, and dependency-interface comments are not carried; an interface's comment is
attached above the wrong declaration in the proto file.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
Escape, do not fence. A whole comment inside a code fence would lose
its formatting. The text is kept as Markdown; the characters rustdoc would read
as HTML or as an intra-doc link are escaped, and every code block becomes a
fenced block marked `text`, so none is compiled as a doctest.

## Edge cases

- Code blocks: indented by four spaces or a tab, fenced without a language, fenced
  as `rust`, fenced with tildes, and an unclosed fence.
- Text rustdoc reads as HTML: `list<string>`, `option<T>`, `<br>`.
- Text rustdoc reads as a link: `[tags]` and `[a][b]`. A real link `[text](url)`
  keeps working.
- A bare URL fails `rustdoc::bare_urls` under `-D warnings`; it is wrapped in
  angle brackets.
- Unbalanced backticks, and a line that ends in a backslash.
- Control characters: a bare carriage return, CRLF, NUL, vertical tab, form feed,
  U+0085, U+2028, and U+2029. None may end a comment line early in Rust or in
  proto.
- A line that starts with `/` or `!` after the comment marker must not turn the
  doc comment into another kind of comment.
- Block comments in the WIT source (`/** … */`) and their leading asterisks.
- JSON Schema `description`: control characters are escaped as JSON requires.
- Where each comment goes: a field, a case, a function, a parameter, a type, an
  interface, a world, a package, and a dependency's items. An interface has no
  declaration of its own in the proto file, so the rule says where its comment
  is written.
- Long lines are not re-wrapped, so the output stays a function of the input.
- The doc text of released per-version modules changes once. That is a
  generator-release change for the migration section.

## Acceptance criteria

- [x] generated doc comments cannot start a doctest and cannot fail `rustdoc -D warnings`;
      the escaping rule is in `emitters.md`
- [x] control characters are normalised before emission
- [x] interface comments attach to the declaration they describe in proto output
- [x] a compile-and-doc test runs `cargo test --doc` and `cargo doc -D warnings` on a fixture
      with hostile comments
