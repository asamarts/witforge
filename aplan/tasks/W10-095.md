## Why

Audit finding D3 (high for 1.0). No model type is `#[non_exhaustive]`, and all have public
fields (`model.rs`). Every addition the roadmap already names (deprecation, source
positions, maps, resources) would be a major version of the library after 1.0. `W10-035`
did this for the diff report types only.

Reviewer-read: `public-api.md` omits public items that exist (`RELEASED_MANIFEST`, eight
root-level helpers, several methods); `emit::output::absolute` has no caller.

## Decision

Decided by the owner on 2026-11-19: every public struct and enum of the model,
the lockfile, and the diagnostics is `#[non_exhaustive]`, with a constructor where
a consumer has to create one. Fields stay public. Everything that the policy
table of `public-api.md` does not list becomes private.

## Edge cases

- A `#[non_exhaustive]` struct cannot be built with a struct literal outside the
  crate. List the types a consumer constructs, and give those a constructor. The
  CLI is another crate and is the first consumer to adapt.
- A `#[non_exhaustive]` enum needs a wildcard arm in every `match` outside the
  crate. That breaks a library user of 0.5, so the changelog has an entry for
  library users.
- Making unlisted items private is a breaking change too, and goes into the same
  release.
- The derives of a public type are part of its interface. Record which are
  promised.
- Adding a field is compatible afterwards. Changing a field's type stays breaking,
  because the fields are public.
- The semver gate rejects this change by design. Lifting `--release-type minor`
  for one release has to be undone. Tie the exception to that version in a
  tracked file the workflows read, so it expires by itself and a reminder is not
  needed.
- Comparing the policy table with the crate's public items catches additions only
  with a listing of the public interface, which needs rustdoc's JSON output from
  a pinned nightly. A test that only names every listed item catches removals
  alone. Decide which one, and keep it out of the MSRV job.
- `ContractError` and the diff report types were done in `W10-035`.
- `emit::output::absolute` has no caller and is removed.

## Acceptance criteria

- [x] every public struct and enum of the model, the lockfile, and the diagnostics is
      `#[non_exhaustive]`, and each type a consumer constructs has a constructor
- [x] every public item is in the policy table, and a test compares the table with the
      crate's public API listing
- [x] items the policy table does not list are private, and unused public items are removed
- [x] the breaking change and its library-user migration guidance are prepared for the 0.7.0
      release task (`W10-099`); publication is not part of this implementation task
- [x] the semver gate (`cargo semver-checks check-release -p witforge --release-type minor`)

      minor` in `ci.yml` and `release.yml` for that release only and restores it afterwards;
      the release checklist names the step
