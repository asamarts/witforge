## Why

Python services and plugins using WIT contracts currently require `componentize-py` (embedding CPython inside Wasm) or untyped protobuf wrappers. A built-in `witforge py` emitter generates idiomatic Python 3.11+ stdlib-only frozen slotted dataclasses, `Enum`, `Protocol` interfaces, and union variants with zero runtime dependencies.

## Acceptance criteria

- [ ] Implement `witforge::emit::python` and `witforge py` CLI / `[project.<name>.python]` config emitting Python 3.11+ stdlib-only packages (`@dataclass(frozen=True, slots=True)`, `Enum`, `Protocol`, `Union`, `py.typed`, per-version modules)
- [ ] Map every supported WIT construct (`record`, `variant`, `enum`, `flags`, `option`, `result`, `char`, `list<T>`, `list<T, N>`, `map<K, V>`, aliases, interfaces, worlds, `deps/`, docstrings, deprecation notes) per `docs/design/polyglot-emitters.md`
- [ ] Enforce deterministic LF-only output, `#` ownership headers, PEP 8 clean formatting, and `--check` drift detection
- [ ] Prove emitted Python packages with golden tests and real `python3` import/runtime/typecheck verification across all supported WIT constructs
