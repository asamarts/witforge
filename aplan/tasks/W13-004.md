## Why

Python services and plugins using WIT contracts currently require `componentize-py` (embedding CPython inside Wasm) or untyped protobuf wrappers. A built-in `witforge py` emitter generates idiomatic Python 3.11+ stdlib-only frozen slotted dataclasses, `Enum`, `Protocol` interfaces, and union variants with zero runtime dependencies.

## Acceptance criteria

- [x] Implement additive `witforge::emit::python` (`#[non_exhaustive]` `PythonOptions`, no `Copy`), `witforge py` CLI, and `[project.<name>.python]` config wired into `ensure_distinct_output_roots` and `witforge generate`, emitting Python 3.11+ stdlib-only packages (`@dataclass(frozen=True, slots=True)`, `Enum`, `Protocol`, `Union`, empty PEP 561 `py.typed` marker via `output.rs`, per-version modules)
- [x] Map every supported WIT construct (`record`, `variant`, `enum`, `flags`, `option`, `result`, `char`, `list<T>`, `list<T, N>`, `map<K, V>`, aliases, interfaces, worlds, `deps/` including cross-major `DepLayout`, docstrings, deprecation notes) per `docs/design/polyglot-emitters.md`
- [x] Enforce deterministic LF-only nested output, `#` ownership headers, PEP 8 clean formatting, and `--check` drift detection
- [x] Prove emitted Python packages with offline golden/unit tests in `cargo test --workspace --locked`, verify `python3` import/runtime checks, update `docs/design/public-api-inventory.txt`, and document CLI/config keys in `docs/guide/reference.md`
