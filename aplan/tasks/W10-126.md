## Why

Fifth-wave independent adversarial audit across `W10-125` (`0349df3..5783e29`) and the full
`v0.7.0..HEAD` increment uncovered 13 concrete, reproducible defects:

- `docs.rs`: fenced code interrupting a list item leaks `list_content_col` (doctest escape);
  nested lists (`col >= 4`), multi-space list markers (`-   item`), and first-line indented
  code in list items (`-     code`) escape as live Rust doctests; odd trailing backslash in
  link title (`"a\"`), unbalanced `(` across URL+title, escaped `\>` in `<url\>`, and
  non-ASCII whitespace bypass `parse_external_link`/`is_external_link_dest` validation and
  fail `rustdoc -D warnings`.
- `glue.rs`: three off-by-one width thresholds in `push_let_else_err` (exact length 100 and
  `let_eq` length 101) and `Wrapper { value: ::core::option::Option::Some(inner) }` wrapping
  at `inner_indent >= 64` fail `rustfmt --check` under both Edition 2021 and Edition 2024.
- `convert.rs`: `record_body` and `flags_body` `wrap_ok` missed `FN_CALL_WIDTH` (60) and exact
  `MAX_WIDTH` (100), failing `rustfmt --check` under both editions.
- `rust.rs`: off-by-one `depth + 1` in `estimate_variant_layout` truncates max-depth (32)
  variant payloads and omits `#[allow(clippy::large_enum_variant)]`.
- `lib.rs`: unclosed block comment on a `package` header line leaves `*pos` at the trailing
  byte instead of advancing to `bytes.len()`.
- Cross-root `--released` manifests silently apply bare directory names (including `retired`)
  to unrelated WIT roots in `load_root_released_manifest`, `check_root`, `check_release`,
  `load_versions_with_released`, and `inspect`; multi-project `check`/`generate`/`freeze`
  blindly forward a single `--released` path to every project without `--project`.
- Symlinked `wire.lock` in unreleased directories is refused by `inspect <version_dir>`
  (`WF9004`) but silently followed by `inspect <wit_root>`, `check`, `lock`, `diff`,
  generators, and `WireLock::write_rendered_atomic`.
- `load_versions_with_released` reports `<wit_root>/released` instead of the explicit
  `--released` path on `WF1100` retirement-order diagnostics.
- Dangling-symlink `wire.lock` misclassified as `WF9002` instead of `WF9004` in
  `ReleasedManifest::load`, `release`, and `new-version`.
- `fuzz/fuzz_targets/structured_gen.rs` false-positive panics on WIT doc comments containing
  `::std::` or `@<major>.<minor>.0;` before the `package` header.
