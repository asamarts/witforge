## Why

1.0 is a promise about the library API, generated output, and conformance. It
needs a settled surface, cross-platform CI, and a conformance suite, not just
feature completeness.

## Acceptance criteria

- [x] public API is reviewed and documented
- [x] the boundary error policy is published; no typed-error promise remains for 1.0
- [x] conformance fixtures cover every supported WIT construct and mapping
- [x] CI runs Linux, macOS, and Windows (already configured and green)
- [x] 1.0 release criteria and deprecation runways are published

## Decision

The public surface is documented in
[`public-api.md`](../../docs/design/public-api.md). `anyhow::Error` remains the boundary error
type with the stable `ContractError` classification; no typed-error enum is promised for 1.0.
The conformance matrix is in [`conformance.md`](../../docs/design/conformance.md), and the
release criteria and deprecation runways are in
[`release-1.0.md`](../../docs/design/release-1.0.md).
