## Why

A fourth review, of `main` after the 0.1.1 release, found that the freeze check
followed copies as well as renames of the manifest (`git log --follow`), so a
second WIT root whose manifest resembled the first's inherited the first root's
history and failed for good; that `check` required the canonical lockfile even
for a released version, which `lock` refuses to rewrite, so a released lockfile
checked out with CRLF (`core.autocrlf=true`) or carrying a comment, as 0.1.0
accepted, could never pass `check` again; that `lock --lock` wrote into a
subdirectory of another WIT root's released directory; that the missing-lockfile
hint was not shell-quoted and dropped `--lock` and `--released`, and that a hint
for a path starting with `-` could not be run; that `glue` generated output for
a contract `proto` refuses; that `check` and `lock` accepted `wit/v0.1` holding
`@0.2.0`; and that a manual release run from a tag would publish. It also found
four earlier fixes that no test failed without: internal emitter errors through
each generator's plan, the generators' package check for a contract with no
members, their refusal of a symlinked version directory no manifest lists, and
the freeze check's exact-spelling test for `wire.lock`.

## Acceptance criteria

- [ ] the freeze check follows only renames of the manifest, and gives git paths
  literally and reads them back unquoted
- [ ] `check` reads CRLF as LF and requires the canonical lockfile only for an
  unreleased version; `lockfile.md` says what it requires and how to pin LF
- [ ] `lock` refuses a lockfile in a subdirectory of a released directory of any
  WIT root
- [ ] internal emitter errors, the generators' package check for a memberless
  contract, their refusal of an unlisted symlinked version directory, and the
  freeze check's exact `wire.lock` spelling are each guarded by a test
- [ ] hints are shell-quoted, keep `--lock` and `--released`, and spell a path
  starting with `-` so that it runs
- [ ] `glue` refuses what `proto` refuses, and `check` and `lock` refuse a
  version directory holding another version
- [ ] a command run inside a symlinked version directory is documented as seeing
  only the link's target
- [ ] `publish` and `github-release` run only for a tag push
- [ ] `AGENTS.md` no longer names 0.1.0 as the current version
