## Why

The MVP uses owned parameters for a uniform, object-safe trait. The cost of clones
should be measured before deciding whether a new contract version should use
borrowed inputs.

## Acceptance criteria

- [ ] representative host/plugin call paths are measured
- [ ] owned vs borrowed ergonomics and lifetime cost are recorded
- [ ] a decision with a trigger is added to the decision log
- [ ] no API change ships without a new contract version

## Why it is untestable

This is a measurement and decision task; implementation would follow as a new
task with tests.
