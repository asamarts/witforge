## Why

`wit-parser 0.263` already parses `map<K, V>` and fixed-length `list<T, N>`, and `WF1020` notes `map` is not supported yet. Maps (headers, labels, metadata, config tables) are the primary remaining WIT modeling gap for real-world contracts. Candidate headline feature for `0.9.0` or `1.1.0`.

## Acceptance criteria

- [x] Specify deterministic Rust (`BTreeMap<K, V>`, `[T; N]`, `char`), protobuf (`map<K, V>` / entry wrapper, length-checked repeated, range-checked `uint32`), JSON Schema, glue, lockfile canonical grammar, diff, and conversion rules
- [x] Implement across `subset`, `model`, `lock`, all emitters, `convert`, and `diff` with full compile-matrix and conformance tests
