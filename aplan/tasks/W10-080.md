## Why

Audit findings C6 and C7 (medium). No diagnostic names a source file and line.

Re-run 2026-11-18, with `wit/v0.1/a.wit` valid and `wit/v0.1/b.wit` referring to an
undeclared type on line 3:

```text
witforge: failed to load the WIT package in wit/v0.1: failed to parse package: wit/v0.1:
type `nosuch` does not exist                                  (exit 2; SARIF: WF9000, no location)
```

and for a subset violation the SARIF location is
`{"artifactLocation": {"uri": "ex:h/types/r.a"}}`: a logical name in the field GitHub code
scanning reads as a repository path, so the alert attaches to no file.

Reviewer-read: nothing calls `Diagnostic::with_position`, so no `region` is ever emitted;
drift diagnostics carry unnormalised paths; `diff --format sarif` without `--check` emits
`level: error` and exits 0; rules carry an id and no description; wit-parser can render an
error with its source snippet and this is not used.

## Edge cases

- Lines and columns are 1-based. State the column unit: SARIF defaults to UTF-16
  code units. Test a line with a tab and one with a non-ASCII character.
- CRLF files, and a file with a byte-order mark.
- A package of several files, a file under `deps/`, and a member that reaches the
  interface through `use`: the position is the declaration, not the use.
- Lockfile diagnostics carry the line in `wire.lock`. A discrepancy between the
  contract and the lockfile has two places; choose the primary one and put the
  other in `relatedLocations`.
- Paths are relative to the working directory, with forward slashes on Windows. A
  contract outside the working directory gets an absolute `file:` URI, not a path
  with `..`.
- `diff --format sarif` without `--check` exits 0 and its results are not `error`.
- `wit-parser`'s rendered message with its source snippet goes to the human
  output. The structured position comes from its span, not from parsing that text
  (`W10-096`).
- `Diagnostic::with_position` exists and has no caller. New fields on `Diagnostic`
  are additive only after `W10-095`.
- Rule help needs a public address. `docs/design/` is excluded from the site, so
  the codes need a page under `docs/guide` or `docs/reference`.
- Uploading SARIF needs `security-events: write` and is not available to a pull
  request from a fork. Workflow annotations are the fallback (`W10-086`).

## Acceptance criteria

- [x] WIT syntax and resolution errors name the file, line, and column
- [x] subset and lockfile diagnostics carry the declaring file and line; the logical name
      moves to `logicalLocations`
- [x] SARIF `artifactLocation.uri` is a repository-relative path, and levels match the exit
      status
- [x] rule metadata has a short description and a help link
- [x] each diagnostic carries what a workflow annotation needs (file, line, column, level,
      message); the Action emits the annotations under `W10-086`
