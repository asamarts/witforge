## Why

Audit finding C9 (medium).

- Re-run 2026-11-18: directories named `v0.2.0`, `V0.2`, and `v0.2-rc1` next to `v0.1` are
  ignored without a message; `witforge rust wit` exits 0 and generates only `v0_1.rs`. A
  mistyped directory name silently drops a version from the output.
- Re-run 2026-11-18: `out = "~/gen-out"` in `witforge.toml` creates a directory literally
  named `~` under the project.
- Reviewer-run: `v00.2` is an error while a version number that overflows `u64` is ignored;
  a file named `v00.2` is an error; a byte-order mark in `wit/released` is rejected.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision: a
configuration path that starts with `~` or contains `$` is refused with exit 2.
It is not expanded. Paths in the file are relative to the file, and an expanded
path would make the output location depend on the machine. Section 11.1 of
`emitters.md` already says that paths "are not expanded through `~`".

## Edge cases

- Near-miss names: `v0.2.0`, `V0.2`, `v0.2-rc1`, `v00.2`, `v0.02`, `v1`, `v1.`,
  and a number that overflows `u64`, each as a directory and as a file.
- Names that stay ignored because they do not start with `v` and a digit:
  `vendor`, `versions.md`, `released`, and hidden entries.
- An entry in `released` that names a directory which does not exist.
- Configuration paths: `~`, `~user`, `$HOME`, `${VAR}`, and `%VAR%` on Windows.
  An absolute path and a path with `..` stay accepted.
- Command-line paths are not checked; the shell has already expanded them.
- `released` with a byte-order mark, with CRLF line endings, with trailing
  whitespace, with a blank line, and with a duplicate entry.
- A byte-order mark in `witforge.toml` and in a `.wit` file. The criterion accepts
  one in `released`. Test what the TOML and WIT parsers do with one and state it;
  where a parser refuses, the message names the mark.

## Acceptance criteria

- [x] a directory or file under a WIT root whose name starts with `v` or `V` followed by a
      digit and is not a valid `v<major>.<minor>` is an error naming the entry
- [x] configuration paths that start with `~` or contain `$` are refused with exit 2
- [x] `released` is read with or without a byte-order mark
