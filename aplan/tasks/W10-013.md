## Why

Independent maintainers need to understand witforge's fit, outputs, runtime boundaries, integration path, and limitations quickly before outreach. The repository has strong source documentation but no navigable public site and the README is too dense as the landing page.

## Acceptance criteria

- [ ] README presents the product, high-fit and anti-fit profiles, outputs, install path, example workflow, release status, and documentation link concisely
- [ ] a basic public documentation site has a landing page and guides for choosing witforge, authoring a contract, generation, evolution, CI, JSON projections, and Component Model boundaries
- [ ] the site links runnable single-version and evolved examples without copying their status
- [ ] all documented commands and both examples are exercised with the published 0.4.3 binary
- [ ] GitHub Pages is configured from the committed docs tree and the published site is observed
- [ ] local and external documentation links pass and public docs state current limitations without implying unimplemented language generators

## Why it is untestable

This task changes public documentation and Pages configuration, not compiled behavior. Reverting it cannot make a Rust test fail; executable examples, package checks, link checks, and the deployed page provide the applicable verification.
