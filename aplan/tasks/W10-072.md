## Why

Audit finding B15 (medium, reviewer-run unless noted).

- Generated conversions use an untyped `Result::Ok(x)?`. If the consumer adds another
  `From<…> for ConversionError` in the including crate, type inference fails across the file
  (67 errors in the reviewer's run).
- The output triggers `clippy::redundant_closure`.
- A refusal to generate, and a `ConversionError` at run time, do not name the version pair
  or the direction.
- New-to-old conversion drops added fields silently; the evolution guide says it "reports
  data that cannot be represented".
- `#[non_exhaustive]` on `ConversionError` has no effect in the crate that includes the
  module, which is the only place it is used.

## Decision

Decided by the owner on 2026-11-19: this task ships in 0.6.0 (`W10-069`).

Default chosen while documenting the task on 2026-11-19, not an owner decision:
new-to-old conversion keeps dropping added fields and flags without reporting
them, and the guide and the specification say so. Section 9.3 already specifies
"dropped", and the evolution guide was corrected on 2026-11-18 (`W10-042`). A
checked variant can be added later without breaking anyone.

## Edge cases

- A consumer's `impl From<std::io::Error> for ConversionError`, a second `From`
  impl, and `From<ConversionError>` for the consumer's own error.
- Naming the conversion needs storage in the error. Adding a field to the existing
  struct variants breaks a pattern that names every field (`MissingMember { path }`)
  in the crate that includes the module, where `#[non_exhaustive]` has no effect.
  Default: accept that for 0.6.0 and put it in the migration section (patterns add
  `..`), because `convert.rs` is regenerated when a consumer moves its pin.
- A chain of versions: converting `v0.1` to `v0.3` goes through `v0.2`, and the
  error says which hop failed.
- A refusal to generate names both versions, the direction, and the member.
- A version pair in which no type converts must not leave an unused import or
  dead code behind.
- The output is free of Clippy warnings at the default level. Pedantic lints are
  not promised; say which level the harness enforces (`W10-068`).
- `MissingMember` and `UnknownCase` keep `'static` WIT identities.
- The specification's statement about `#[non_exhaustive]` was corrected on
  2026-11-18 (`W10-043`). What remains is the doc comment that is generated on
  `ConversionError`.

## Acceptance criteria

- [x] generated conversions compile when the consumer adds its own `From` impls for
      `ConversionError` (a compile test adds one)
- [x] the output is free of Clippy warnings at the default level
- [x] generation refusals and `ConversionError` name the two versions and the direction
- [x] the guide, the specification, and the generated doc comment say that new-to-old
      conversion drops added fields and flags without reporting them
- [x] the generated doc comment on `ConversionError` says what `#[non_exhaustive]` does
      and does not do, as section 9.1 now does
