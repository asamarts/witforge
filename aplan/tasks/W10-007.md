## Why

Generators currently require byte-for-byte-equivalent dependency models across contract
versions, while version-level `check` and `diff` can call a changed dependency compatible.
The 1.0 contract needs one explicit invariant and one actionable comparison.

## Acceptance criteria

- [x] the 1.0 policy explicitly requires one identical pinned dependency graph across versions
      in a generated WIT root
- [x] one shared comparison reports the first changed package, version, interface, type, or
      function and is used by every generator
- [x] `diff` refuses mismatched dependency graphs instead of reporting no compatible changes
- [x] tests cover added, removed, version-bumped, shape-changed, and docs-only dependency changes
- [x] documentation states what single-version `check` can and cannot establish
