## Why

Generators currently require byte-for-byte-equivalent dependency models across contract
versions, while version-level `check` and `diff` can call a changed dependency compatible.
The 1.0 contract needs one explicit invariant and one actionable comparison.

## Acceptance criteria

- [ ] the 1.0 policy explicitly requires one identical pinned dependency graph across versions
      in a generated WIT root
- [ ] one shared comparison reports the first changed package, version, interface, type, or
      function and is used by every generator
- [ ] `diff` refuses mismatched dependency graphs instead of reporting no compatible changes
- [ ] tests cover added, removed, version-bumped, shape-changed, and docs-only dependency changes
- [ ] documentation states what single-version `check` can and cannot establish
