## Why

Marketing pages (`/witforge/`, `/witforge/outputs/`) and Starlight documentation pages (`/witforge/docs/.../`) must feel like one cohesive product, not two stitched-together sites. Sharing a single sticky header, blue design token system, theme persistence script, OpenGraph metadata, footer, and accessible navigation across both layers gives readers instant orientation whether they arrive on the homepage, the outputs showcase, or a diagnostic code anchor.

## Why it is untestable

This task creates Astro UI layout components, Starlight component overrides, and CSS stylesheets that are not exercised by `.aplan.yml`'s Rust Cargo test runners. No `cargo test` can fail if navigation styling or theme persistence is reverted; verification runs through `npm --prefix site run build`, `check-links.mjs` in `W12-008`, and multi-viewport light/dark manual review.

## Decision

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Primary navigation bar items: brand lockup (`SiteLogo` + `witforge`), `Docs` (`/witforge/docs/`), `Quickstart` (`/witforge/docs/quickstart/`), `Outputs` (`/witforge/outputs/`), `Reference` (`/witforge/docs/reference/`), dynamic version pill (`v0.9.0` linking to the GitHub release tag), GitHub icon link, and light/dark `ThemeToggle`.
- Starlight `Header.astro` override wraps the exact same `SiteNav` alongside Starlight's Pagefind `<Search />` widget and mobile sidebar toggle so search stays one click or `Ctrl+K` away on every doc page.
- Theme storage contract matches Starlight's exact `starlight-theme` convention: `localStorage.getItem('starlight-theme')` stores `"light"`, `"dark"`, or `""` (auto/system). Treat `""` and `null` as OS preference (`prefers-color-scheme: dark`), always write `"light"` or `"dark"` onto `document.documentElement.dataset.theme` (never `""`), and notify `window.StarlightThemeProvider?.updatePickers(next)` when present.
- Because Starlight renders its own `Page.astro` (not `BaseLayout.astro`), wire `<meta name="theme-color">`, `og:image` (`https://asamarts.github.io/witforge/og-card.png`), `twitter:card`, and `Header.astro` / `Footer.astro` / `custom.css` directly in `site/astro.config.mjs` (Starlight `head:` + `components:` + `customCss:`).
- `site.css` loads only inside `BaseLayout.astro` (never polluting Starlight prose spacing) and includes explicit `:root[data-theme='dark'] .astro-code` rules mapping Shiki's `--shiki-dark` and `--shiki-dark-bg` variables so Astro's `<Code />` blocks on marketing pages switch cleanly in dark mode. `custom.css` maps Starlight's `--sl-*` variables cleanly onto `tokens.css`.

## Approach

1. Build `ThemeInit.astro` and `ThemeToggle.astro` handling Starlight's `starlight-theme` storage contract (`""` / `"light"` / `"dark"`), OS preference listeners, `<meta name="theme-color">` updates (`#0a0f1a` dark / `#ffffff` light), and `document.documentElement.classList.add('js')`.
2. Build `BaseLayout.astro` with complete `<head>` metadata: canonical URL, OpenGraph + Twitter Card tags pointing to `https://asamarts.github.io/witforge/og-card.png`, `favicon.svg`, `theme-color`, skip-to-content link, `SiteNav`, main slot, `SiteFooter`, and lightweight progressive-enhancement scripts for accessible `[data-tabs]` and `[data-copy]` controls.
3. Build `SiteNav.astro` with frosted backdrop blur, active-route state in cobalt blue, responsive mobile navigation disclosure working cleanly at `375px`, and >= 3:1 keyboard focus outlines.
4. Build Starlight overrides `site/src/components/starlight/Header.astro` and `site/src/components/starlight/Footer.astro` and wire them, `site/src/styles/custom.css`, and Starlight `head:` metadata tags into `site/astro.config.mjs`.
5. Build `site/src/pages/404.astro` providing clear recovery links (`Home`, `Docs overview`, `Quickstart`, `Outputs`, `CLI reference`, `Diagnostic codes`) using `BaseLayout`.
6. Author `site/src/styles/site.css` (including `.astro-code` dark-mode Shiki rules) and `site/src/styles/custom.css` with `:root:not(.js)` progressive-enhancement rules and `@media (prefers-reduced-motion: reduce)` handling.

## Edge cases

- Switching theme on `/` and navigating to `/docs/quickstart/` (and back) must preserve the exact light/dark choice with zero FOUC, including when `starlight-theme` is empty (`""`) or absent (`null`).
- Starlight doc pages must emit `<meta property="og:image" content="https://asamarts.github.io/witforge/og-card.png">` and update `<meta name="theme-color">` on theme toggle just like `BaseLayout` pages.
- With JavaScript disabled, navigation links, code blocks, and tabbed panels must remain fully readable and operable.
- Starlight's Pagefind `<Search />` modal must respect both light and dark cobalt tokens with readable contrast on highlighted search matches.
- Mobile layout at 375px width must have zero horizontal overflow across both `BaseLayout` and Starlight pages.
