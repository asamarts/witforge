## Why

Audit finding A2 (critical). The `list<u8>` → `bytes` mapping is decided on the spelling of
the element type (`is_u8` at `proto.rs:1649` and `glue.rs:1281`), while the lockfile records
the resolved type. Two contracts with the same lockfile therefore have different encodings.

## Reproduction (re-run 2026-11-18)

```wit
package ex:b@0.1.0;
interface types {
  type byte = u8;
  record r { a: list<byte>, b: list<u8> }
}
```

`wire.lock` records `list<u8>` for both fields. `v0.proto` has `repeated uint32 a = 1;` and
`bytes b = 2;`. Respelling `a` as `list<u8>` in a later minor passes
`check --against` with an unchanged lockfile and changes the encoding of field 1.

Reviewer-run: the wrapper name `ListOfU8` is produced for both shapes, and mixing
`list<list<list<byte>>>` with the `u8` spelling produces glue that does not compile.

## Decision recorded here

The fix changes generated protobuf for a contract that today spells a byte list through an
alias. Recommendation: resolve aliases and emit `bytes` everywhere, because the lockfile
already states that the two spellings are one type; say so in the changelog as a wire-format
correction. The only known consumer (alint's proof crate) does not use an alias of `u8`.

## Acceptance criteria

- [ ] every emitter decides the byte-list mapping on the resolved element type
- [ ] a fixture with both spellings, at top level and nested three deep, generates identical
      field types and compiles against prost
- [ ] the JSON Schema emitter makes the same decision as proto and glue
- [ ] `emitters.md` states the rule and the changelog names the affected shape
