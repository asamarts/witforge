## Why

Engineers evaluating a contract compiler want two concrete answers before trying it: "Exactly how does every WIT type map into Rust, Protobuf, JSON Schema, and glue?" and "Exactly which contract edits stay wire-compatible, source-compatible, and adapter-convertible?" Creating a dedicated `/witforge/outputs/` showcase page (witforge's technical counterpart to `ayaml`'s `/benchmarks/` page) answers both questions visually and accurately in one place, linking straight into the authoritative reference guides.

## Why it is untestable

This task creates an Astro page, structured TypeScript reference tables, and an accessible SVG diagram that are not covered by `.aplan.yml`'s Rust Cargo runners. Link integrity, SVG semantics, and prose constraints are validated by `site/scripts/check-links.mjs` in `W12-008`.

## Decision

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Route the showcase page at `/witforge/outputs/` (`site/src/pages/outputs.astro`), linked from the primary `Outputs` item in `SiteNav.astro`.
- Structure the page into three focused technical sections:
  1. **WIT-to-Projection Type Mapping Matrix** (`site/src/data/matrices.ts`): tabbed/filterable reference covering primitives (`bool`, `u8`..`u64`, `s8`..`s64`, `f32`, `f64`, `char`, `string`), composite types (`record`, `variant`, `enum`, `flags`, `option<T>`, `result<T, E>`), collections (`list<u8>`, `list<T>`, fixed-length `list<T, N>`, `map<K, V>`), and cross-package `deps/` imports across Plain Rust (noting `--serde`, `--no-std`, and `--eq-hash`), Protobuf (`proto3` + `wire.lock`), JSON Schema (Draft 7 / Draft 2020-12), and checked Rust Glue (`GlueError`).
  2. **Contract Evolution & Diff Verdict Matrix**: clear compatibility table covering real contract edits with exact normative verdicts:
     - Add `option<T>`, non-byte `list<T>`, or `map<K, V>` field (wire/decode compatible; source/API breaking; `convert.rs` defaults)
     - Add `list<u8>` field (wire compatible; **decode breaking `new<-old`** due to proto3 `optional bytes` presence even though `convert.rs` defaults!)
     - Add required field (`string`, scalar, `char`, `list<T, N>`, record, etc.) (wire compatible; decode breaking `new<-old`; source/API breaking; blocks `old -> new` adapter)
     - Add enum or variant case (wire compatible; source/API breaking; decode breaking `old<-new`)
     - Remove optional / non-byte-list / map field (`decode` compatible, `wire` compatible with reserved tag, source/API breaking) vs remove required field (`decode` breaking `old<-new`) vs remove enum/variant case (`decode` breaking `new<-old`)
     - Retype field or rename item (breaking across wire/source/API/decode; belongs in a new major)
     - Add interface function (wire compatible; source/API breaking; decode breaking `old<-new`)
     - Docs-only change in a new version directory (never in-place on a frozen released directory; compatible across all views)
  3. **Evolution Lifecycle SVG Diagram (`EvolutionDiagram.astro`)**: accessible zero-JS inline SVG showing `v0.1 (released, frozen)` -> `witforge new-version` -> `v0.2 (draft, locked --against v0.1)` -> `witforge diff --git-base` + `convert.rs` adapters -> `witforge release` + `witforge freeze`.

## Approach

1. Cross-check every single mapping row and diff verdict in `site/src/data/matrices.ts` directly against `docs/design/emitters.md`, `docs/design/diff.md`, `docs/guide/json-projections.md`, and `docs/guide/evolution.md` so zero technical inaccuracies slip in (explicitly highlighting `list<u8>` `optional bytes` presence rules and `option<T>` JSON Schema `null`-vs-omittable rules).
2. Build `site/src/components/EvolutionDiagram.astro` using CSS custom properties for light/dark polarity, `role="img"`, `aria-labelledby`, `<title>`, and `<desc>`.
3. Build `site/src/pages/outputs.astro` with clean responsive table wrappers (`overflow-x: auto`), accessible category filter tabs (`All`, `Primitives`, `Composites`, `Collections`), clear semantic badges (compatible, breaking, conditional, opted-in), and direct links to deep-dive docs (`Contract authoring`, `Generated output`, `Evolution`, `JSON projections`, `Non-Rust implementations`).
4. Ensure every caption, cell, and explanatory note is concise, readable, and contains zero em dashes or AI-prose clichés.

## Edge cases

- Narrow mobile screens (`375px`) must scroll wide comparison tables smoothly inside bordered wrappers without breaking page width.
- With JavaScript disabled, all mapping rows must remain visible in the full table (progressive enhancement via `:root:not(.js)`).
- Every cell describing `Eq`/`Hash`, `no_std`, `list<T, N>`, `map<K, V>`, or `list<u8>` must reflect exact 0.9.0 behavior (`1 <= N <= 65536`, `map` keys limited to `bool`, integer, `char`, `string`, `Eq`/`Hash` omitted on float-containing types, `list<u8>` decode break on addition).
