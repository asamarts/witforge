## Why

nginx-lint maintains a versioned multi-language Component Model plugin SDK and recently migrated worlds while retaining historical fixtures. Its main plugin world uses resources, but its flat parser contract may offer a bounded value-only seam.

## Acceptance criteria

- [ ] pin the reviewed release/commit and map its WIT packages, host/resource API, parser world, SDK generators, compatibility fixtures, and version transition
- [ ] identify observed API-evolution or duplicated-SDK costs that witforge could and could not address
- [ ] check the complete WIT package and the isolated parser/value surface against witforge 0.4, recording every exact unsupported construct
- [ ] evaluate whether splitting a value-only package would provide independent value or merely restructure working code for witforge
- [ ] assess stable protobuf identity and plain Rust/schema projections only where nginx-lint has an actual second transport or schema consumer
- [ ] distinguish Component Model runtime/binding work that remains wit-bindgen/Wasmtime's responsibility
- [ ] record smallest adoption slice, migration cost, and go/no-go recommendation
- [ ] apply the external-adoption protocol: label material claims, decide all four gates, complete the six-dimension matrix, state the falsifier, and choose contact, defer, or no-contact
- [ ] record the canonical outreach path: a focused GitHub issue, because the repository has no Discussions channel

## Why it is untestable

This task is research against an independently maintained external contract.

## Migration disposition

Detailed candidate research and outreach preparation moved to the private `asamarts/witforge-research` repository on 2026-11-11. This public research task is dropped; `W10-001` still owns witforge's independent-adoption release gate.
