## Why

Java lacks native unsigned integer types and uses UTF-16 `char`, so standard `protoc --java_out` messages cannot enforce WIT's unsigned narrow-integer ranges, Unicode scalar code points, closed enums, required `optional` presence, or fixed-length list bounds on their own. Checked Java glue targeting `com.google.protobuf` enforces exact WIT decode and encode parity.

## Acceptance criteria

- [ ] Implement additive opt-in Java checked protobuf glue (`witforge java-glue` / `[project.<name>.java-glue]` wired into `ensure_distinct_output_roots` and `witforge generate`) targeting official `com.google.protobuf` (`protobuf-java` + `protobuf-java-util` `JsonFormat`, supporting `java_multiple_files = true|false` paired with `W11-039`, structured `WitforgeGlueException`)
- [ ] Enforce all 13 rows of the WIT decode profile plus encode-side unsigned/narrow integer (`Integer.compareUnsigned`/`Long.compareUnsigned`) and Unicode scalar (`Character.isValidCodePoint` and non-surrogate) validation for binary and proto3-JSON payloads
- [ ] Add offline golden/unit tests in `cargo test --workspace --locked`, add a SHA-pinned Java 21 conformance CI job in `.github/workflows/ci.yml` running `javac` and `W11-034` conformance vectors, update `docs/design/public-api-inventory.txt`, and document CLI/config keys in `docs/guide/reference.md`
