## Why

Audit finding C8 (low).

- Re-run in the first audit pass: `witforge diff wit/v0.2 wit/v0.1` prints "cannot diff
  version 0.1.0 against older version 0.2.0"; the two versions are swapped
  (`diff.rs:241-243`).
- Reviewer-run: the remedy text says to run a bare `witforge lock`
  (`emit/versions.rs:319`, `diff.rs:378`), which is a usage error without a directory; a
  generator run with a missing `wire.lock` prints only "failed to read";
  `witforge check wit` on a WIT root says "no `package` header" without saying that a
  version directory is expected.

## Edge cases

- A test takes each remedy the tool prints and runs it as printed. That is what
  keeps "run `witforge lock`" from coming back without its directory.
- A remedy that needs a path the tool does not know, such as the previous
  lockfile for `--against`, names the missing part in words. It does not print a
  command that cannot run.
- A path with a space in a printed command is quoted.
- The reversed-endpoints message names the two versions in the order given, and
  the command with the arguments swapped.
- A generator on a root where one version lacks `wire.lock` names the file and
  the two ways forward (`--first`, or a copy and `--against`), as `check` does.
- `check` on a WIT root says that a version directory is expected and lists the
  ones it found.
- The JSON and SARIF `message` fields carry the corrected text. The tests match
  stable substrings, so wording can still improve.

## Acceptance criteria

- [ ] each message above is corrected and asserted by a test
- [ ] every remedy the tool prints is a command that runs as printed
