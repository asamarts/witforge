## Why

Audit findings B8 and B10 (medium).

- Re-run 2026-11-18: a dependency declaring `record get-request` and `get: func()` makes
  `witforge proto` exit 1 ("proto name `TypesGetRequest` is produced by both …") and
  `witforge glue` exit 0 (`glue.rs:120-131`). Glue is generated for a schema that cannot
  exist.
- Reviewer-run: for a foreign named option in a list or oneof position, `from_proto` accepts
  an unset wrapper as `None` (`glue.rs:2389-2392`); the local and anonymous paths return
  `InvalidState` for the same input.
- Reviewer-run: synthesized glue helpers have no doc comment although `emitters.md`
  section 7.1 says each gets one, and empty doc lines carry trailing whitespace.

## Edge cases

- `glue` gives the message and exit status that `proto` gives for a collision in
  the root and for one in a dependency. Both are also reported by `check`
  (`W10-067`).
- An unset wrapper on every path: a local named option, an anonymous option, and a
  foreign named option, each as a field, a list element, a oneof member, a
  parameter, and a function result.
- An absent message field is `MissingField`; a present wrapper whose oneof is
  unset is `InvalidState`. The two stay distinct.
- Proto3 JSON: a `null` wrapper and an absent one.
- Senders: glue's own `to_proto` always sets the oneof, so no message from
  generated code is newly refused. Check that the decode rules for non-Rust
  implementations (`docs/guide`) already require a set wrapper, and add the
  sentence if they do not.
- An empty doc line is `///` with nothing after it, in plain Rust, glue, and the
  proto comments. A test scans every golden file for trailing whitespace.
- A synthesized helper's doc comment names the WIT type or function it serves.

## Acceptance criteria

- [ ] glue runs the proto emitter's validation for the root and every dependency
- [ ] an unset wrapper is `InvalidState` on every path, with a test per path
- [ ] generated helpers are documented as the specification says and no generated line ends
      in whitespace
