## Why

Go matches WIT's exact signed/unsigned integer widths (`uint8..uint64`, `int8..int64`), Unicode `rune`, and fixed-length arrays (`[N]T`), yet existing Go WIT tooling (`wit-bindgen-go`) targets TinyGo/WASI 0.2 runtime helpers rather than plain zero-dependency Go packages.

## Acceptance criteria

- [ ] Implement `witforge::emit::go` and `witforge go` CLI / `[project.<name>.go]` config emitting `gofmt`-clean Go 1.22+ stdlib-only packages (`struct`, typed enum constants + `Valid()`, sealed variant/result interfaces, exact integer widths, native `[N]T`, `deps/` imports, `worlds` metadata, Go doc comments)
- [ ] Enforce deterministic LF-only output, `// Code generated by witforge` ownership headers (matching standard Go conventions), and `--check` drift detection
- [ ] Prove emitted Go packages with golden tests and real `go build` / `go vet` / `gofmt` checks covering all supported WIT constructs
