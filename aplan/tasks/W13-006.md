## Why

Go matches WIT's exact signed/unsigned integer widths (`uint8..uint64`, `int8..int64`), Unicode `rune`, and fixed-length arrays (`[N]T`), yet existing Go WIT tooling (`wit-bindgen-go`) targets TinyGo/WASI 0.2 runtime helpers rather than plain zero-dependency Go packages.

## Acceptance criteria

- [ ] Implement additive `witforge::emit::go` (`#[non_exhaustive]` `GoOptions`, no `Copy`), `witforge go` CLI, and `[project.<name>.go]` config wired into `ensure_distinct_output_roots` and `witforge generate`, emitting `gofmt`-clean Go 1.22+ stdlib-only packages (`struct`, typed enum constants + `Valid()`, sealed variant/result interfaces, exact integer widths, native `[N]T`, `deps/` imports with `DepLayout`, `worlds` metadata, Go doc comments)
- [ ] Enforce deterministic LF-only nested per-version package directories via `output.rs`, `// Code generated by witforge ... DO NOT EDIT.` ownership headers, and `--check` drift detection
- [ ] Prove emitted Go packages with offline golden/unit tests in `cargo test --workspace --locked`, verify `go build`/`go vet`/`gofmt` checks, update `docs/design/public-api-inventory.txt`, and document CLI/config keys in `docs/guide/reference.md`
