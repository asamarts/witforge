## Why

Audit findings F6 and F8 (low).

- There is no `CONTRIBUTING.md`, issue or pull-request template, or code of conduct, and no
  page says how to update golden files or run the gates locally with `TMPDIR` set. The
  repository is public.
- 29 cross-links in `docs/` point at `.html` targets, which work on the Pages site and are
  404 when the same file is read on GitHub (re-run in the first audit pass).

## Why it is untestable

This is documentation and repository metadata.

## Edge cases

- Links between documentation pages are written as relative `.md` paths. GitHub
  follows them as they are, and GitHub Pages rewrites them when it builds the
  site.
- The README is also shown on crates.io, where a relative link is broken. Its
  links to the site stay absolute.
- A public page that links into `docs/design/` leads nowhere on the site, because
  that tree is excluded. Such a link goes to the file on GitHub.
- The link check covers both forms: the files in the repository, and the built
  site.
- Anchors inside a page, not only the page.
- `CONTRIBUTING.md` says where the tests write their scratch files and how
  `TMPDIR` moves them. It describes how golden files are regenerated as that is
  done today.
- A contributor without `aplan`: say what they do instead, and who writes the
  task.
- A code of conduct is in the finding and not in the criteria. Adopt one or
  record that none is adopted.
- The issue form asks for the version, the command, and a contract that
  reproduces the problem.

## Acceptance criteria

- [ ] `CONTRIBUTING.md` covers the local gates, scratch space, golden updates, the plan
      (`aplan`), and the rule that a contract change is a new version directory
- [ ] issue and pull-request templates exist
- [ ] links between documentation pages resolve both on GitHub and on the site, and the link
      check covers both
