## Why

Nushell's process-plugin protocol has handshake/versioning, concurrent calls, streams, callbacks, signals, and rich dynamic values. It is strong protocol-evolution prior art but probably outside the current subset.

## Acceptance criteria

- [ ] pin the current protocol reference and implementations for JSON/MessagePack, signatures, values, streams, callbacks, cancellation, and compatibility negotiation
- [ ] identify bounded value/message portions where WIT-first generation could objectively remove duplication
- [ ] classify recursive/dynamic values, maps, streams, concurrency, callbacks, signals, and custom values against witforge 0.4
- [ ] compare Nushell's handshake/version evolution with witforge's lockfile and version-conversion model
- [ ] state objective benefits, migration cost, exact gaps, and a go/no-go recommendation
- [ ] apply the external-adoption protocol: label material claims, decide all four gates, complete the six-dimension matrix, state the falsifier, and choose contact, defer, or no-contact
- [ ] record the canonical outreach path: a GitHub Discussion for design discovery, with Discord or an issue only as directed by the contribution guide

## Why it is untestable

This is external protocol research and decision documentation.
