## Why

Audit finding F-04:
1. If `old` had a live `option<u32>` at number 1 and `new` removes it without reserving and assigns number 1 to `option<string>`, `diff --check=decode` exits 0 despite guaranteed binary decode failure in both directions.
2. If `new/wire.lock` deletes or alters an entry that was `reserved` in `old/wire.lock` (within the same major), `diff --check=wire` reports zero changes (`COMPATIBLE`, exit 0).

## Decision

- Detect wire-number reuse against both old reserved numbers and old live numbers, marking reused additions and affected removals as `wire_breaking` and `DecodeVerdict::breaking_both()`.
- Add `ChangeElement::ReservedEntry` (`"reserved entry"`, semver-safe on `#[non_exhaustive]`) with `ChangeKind::Removed` (and `Renumbered`/`Retyped` if altered) and `wire_breaking: true` for same-major `reserved` entry regressions.

## Acceptance criteria

- [x] Reusing a removed live member's wire number fails both `--check=wire` and `--check=decode` (`BREAKING(both)`)
- [x] Deleting or altering a same-major `reserved` lockfile entry reports `reserved entry` as `wire: BREAKING`
- [x] Cross-major diffs continue to treat each major as an independent wire namespace
- [x] Unit, CLI, and JSON diff tests cover both regressions
