## Why

The second audit found that the two properties witforge exists to provide do not hold for
ordinary contracts: wire identity can change without a gate noticing (`W10-045` to
`W10-058`), and generated code can fail to compile while every command exits 0 (`W10-059` to
`W10-067`). The release also carries the fixes for data loss and non-determinism in the tool
itself (`W10-073`, `W10-075`, `W10-077`, `W10-078`). Several fixes change generated output
for affected contracts (`W10-046`, `W10-050`, `W10-059`, `W10-077`), so they belong in one
minor release with a migration section rather than in patch releases.

The owner decided on 2026-11-18 not to publish a 0.5.1 (`W10-044`, dropped). The fixes that were
already on `main` after `v0.5.0` (atomic generated writes, symlink refusal in released
directories, `diff` reversed-endpoint rejection and missing-lock guidance, required-addition
blocker notes, Action request timeouts) and the corrections of `W10-039` to `W10-043` therefore
ship in this release.

## Acceptance criteria

- [ ] every blocker is closed with test evidence
- [ ] the changelog has a migration section listing each change that alters generated output
      or refuses a previously accepted contract, and how to tell whether a contract is
      affected
- [ ] the compile matrix from `W10-068` passes on the release commit
- [ ] the changelog section lists every user-visible change since `v0.5.0`, including the ones
      merged before the second audit
- [ ] the tagged Action runs `check` and `diff` on a hosted runner, and the log shows both
      commands
- [ ] alint's proof crate regenerates and passes against the release

## Why it is untestable

A release is a publication step; the release workflow's gates are its evidence.
