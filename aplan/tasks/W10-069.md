## Why

The second audit found that the two properties witforge exists to provide do not hold for
ordinary contracts: wire identity can change without a gate noticing (`W10-045` to
`W10-058`), and generated code can fail to compile while every command exits 0 (`W10-059` to
`W10-067`). The release also carries the fixes for data loss and non-determinism in the tool
itself (`W10-073`, `W10-075`, `W10-077`, `W10-078`) and three changes to generated output
that the owner added on 2026-11-19 (`W10-070`, `W10-072`, `W10-074`). Many of these fixes
change generated output or refuse a contract that was accepted, so they belong in one
minor release with a migration section, not in patch releases.

The owner decided on 2026-11-18 not to publish a 0.5.1 (`W10-044`, dropped). The fixes that were
already on `main` after `v0.5.0` (atomic generated writes, symlink refusal in released
directories, `diff` reversed-endpoint rejection and missing-lock guidance, required-addition
blocker notes, Action request timeouts) and the corrections of `W10-039` to `W10-043` therefore
ship in this release.

## Why it is untestable

A release is a publication step; the release workflow's gates are its evidence.

## Decision

Decided by the owner:

- 2026-11-18: no 0.5.1 is published (`W10-044`, dropped). The fixes that were on
  `main` after `v0.5.0` and the corrections of `W10-039` to `W10-043` ship in this
  release.
- 2026-11-19: `W10-070` (JSON Schema results), `W10-072` (generated conversions),
  and `W10-074` (clean generated Rust) join this release. Each changes generated
  output, and a consumer should regenerate and read one migration section once.

Not a blocker, by choice: `W10-086`. The documented Action snippets were made safe
under `W10-039`, and the changelog says what a workflow that already passes the
diff inputs will see.

## Edge cases

- Order of the two version edits. The release-preparation commit moves the
  workspace version and the documentation to 0.6.0 and leaves `ci.yml` on 0.5.0.
  The commit after publishing moves `ci.yml`. From the first commit after the tag,
  `ci/check-release.sh` fails until that second edit is made.
- The semver gate compares 0.6.0 with 0.5.0 under `--release-type minor`. A
  blocker that needs a breaking library change fails it. `W10-095` is not in this
  release, so such a change is made additively, or `W10-095` joins the release
  with the gate exception that task describes.
- The protobuf history gate runs every fixture against all eleven earlier
  releases. Expected to pass: added `reserved` statements (`W10-045`), added
  wrapper messages (`W10-060`), and leading dots (`W10-062`). The byte-list
  correction (`W10-046`) must not touch an existing fixture, and `W10-074` keeps
  the empty method enum in the proto file for this reason.
- Every consumer's generated output changes: the ownership header (`W10-073`),
  formatting and documentation (`W10-066`, `W10-074`), identifiers of upper-case
  words (`W10-059`), and the result schema (`W10-070`). The migration section has
  one entry per change, each with how to tell whether a contract is affected.
- The tagged Action smoke in `release.yml` passes no diff input (read 2026-11-19:
  it runs `check` and the generators). The criterion about the hosted log needs a
  step there that passes `diff-old` and `diff-new`, with `diff-check: "false"`
  because `examples/evolved` is source-breaking.
- Publication to crates.io cannot be undone and runs before the binaries are built
  (`W10-087` is not a blocker). If a platform build fails afterwards, the remedy
  is 0.6.1, not a moved tag.
- A released directory that the new refusals make unusable (`W10-045`, `W10-047`,
  `W10-053`): confirm that no fixture, example, or alint contract is one, and name
  the cases in the migration section.
- The minimum supported Rust version stays 1.88 unless a blocker needs a newer
  one, and then the changelog says so.
- The `[Unreleased]` section becomes the dated 0.6.0 section, and its opening note
  that nothing in it is released goes.
