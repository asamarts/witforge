## Why

All five language emitters and the `W11-001` plugin runner should participate seamlessly in `witforge generate`, `witforge.toml`, the published GitHub Action, and CI verification so polyglot codegen cannot drift or regress across Rust, TypeScript, Python, Go, Java, and C#.

## Acceptance criteria

- [ ] Wire `ts`, `py`, `go`, `java`, `csharp` (plus their glue options) and configured plugins into `witforge generate` (`--only`, `--check`, `witforge.toml`) without altering behavior for projects that only configure existing Rust/Proto/Schema/Glue/Doc outputs
- [ ] Extend `action.yml` and `action/index.js` (`generators:` allowlist + `action/test.js` unit tests) to support the polyglot emitters cleanly
- [ ] Add a dedicated multi-language CI job in `.github/workflows/ci.yml` compiling emitted output and executing `W11-034` cross-language conformance round-trip tests across Rust, TypeScript, Python, Go, Java, and C#
- [ ] Document the new CI job and Action inputs in `ci/README.md` and `docs/design/action.md`
