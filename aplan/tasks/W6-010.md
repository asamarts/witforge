## Why

An independent review of 0.1.0 as published found that generation could write
through a symlink or over a hand-written file (including a WIT source), that
`lock --lock` and a symlinked version directory got past the released refusal,
that the generators skipped a symlinked version directory, that lockfile keys
from another package passed outside `--against`, that the release workflow
ignored a failed release check or crates.io lookup, and that the release-freeze
check could be bypassed by a merge or a differently spelled root.

## Acceptance criteria

- [x] generation refuses a symlink, a directory, or an unowned file at an
  expected path before changing anything
- [x] `lock` refuses a `--lock` path inside a released directory and a released
  version directory that is a symlink
- [x] the generators follow symlinked version directories and refuse
  non-canonical version names (W6-011 reverses the first half: no command
  follows a symlinked version directory, so the evidence now names the tests
  that refuse one)
- [x] keys from another package are refused in every mode; parameter-key
  interfaces are identifiers; an unchanged lockfile is not rewritten
- [x] the release workflow fails on a failed release check or crates.io lookup,
  and a CI job lints workflows for masked failures
- [x] the freeze check reads the full history, checks every listing commit,
  resolves the root, and refuses untracked files
- [x] the release check requires the CLI to depend on the released library
