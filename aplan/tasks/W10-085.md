## Why

Audit finding C12 (low).

- `witforge --version` on `main` prints `0.5.0` although 873 source lines differ from the
  tag, so a bug report cannot identify the build.
- There is no `--quiet` or `--verbose`.
- `diff --check` fails on any breaking view; a project that accepts source-breaking but not
  wire-breaking changes in a 0.x minor cannot express that.
- There are no shell completions and no `witforge explain WF1001`.

## Edge cases

- `--version` from a release tag prints the version alone. Any other build adds
  the commit, and says when the tree had local changes.
- A build with no Git data: `cargo install` from crates.io, a source archive, and
  the verification build of `cargo package`. The build script must not fail
  there, and such a build prints the version alone.
- No timestamp in the binary, so builds stay reproducible.
- `--quiet` removes notes and summaries. It removes no error, and nothing from a
  JSON or SARIF report.
- The set of gating views defaults to all of them, which is today's `--check`.
  An unknown view and an empty set are usage errors. The decode view of `W10-097`
  joins the same option, and the Action's `diff-check` input maps onto it.
- Completions come from the argument definitions, so they cannot fall behind. If
  that needs a new dependency, it passes `cargo deny` and builds on the minimum
  supported Rust version.
- `explain` needs the text at run time. `diagnostics.md` is under `docs/design`,
  which is not in the published crate. Keep the explanations in the source and
  generate the document's table from them, or the reverse; one source either way.
- `explain` with an unknown code is a usage error.
- The test that every code has an entry is the one `W10-079` needs.

## Acceptance criteria

- [x] `--version` shows the commit for a build that is not from a release tag
- [x] `--quiet` suppresses notes; exit codes are unchanged
- [x] `diff --check` accepts the set of views that gate
- [x] completions for bash, zsh, and fish can be generated
- [x] `explain` prints the `diagnostics.md` entry for a code, and a test asserts every code
      the tool can emit has an entry
