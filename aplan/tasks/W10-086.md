## Why

Audit findings E5 and F5 (medium).

- `resolveVersion('', ref)` returns `latest` for any ref that is not a version tag
  (`action/index.js:29-38`, `149-150`). A consumer who pins the Action to a commit SHA, as
  GitHub's hardening guide recommends, runs whichever binary is newest that day: the pin
  fixes the JavaScript and not the tool.
- The Action cannot run `check --against`, the release-freeze check, or `--format sarif`,
  and emits no workflow annotations. The documented snippet therefore cannot express the
  check the evolution guide asks for.
- The documented snippet (`diff-old: wit/v0.1`, `diff-new: wit/v0.2`) fails on this
  repository's own `examples/evolved`, because `diff-check` defaults to true and that
  example has a source-breaking change (reviewer-run with the commands the Action would
  plan). Today the failure is hidden by `W10-039`.
- `diff-check`, `version`, `project`, and `github-token` are documented only in
  `docs/design/action.md`, which `docs/_config.yml` excludes from the site.
- The platform map has no `linux/arm64`; the temporary directory is never removed; downloads
  are not retried; inputs are validated after the download.

## Acceptance criteria

- [ ] a ref that is not a release tag installs the version recorded in the Action's own tree
      at that ref, or fails asking for `version`; it never silently installs `latest`
- [ ] inputs exist for `against`, the freeze check, and the report format; a failing check
      produces annotations or an uploaded SARIF file
- [ ] inputs are validated before anything is downloaded; the scratch directory is removed
- [ ] every input is documented on the public site, with a snippet that passes on
      `examples/evolved` and one that shows a failing gate
- [ ] `node --test action/test.js` covers version resolution for a tag, a SHA, and a branch

## Why it is untestable

The Action is JavaScript run by `node --test` and the hosted runner; no configured cargo
runner lists its tests.
