## Why

The emitted `.proto` files currently carry no language-specific file options (`go_package`, `java_package`, `java_multiple_files`, `java_outer_classname`, `csharp_namespace`). Go consumers cannot compile emitted `.proto` files with `protoc-gen-go` without per-file `M` mapping flags, and Java/C# consumers get default package/namespace placement instead of idiomatic module layout. Supporting opt-in, strictly non-wire file options is the first step of Stage 1 polyglot readiness ahead of `W11-034` and `M-p13`.

## Decision

Owner decision recorded on 2026-11-26 (unblocked ahead of `W10-001` as strictly additive `0.x` polyglot Stage 1 work):

- Add an additive `#[non_exhaustive]` `ProtoOptions` struct (without `Copy`, with `Default`/`new()`/builder methods) and additive `plan_with_options`, `plan_with_released_and_options`, `generate_with_options`, `check_with_options`, and `emit_major_with_options` entrypoints in `witforge::emit::proto`, keeping all existing `0.7.0+` signatures unchanged and updating `docs/design/public-api-inventory.txt`.
- Expose canonical kebab-case CLI flags (`--go-package`, `--java-package`, `--java-multiple-files`, `--java-outer-classname`, `--csharp-namespace`) on `witforge proto` and matching `[project.<name>.proto]` keys (plus optional per-package overrides under `[project.<name>.proto.packages."ns:name"]`) in `witforge.toml` (`#[serde(deny_unknown_fields)]`).
- Keep default `.proto` output byte-for-byte unchanged when no file options are configured.
- File options never affect wire identity, lockfile keys, `wire.lock`, or `diff --check=wire,decode` verdicts.
- Validate option values using language-appropriate rules (allowing `import/path;pkg_alias` for `go_package`, while rejecting `;`, control characters, or invalid identifiers in `java_package`, `java_outer_classname`, and `csharp_namespace`), reusing existing structured diagnostic codes (`WF9001`/`WF9003` for CLI/config errors, `WF2001` for contract/generation collisions).

## Edge cases

- Multiple majors (`v1`, `v2`) and `deps/` dependency `.proto` files (including `DepLayout::is_disambiguated` cross-major pinned deps) derive deterministic, collision-free per-file values from a configured prefix (escaping hyphenated/keyword WIT segments cleanly).
- A single shared `java_outer_classname` would collide across multiple `.proto` files inside the same `java_package`: either derive distinct per-file class names when a prefix/template is used or explicitly refuse colliding outer class names within one `java_package`.
- Emitted `.proto` files with all five file options enabled must continue to compile cleanly through `protox` 0.10, `prost-build` 0.14, `pbjson-build` 0.9, and `witforge-build` without altering Rust module paths or `witforge glue`.
- `buf breaking` with default rules flags changed file options once if a consumer opts in later; document that clearly in `docs/guide/non-rust.md`.
- Existing fixtures emit zero file options so `ci/check-buf-history.sh` and existing golden tests remain unchanged.
