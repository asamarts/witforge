## Why

The CLI is growing from two commands into `check`, `lock`, and later emitter
subcommands, with `--first`, `--against`, `--released`, and `--check`. Manual
parsing has already produced help/flag edge cases.

## Acceptance criteria

- [x] `clap` parses `check` and `lock` with useful errors and a subcommand shape ready for emitters
- [x] `--first`/`--against` are mutually exclusive
- [x] released-directory refusal uses exit 2
- [x] exit codes and no-write-on-error are covered by CLI tests
- [x] existing `check`/`lock` behavior is preserved
- [x] emitter subcommands are wired by W3-003, W4-007, and W4-006, not here
