## Why

Standard protobuf generators do not enforce `witforge`'s narrow-integer ranges, Unicode `char` scalar checks, required `optional` presence, closed enums, selected oneofs, fixed-length `list<T, N>` exact lengths, `map<K, V>` key validation, or wrapper-state rules. To support both external `protoc`/`buf` consumers and the built-in polyglot checked glue emitters in `M-p13` (TypeScript, Python, Go, Java, C#), `witforge` needs a deterministic, language-neutral conformance profile and fixture bundle proven against its own Rust glue.

## Decision

Owner decision recorded on 2026-11-26 (unblocked ahead of `W10-001` as Stage 1 polyglot foundation work):

- Define a versioned, language-neutral conformance fixture manifest format (`conformance_version = 1`, deterministic JSON carrying base64 protobuf binary payloads, proto3-JSON payloads, expected accept/reject outcome, expected `GlueError` category, and target message/function identity).
- Implement an opt-in fixture generator (`witforge conformance` / `witforge::conformance`) covering all 13 rows of the WIT decode profile in `docs/guide/non-rust.md` without imposing any runtime or Protovalidate dependency on emitted `.proto` files.
- Keep Protovalidate annotations deferred unless a real external consumer proves a need beyond checked glue and conformance fixtures.
- Prove every generated valid and invalid conformance vector mechanically against `witforge`'s own compiled Rust `prost` + `pbjson` glue in `cargo test`.

## Acceptance criteria

- [ ] Specify the versioned language-neutral decode conformance profile and fixture bundle schema (`conformance_version = 1`) in `docs/design/conformance.md` and `docs/design/emitters.md`
- [ ] Implement deterministic conformance fixture generation covering all 13 decode-profile categories: narrow integer bounds (`u8`/`u16`/`s8`/`s16`), `char` scalars/surrogates/`>0x10FFFF`, required `optional` presence, `option<T>`, closed enums (zero and unknown), variant/result unset `oneof` and wrapper states, `list<T>` nested wrappers, `list<T, N>` (`N-1`/`N`/`N+1`), `map<K, V>` scalar/char keys, flags, and function request/response envelopes
- [ ] Prove every generated valid vector round-trips cleanly and every invalid vector fails with the expected `GlueError` kind through `witforge`'s compiled Rust glue in both binary protobuf and proto3-JSON forms
- [ ] Keep default `.proto` output and all validation/runtime dependencies strictly opt-in (zero changes to default emitted schemas)
- [ ] Document the conformance workflow for external non-Rust consumers and `M-p13` polyglot emitters in `docs/guide/non-rust.md`
