## Why

Standard protobuf generators do not enforce witforge's narrow-integer ranges, required presence, closed enums, selected oneofs, or wrapper-state rules. Documentation is the immediate interoperable baseline; a real non-Rust adopter must determine whether comments, portable fixture bundles, opt-in Protovalidate annotations, or another mechanism reduces integration errors without imposing a runtime or schema dependency on every consumer.

## Acceptance criteria

- [ ] measure one independent non-Rust implementation against valid and invalid binary and proto3-JSON cases
- [ ] define a versioned, language-neutral decode profile and fixture format if the adopter needs generated conformance assets
- [ ] evaluate generated field comments, fixture bundles, and opt-in Protovalidate annotations against determinism, dependency, and compatibility constraints
- [ ] keep all validation imports and runtime requirements opt-in
- [ ] implement and test only the smallest mechanism justified by observed adopter failures, or record a decline with a concrete revisit trigger
