## Why

Standard protobuf generators do not enforce `witforge`'s narrow-integer ranges, Unicode `char` scalar checks, required `optional` presence, closed enums, selected oneofs, fixed-length `list<T, N>` exact lengths, `map<K, V>` key validation, or wrapper-state rules. To support both external `protoc`/`buf` consumers and the built-in polyglot checked glue emitters in `M-p13` (TypeScript, Python, Go, Java, C#), `witforge` needs a deterministic, language-neutral conformance profile and fixture bundle proven against its own Rust glue.

## Decision

Owner decision recorded on 2026-11-26 (unblocked ahead of `W10-001` as Stage 1 polyglot foundation work; depends on `W11-039` so the committed conformance `.proto` fixture carries `go_package`/`java_package`/`csharp_namespace` file options for `M-p13` language harnesses):

- Define a versioned, language-neutral conformance fixture manifest format (`conformance_version = 1`, deterministic JSON carrying base64 protobuf binary payloads, proto3-JSON payloads, expected accept/reject outcome, direction `decode` vs `encode`, expected `GlueError` category, and target message/function identity).
- Scope the fixture generator to a canonical, comprehensive built-in WIT conformance contract (covering all 13 decode-profile rows + `deps/` foreign types and functions) exported via an additive `witforge::conformance` module and `witforge conformance --out <DIR> [--check]` CLI command (zero new runtime dependencies in `crates/witforge` by using small pure-Rust wire/base64/JSON encoders, matching `inspect.rs`).
- Keep Protovalidate annotations deferred unless a real external consumer proves a need beyond checked glue and conformance fixtures.
- All new public library types/options are `#[non_exhaustive]` and additive over `0.7.0+`; update `docs/design/public-api-inventory.txt` and `docs/guide/reference.md`.

## Acceptance criteria

- [x] Specify the versioned language-neutral decode/encode conformance profile and fixture bundle schema (`conformance_version = 1`) in `docs/design/conformance.md` and `docs/design/emitters.md`
- [x] Implement deterministic pure-Rust conformance bundle generation (`witforge::conformance` + `witforge conformance --out <DIR> [--check]`, zero new runtime crates in `crates/witforge`) covering: all 13 decode-profile rows, `deps/` foreign types/functions, 64-bit integers beyond `2^53 - 1` (`u64::MAX`, `i64::MIN`/`MAX`), supplementary-plane `char` (`U+1F680`, `U+0000`, `U+D7FF`, `U+E000`, `U+10FFFF`) and multi-byte UTF-8, `f32`/`f64` `NaN`/`Infinity`/`-Infinity`/`-0.0`, and encode-side (`toProto`) rejection vectors for languages lacking native narrow/unsigned/scalar-char types
- [x] Prove every generated valid vector round-trips cleanly and every invalid vector fails with the expected `GlueError` kind through `witforge`'s compiled Rust `prost` + `pbjson` glue in both binary protobuf and proto3-JSON forms
- [x] Keep default `.proto` output and all validation/runtime dependencies strictly opt-in, update `docs/design/public-api-inventory.txt`, and document `witforge conformance` in `docs/guide/non-rust.md` and `docs/guide/reference.md` (passing `reference_guide_documents_every_cli_command_option_and_config_key`)
