## Why

The landing page at `https://asamarts.github.io/witforge/` is the first impression for Rust and platform engineers evaluating witforge. Unlike `ayaml` (whose landing page centers on YAML parser benchmarks), witforge's core value is contract integrity: compiling one hand-written WIT package with an append-only wire lockfile into deterministic Rust, Protobuf, JSON Schema, checked glue, Markdown reference docs, version adapters, and compatibility diff reports. The homepage should communicate that architecture and prove it with real generated code within seconds, in clear, natural engineering prose.

## Why it is untestable

This task creates Astro marketing components and inline SVG diagrams whose layout, clarity, and visual hierarchy cannot be enforced by `.aplan.yml`'s Rust Cargo tests. Snippet drift against `examples/`, SVG accessibility attributes, and zero-em-dash rules are mechanically checked by `site/scripts/check-links.mjs` in `W12-008`.

## Decision

Decided by the owner on 2026-11-25:

- Follow the sleek, modern structural rhythm of `asamarts/ayaml`'s site without cloning it verbatim, using witforge's blue highlight palette and custom SVG logo.
- Optimize all copy specifically for witforge's core use cases, features, and functionality, using clear, natural, readable prose with zero em dashes and zero AI-generated writing patterns.

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Source every landing-page code tour excerpt directly from real committed files in the repository (`examples/single/` and `examples/evolved/`) via a build-time loader (`site/src/lib/examples.ts`) so the homepage never displays hand-invented or drifted output:
  - Primary contract tabs sourced from `examples/single/` (`example:ingest@0.1.0`): `contract.wit`, `wire.lock`, `Plain Rust` (`v0_1.rs`), `Protobuf` (`v0.proto`), `JSON Schema` (`v0_1.schema.json`), and `Rust Glue` (`v0.rs`).
  - Evolution adapter tab sourced from `examples/evolved/` (`example:tasks`, clearly labeled as the two-version evolved example): `Version Adapter` (`convert.rs`), paired with direct links to `witforge doc` and `witforge diff --git-base` in the reference guides.
- Organize the homepage into six crisp, scannable bands:
  1. **Hero + Quick Install**: cobalt eyebrow pill (`WIT-first contract compiler`, dynamic version from `Cargo.toml`, `MSRV 1.88`, `Apache-2.0 / MIT`), concise headline ("One WIT contract. Every stable projection."), clear 2-sentence lede, primary/secondary CTAs (`Quickstart`, `Explore outputs`, `Read docs`), and a tabbed install card (`cargo install`, `cargo binstall`, `GitHub Action`, `witforge-build`) with copy buttons.
  2. **Proof Strip**: four concrete, accurate numbers (`5` deterministic emitters, `4` diff views, `0` runtime deps in default plain Rust, `7` SLSA-attested prebuilt targets).
  3. **Compiler Pipeline Visual (`PipelineDiagram.astro`)**: accessible zero-JS inline SVG styled with CSS variables (light + dark native) tracing `contract.wit` + `deps/` + `wire.lock` through Subset & Lockfile validation into Plain Rust (`+ convert.rs`, `worlds.rs`), Protobuf (`.proto`), JSON Schema (Draft 7 / 2020-12), Rust/prost Glue, and Markdown Docs (`witforge doc`), alongside `diff`, `inspect`, and `freeze`.
  4. **Interactive Output Code Tour (`OutputTour.astro`)**: accessible `[data-tabs]` showcase displaying real verified excerpts from `examples/single/` and `examples/evolved/` with dual-theme Shiki highlighting and copy buttons, with a clear link to `/witforge/outputs/` for full type and evolution matrices.
  5. **Core Guarantees Grid** (6 concise cards): append-only wire lockfile, frozen released versions, 4-view diff with `--git-base` and project policies, portable WIT subset (`char`, fixed lists, maps, `deps/`), zero-dependency default plain Rust (with opt-in `no_std`, `serde`, `Eq`/`Hash`, `TryFrom`), and machine-readable CI (`json`/`sarif`, `inspect` JSON IR, `witforge doc`, GitHub Action, static `musl` with SLSA attestations).
  6. **Scope & Boundaries + Reference Strip**: three clear cards explaining where witforge fits, how non-Rust consumers use protobuf + the decode profile, and how witforge works alongside `wit-bindgen` and Wasmtime, followed by direct reference links (`docs.rs/witforge`, `docs.rs/witforge-build`, `CLI reference`, `Diagnostic codes`, `Migration guide`, `llms.txt`).

## Approach

1. Implement `site/src/lib/examples.ts` to read focused excerpts directly from `examples/single/` and `examples/evolved/` at Astro build time (failing the build immediately if any file or anchor marker is missing).
2. Build `site/src/components/PipelineDiagram.astro` as a clean inline SVG with `role="img"`, `aria-labelledby`, `<title>`, `<desc>`, explicit `viewBox`, generous padding, crisp arrowheads, and CSS variable colors so dark mode adapts cleanly.
3. Build `site/src/components/OutputTour.astro` using Astro's `<Code themes={{ light: 'github-light', dark: 'github-dark' }} />` inside an accessible WAI-ARIA tablist (`role="tablist"`, `role="tab"`, `role="tabpanel"`, Left/Right/Home/End keyboard navigation, and progressive-enhancement no-JS fallback).
4. Assemble `site/src/pages/index.astro` using `BaseLayout.astro`, ensuring every heading, card, and caption reads like direct systems-engineering documentation: short sentences, concrete facts, zero em dashes, zero buzzwords.

## Edge cases

- Long code lines in `OutputTour` or quick-install tabs must scroll horizontally inside the code container without widening the mobile viewport.
- Tab keyboard navigation must move focus and active state cleanly and keep ARIA attributes (`aria-selected`, `tabindex`, `hidden`) synchronized.
- All version numbers in install snippets (`cargo install witforge-cli --version X.Y.Z`, `asamarts/witforge@vX.Y.Z`, `witforge-build = "X.Y.Z"`) must interpolate `WORKSPACE_VERSION` from `site/src/lib/site.ts` so future releases never drift.
- Inline SVG labels must never clip or overlap across desktop and mobile viewports.
- Clearly distinguish the single-version tabs (`examples/single`, `example:ingest`) from the evolved adapter tab (`examples/evolved`, `example:tasks`) so readers are never misled into thinking two different contracts are one.
