## Why

Audit finding B5 (medium). References to a dependency's messages are written without a
leading dot (`proto.rs:764-781`, `1628-1635`). Re-run 2026-11-18: root `acme:example` using
`example:shared` emits

```proto
package acme.example.v0;
import "example.shared.v0.proto";
…  example.shared.v0.TypesThing t = 1;
```

protoc resolves names innermost-first, so `example` binds to `acme.example` and the reference
does not resolve (reviewer-run with protoc; the emitted text was re-run). The reviewer also
found imports emitted for dependencies no message refers to (`proto.rs:676-699`), which
protoc reports as warnings.

## Edge cases

- A root namespace equal to a dependency's namespace segment (`acme:example`
  using `example:shared`, the reproduction), a root package name equal to a
  dependency's namespace, and a dependency whose name equals a segment of the
  root's package.
- Every position that can name a foreign type: a field, a oneof member, a wrapper
  field, and a request or response message.
- References inside one package may stay relative. State the rule and test a
  message whose name equals a package segment.
- A dependency that only a world import or export reaches has no type reference
  and gets no import line.
- A dependency under `deps/` that nothing refers to still gets its own proto
  file, and no file imports it.
- Import lines are sorted, so adding a reference does not reorder them.
- A leading dot changes the text of every dependency fixture's proto file and
  none of its descriptors. `ci/check-buf-history.sh` against the earlier releases
  is the proof, and the changelog calls it a text-only change.
- prost-build's output for the fixtures is unchanged.

## Acceptance criteria

- [x] every cross-package reference is written `.namespace.name.vN.Type`
- [x] an import is emitted only when a reference needs it
- [x] a compile test covers a root package whose name equals a dependency's namespace
