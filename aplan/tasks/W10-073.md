## Why

Audit finding C4 (high, re-run in the first audit pass). A generator deletes files in its
output root that carry its ownership header and are not in the new plan. The Rust, proto,
and glue generators share one header (`// @generated by witforge; do not edit.` at
`emit/rust.rs:16`, `emit/proto.rs:20`, `emit/glue.rs:22`), so:

- `witforge rust wit --out gen` followed by `witforge glue wit --out gen …` deletes the Rust
  files, and the reverse;
- two WIT roots generated into one `--out` delete each other's files.

`emitters.md:36` and `docs/guide/generation.md:56` say the headers are distinct.
Reviewer-read: `resolve_paths` (`main.rs:359-365`) does not check that the `out` values of
one configuration differ.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.

- The header names the generator and the contract's `namespace:name`, and keeps
  the `@generated` token that code hosts recognise. The JSON Schema `$comment`
  follows the same rule.
- A generator removes only files whose header names that generator and that
  contract. A root that holds a file with another generator's or another
  contract's header is refused with exit 2, and nothing is written.
- A file with the old shared header is adopted by the generator that runs, as
  today, and rewritten with the new header on that run. A root that mixes old
  headers of two generators cannot exist, since they have been deleting each
  other's files.

## Edge cases

- Both orders of two generators into one root, and two WIT roots into one root.
- `--check` on a root with a foreign header: the file is reported as belonging to
  another generator or contract, not as an extra file of this one.
- Output paths in one configuration that are equal, nested (`gen` and
  `gen/proto`), or equal after symlinks are resolved (`W10-075`).
- A case-insensitive file system: `Gen` and `gen`.
- A hand-written file whose first line happens to be a generated header, and a
  generated file that was edited by hand.
- A file with no header in the root is left alone, as today.
- Two roots for two majors of one package (the layout `W10-093` documents as
  working) have the same contract name. They need different output roots, and the
  header cannot tell them apart; the check on configured paths is what catches it.
- Every generated file changes its first line once. A consumer's `--check` fails
  until it regenerates. That is one line in the migration section.
- `emitters.md` section 1 and `docs/guide/generation.md` were corrected on
  2026-11-18 to say that the header is shared. They change again with this task.

## Acceptance criteria

- [x] each generator writes a header that names it and its contract, and removes only files
      with that header; a file with the old shared header is adopted and rewritten
- [x] a root that holds another generator's or another contract's files is refused with
      exit 2 before anything is written
- [x] a configuration whose `out` paths coincide or nest is a usage error
- [x] tests cover both orders of two generators and two roots
