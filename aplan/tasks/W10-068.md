## Why

Audit finding D5 (high). Every "generated code does not compile" finding of this audit
(`W10-059` to `W10-066`) passed the existing suite, because:

- golden files are produced by the emitter they test, so they prove stability, not
  correctness;
- only a handful of fixtures are compiled against prost (`emit_glue.rs`, `deps_glue*.rs`,
  `serde.rs`, `e2e.rs`), all with lower-case multi-letter names;
- the examples' generated code is checked for drift but never compiled (the roadmap lists it
  as planned);
- no test states the invariant "`check` passes ⇒ generators succeed ⇒ output compiles".

## Edge cases

- Every entry of the matrix states its expected result: it compiles and round-trips,
  or `check` refuses it. An entry that silently stops being generated would
  otherwise pass.
- Cost. One scratch crate holds many cases as modules and is built once per test
  binary, with a build directory that later runs reuse. Record the measured time
  on a hosted runner and set a budget; the harness also runs in the MSRV job.
- No network beyond the crates already in `Cargo.lock`: the scratch crate resolves
  against the workspace's lockfile, and the schema is compiled with the `protox`
  and `prost-build` versions the existing compile tests use.
- Editions 2021 and 2024 for the scratch crate. `gen` is a keyword only in 2024,
  and rustfmt's default style differs between them (`W10-074`).
- The supported prost-build range (`W10-059`): each release in it is built.
- Names: one-letter words, upper-case words, digits, every Rust keyword including
  the ones that cannot be raw identifiers, and every proto keyword, in each
  position a name can take.
- Shapes: each kind in each position, three levels of nesting, both byte-list
  spellings (`W10-046`), unreferenced named structural types (`W10-060`), and
  types declared in a dependency (`W10-061`).
- The round trip: a plain value to the prost type, to bytes, back to the prost
  type, and back to the plain value; and through proto3 JSON where the fixture
  uses `pbjson`.
- The property generator's contracts are sampled with a fixed seed and a bounded
  count, so a failure reproduces.
- The scratch directory is under `TMPDIR` and is removed on success. On failure
  its path is printed and it is kept.
- Windows: path length of the scratch build, and the linker's time.
- The existing private copies of this logic in `emit_glue.rs`, `deps_glue.rs`,
  and `e2e.rs` move onto the harness, so there is one way to compile generated
  code.

## Acceptance criteria

- [x] one compile-and-round-trip harness takes a WIT directory and builds plain Rust, glue,
      and prost output in a scratch crate; the scratch directory honours `TMPDIR`
- [x] a name matrix (one-letter words, upper-case words, digits, every Rust and proto
      keyword) and a shape matrix (each kind in each position, three levels of nesting,
      dependency-declared types) run through it
- [x] the property generator's contracts run through the harness for a bounded sample
- [x] `examples/*` generated code is compiled and its round trip run in CI
- [x] generated output is also built with `-D warnings`, `cargo doc -D warnings`,
      `-D missing_docs`, and `cargo fmt --check` (see `W10-074`)
- [x] `quality.md` and `conformance.md` describe the harness
- [x] every matrix entry states whether it compiles or is refused by `check`, and the
      harness asserts that statement
