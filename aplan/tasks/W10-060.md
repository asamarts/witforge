## Why

Audit finding B2 (high, re-run in the first audit pass). `type matrix = list<list<string>>`
declared in an interface and used by no field or function gets a glue module that refers to
`WitforgeListOfString`, while the proto emitter creates wrappers only for types reachable
from a member (`proto.rs:232`, `glue.rs:1358-1363`). The generated crate fails with E0425.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.
The proto emitter creates the wrappers that every named `list`,
`option`, and `result` type needs, whether or not a member refers to the type.
Glue then keeps covering every named type, as `emitters.md` section 7.1 says.

The other branch, emitting glue only for what proto emits, needs a reachability
rule shared by two emitters, which is what diverged. It would also make a
dependency's proto file depend on what a root refers to, and two roots that share
a dependency must generate the same file for it.

The schema gains messages for a contract that has such a type. That is additive,
and `buf breaking` accepts it.

## Edge cases

- An unreferenced `list<list<T>>`, `option<list<T>>`, `option<option<T>>`, and a
  named `result`, each nested two deep.
- A named structural type referred to only by another unreferenced one.
- A type that a later minor of the same major starts to use: its wrapper is
  already in the shared proto file, and no name or number moves.
- A type that only one minor of the major declares. The proto file is the union
  for the major.
- A dependency that declares such a type (`W10-061`): its proto file is the same
  whichever root uses it.
- The wrapper of an unreferenced type against a user type of the same name is the
  collision of `W10-050`, and is refused the same way.
- Plain Rust, the conversions, and JSON Schema already cover the type and do not
  change.

## Acceptance criteria

- [ ] the proto emitter creates the wrappers of every named structural type, referenced or
      not, and `emitters.md` sections 4.4 and 7.1 state the rule
- [ ] a compile test covers an unreferenced named `list` and `option`, nested two deep
- [ ] the generated crate of the reproduction compiles, and no proto name or number of
      an existing fixture changes
