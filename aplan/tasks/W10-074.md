## Why

Audit findings B15 (part) and B16 (medium, re-run in the first audit pass). Generated Rust
committed into a consumer's crate fails that crate's ordinary gates:

- four generated files differ under `cargo fmt --check`;
- `#![warn(missing_docs)]` reports generated items;
- a type-only interface gets an empty `pub trait Types {}` and an empty
  `enum TypesMethod { …_UNSPECIFIED = 0 }`;
- a function without a result is emitted as `fn ping(&self) -> ();`.

The only consumer wraps every generated module in
`#[rustfmt::skip] #[allow(warnings, clippy::all, clippy::pedantic)]`. No witforge document
tells an adopter to do that.

## Decision recorded here

Recommendation: make the output clean rather than exempt. Format through one pretty-printer
so `cargo fmt --check` passes, document every public item, emit no trait or method enum for
an interface without functions, and write `fn ping(&self);`. Removing an empty trait is a
source change for a consumer that names it, so it goes into the 0.6.0 migration notes.

## Acceptance criteria

- [ ] generated Rust for every fixture passes `cargo fmt --check`, `clippy -D warnings`, and
      `-D missing_docs` in the compile harness (`W10-068`), or the generator emits the
      attributes itself and the guide says what they are
- [ ] no empty trait or method enum is emitted, or the reason they exist is specified
- [ ] unit-returning functions have no `-> ()`
