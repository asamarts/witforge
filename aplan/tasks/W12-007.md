## Why

`witforge::diagnostic::HELP_BASE_URL` is a SemVer-governed public constant pinned in `docs/design/public-api-inventory.txt` to `"https://asamarts.github.io/witforge/guide/diagnostics.html"`, and `witforge explain <CODE>` plus SARIF `helpUri` reports emit URLs like `https://asamarts.github.io/witforge/guide/diagnostics.html#wf1015`. Likewise, `crates/witforge-cli/Cargo.toml` sets `documentation = "https://asamarts.github.io/witforge/guide/"`, and published releases (`0.1.0`-`0.9.0`) and external bookmarks reference `/quickstart.html` and `/guide/*.html`. Moving canonical documentation to Starlight routes (`/witforge/docs/.../`) must never break a single legacy URL or drop `#wfxxxx` fragments.

## Why it is untestable

This task creates a Node post-build generator (`site/scripts/emit-redirects.mjs`) and static HTML redirect stubs inside `site/dist/` rather than Rust crate logic tested by `.aplan.yml`'s Cargo runners. Unit verification runs through `node --test site/scripts/test-scripts.mjs`, post-build verification runs in `W12-008`, and `W12-009` wires `test-scripts.mjs` into `cargo test`.

## Decision

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Keep `witforge::diagnostic::HELP_BASE_URL` completely unchanged (required by SemVer public API policy).
- Define an explicit, declarative redirect manifest (`site/scripts/redirects.json`) mapping all 16 historical Jekyll paths to their canonical Starlight routes:
  - `/guide/index.html` (serving `/witforge/guide/` and `/witforge/guide/index.html`) -> `/witforge/docs/`
  - `/quickstart.html` -> `/witforge/docs/quickstart/`
  - `/guide/choosing-witforge.html` -> `/witforge/docs/choosing-witforge/`
  - `/guide/contract-authoring.html` -> `/witforge/docs/contract-authoring/`
  - `/guide/generation.html` -> `/witforge/docs/generation/`
  - `/guide/wiring.html` -> `/witforge/docs/wiring/`
  - `/guide/generated-output.html` -> `/witforge/docs/generated-output/`
  - `/guide/non-rust.html` -> `/witforge/docs/non-rust/`
  - `/guide/evolution.html` -> `/witforge/docs/evolution/`
  - `/guide/ci.html` -> `/witforge/docs/ci/`
  - `/guide/reference.html` -> `/witforge/docs/reference/`
  - `/guide/migration.html` -> `/witforge/docs/migration/`
  - `/guide/diagnostics.html` -> `/witforge/docs/diagnostics/`
  - `/guide/json-projections.html` -> `/witforge/docs/json-projections/`
  - `/guide/component-model.html` -> `/witforge/docs/component-model/`
  - `/guide/examples.html` -> `/witforge/docs/examples/`
- Each generated HTML stub must preserve both `?query` and `#fragment` via a synchronous inline script (`window.location.replace(target + window.location.search + window.location.hash)`) because `<meta http-equiv="refresh">` alone drops `#wf1015` in several browsers, while still including an absolute `<link rel="canonical" href="https://asamarts.github.io/witforge/docs/...">`, `<meta name="robots" content="noindex">`, `<noscript><meta http-equiv="refresh" ...></noscript>`, and an accessible fallback link.
- Keep `emit-redirects.mjs` and its unit tests strictly cross-platform (Windows path-separator normalization, `process.env.TMPDIR || os.tmpdir()`, Node stdlib only).

## Approach

1. Create `site/scripts/redirects.json` enumerating all 16 historical Pages paths and their canonical destinations.
2. Implement `site/scripts/emit-redirects.mjs` to validate that every destination page already exists in `site/dist/`, verify no stub collides with a canonical Astro route, and write minimal, valid, self-contained HTML5 redirect stubs into `site/dist/`.
3. Wire `emit-redirects.mjs` into `site/package.json`'s `build` script (`sync:docs && astro build && emit:redirects`).
4. Add unit tests in `site/scripts/test-scripts.mjs` verifying generated stub HTML (absolute canonical link, `noindex`, `window.location.search + window.location.hash` preservation, `<noscript>` refresh, HTML escaping, and zero em dashes).

## Edge cases

- Opening `/witforge/guide/diagnostics.html#wf1015` in a browser must redirect immediately to `/witforge/docs/diagnostics/#wf1015` and scroll to the `WF1015` heading.
- Opening `/witforge/guide/` (no filename) on GitHub Pages serves `dist/guide/index.html`, which must redirect cleanly to `/witforge/docs/`.
- Opening any legacy `.html` URL with JavaScript disabled must still redirect via `<noscript><meta http-equiv="refresh">` and display a clear clickable link.
- `emit-redirects.mjs` must fail the build if a destination route in `redirects.json` does not exist in `site/dist/`.

## Out of scope

- Full post-build verification of all anchor IDs and links across `site/dist/` (`W12-008`).
- Updating `README.md` or `crates/witforge-cli/tests/docs.rs` (`W12-009`).
- Live HTTP checks against deployed GitHub Pages (`W12-011`).
