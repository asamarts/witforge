## Why

Audit finding E9 (low, reviewer-read).

- Release archives contain only the binary; the licence texts are not included.
- There is no `linux/arm64`, Windows arm64, or musl build.
- The crates have no `homepage` or `documentation` key and no `cargo-binstall` metadata; the
  library crate publishes its `tests/` tree.
- `SECURITY.md` relies on private vulnerability reporting being enabled, which nothing
  records or checks, and states no threat model (the tool reads untrusted WIT from pull
  requests and writes files).
- `.private/` is ignored only through the local exclude file, and `.github-account` is
  tracked.

## Why it is untestable

Packaging and repository metadata are proved by the release run and `cargo package --list`.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision:
`linux/arm64` (glibc) is built. A musl build and Windows arm64 are declined for
now, with a trigger to revisit: the first request for either, or a report of the
Action failing in an Alpine container.

## Edge cases

- The Action expects the executable at the root of the archive. Licence files and
  a README are added beside it; the layout does not change, and an Action release
  from before this task still installs a new archive.
- `linux/arm64`: a hosted arm64 runner builds and smoke-tests it natively. Cross
  compilation with an emulated smoke test is the fallback.
- The oldest glibc a binary runs on depends on the image it was built on. State
  the minimum, or build on an older image.
- `cargo-binstall` metadata has to match the asset names
  (`witforge-<version>-<target>.tar.gz`) and the checksum files.
- Excluding the test fixtures from the published library: check that nothing in
  `src` includes one at compile time, and compare `cargo package --list` before
  and after.
- Both crates' packages contain the licence files.
- `SECURITY.md`: the threat model covers untrusted WIT from a pull request, what
  the tool writes and where (`W10-075`), that it opens no network connection, and
  what the Action does with its token. The release checklist verifies that
  private vulnerability reporting is enabled.
- `.github-account` is tracked and names the account that tooling uses. Remove it
  or say why it stays.

## Acceptance criteria

- [x] archives carry the licence files and a README
- [x] `linux/arm64` is built, smoke-tested, and installable through the Action; the
      installation page says that musl and Windows arm64 builds are not provided
- [x] crate metadata is complete and the published crate excludes test fixtures it does not
      need
- [x] `SECURITY.md` states the threat model and the reporting channel is verified
- [x] local-only paths are ignored in the tracked `.gitignore`
