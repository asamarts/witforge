## Why

Audit finding E9 (low, reviewer-read).

- Release archives contain only the binary; the licence texts are not included.
- There is no `linux/arm64`, Windows arm64, or musl build.
- The crates have no `homepage` or `documentation` key and no `cargo-binstall` metadata; the
  library crate publishes its `tests/` tree.
- `SECURITY.md` relies on private vulnerability reporting being enabled, which nothing
  records or checks, and states no threat model (the tool reads untrusted WIT from pull
  requests and writes files).
- `.private/` is ignored only through the local exclude file, and `.github-account` is
  tracked.

## Acceptance criteria

- [ ] archives carry the licence files and a README
- [ ] `linux/arm64` is built, smoke-tested, and installable through the Action; the decision
      on musl and Windows arm64 is recorded
- [ ] crate metadata is complete and the published crate excludes test fixtures it does not
      need
- [ ] `SECURITY.md` states the threat model and the reporting channel is verified
- [ ] local-only paths are ignored in the tracked `.gitignore`

## Why it is untestable

Packaging and repository metadata are proved by the release run and `cargo package --list`.
