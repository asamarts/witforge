## Why

The public documentation site is live, but the repository needs a fresh end-to-end quality review before external outreach. Hosted CI is currently failing, readers need concrete generated-output examples, and all product surfaces should agree on current behavior, boundaries, and release status.

## Acceptance criteria

- [ ] the failing hosted CI jobs are diagnosed from their exact logs and repaired at the cause
- [ ] implementation, public API, CLI, generated output, examples, tests, workflows, packaging, security, and release gates are reviewed for correctness and maintainability
- [ ] every confirmed issue is fixed without speculative feature expansion or warning suppression
- [ ] README shows one or two minimal generated Rust/output examples while remaining concise
- [ ] the documentation site shows representative Rust, protobuf, JSON Schema, and glue output generated by the current release and explains their semantics and limitations
- [ ] public README, site, CLI help, examples, design references, versions, and links are accurate and mutually consistent
- [ ] narrow regression checks and the full local release gate pass
- [ ] the pushed commit's required hosted CI check is green

## Verification

Close on named tests that cover any code behavior changed, plus the repository release gates and observed hosted CI run recorded in the final report.
