## Why

Worlds generated no code in the MVP, and alint's `tests/worlds.rs` reads the WIT
separately because generated code cannot see world roles. An additive shared
worlds module with imports, exports, and explicit direction is the clean option.

## Acceptance criteria

- [x] the need is confirmed by the consumer
- [x] metadata shape is specified without conflating worlds with traits
- [x] generated output is additive and frozen
- [x] tests cover imports, exports, and multiple worlds

## Decision

The alint consumer's `tests/worlds.rs` reads the WIT separately because generated code could not
see world roles. The Rust emitter now adds shared `worlds.rs` metadata: a `World` struct with
name, imported interfaces, and exported interfaces, plus a `WORLDS` constant per version. It is
additive shared output; per-version modules remain frozen. The design is specified in
[`docs/design/emitters.md`](../../docs/design/emitters.md#36-world-metadata).
