## Why

lla has a high-level Rust SDK, native ABI, Wasmtime Component Model path, and protobuf wire contract, while its WIT world transports opaque protobuf bytes. This is a strong architectural match but its maps and recursive TypedValue model exceed witforge 0.4.

## Acceptance criteria

- [ ] pin the reviewed upstream release/commit and map SDK traits, native ABI, WIT world, protobuf envelope, manifests, compatibility checks, and frozen-version policy
- [ ] identify exactly which duplicate definitions or adapters a WIT-first source could remove and which current design choices are deliberate
- [ ] run or statically classify every current protobuf/WIT construct against the witforge subset, including maps, recursion, dynamic values, host imports, batches, and errors
- [ ] evaluate bounded adoption slices that do not require a wholesale Plugin Platform v4 rewrite
- [ ] distinguish witforge feature gaps from lla API remodels and from runtime/package policy outside witforge
- [ ] assess wire-number continuity, version adapters, schema output, plain Rust traits, and cross-host conformance as separate benefits
- [ ] record migration and generated-API risks and a go/no-go recommendation
- [ ] apply the external-adoption protocol: label material claims, decide all four gates, complete the six-dimension matrix, state the falsifier, and choose contact, defer, or no-contact
- [ ] record the canonical outreach path: an lla GitHub Ideas discussion rather than a restricted issue

## Why it is untestable

The output is an external architecture assessment; any accepted compatibility feature or integration needs its own tested task.
