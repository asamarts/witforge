## Why

Standard `protoc --python_out` messages accept out-of-range narrow integers, missing required optional scalars, unknown enum numbers, and unset oneofs silently. Checked Python protobuf glue targeting official `google.protobuf` enforces the exact WIT decode profile with structured `WitforgeGlueError` exceptions.

## Acceptance criteria

- [ ] Implement additive opt-in Python checked protobuf glue (`witforge py-glue` / `[project.<name>.python-glue]` wired into `ensure_distinct_output_roots` and `witforge generate`) targeting official `google.protobuf` (`HasField` presence checks, `json_format` compatibility, per-function request/response helpers, `METHOD` constants, structured `WitforgeGlueError`)
- [ ] Enforce all 13 rows of the WIT decode profile (plus encode-side integer/char/length checks) for both binary protobuf and proto3-JSON payloads
- [ ] Add offline golden/unit tests in `cargo test --workspace --locked`, add a SHA-pinned Python 3.11+ conformance CI job in `.github/workflows/ci.yml` running `W11-034` binary + proto3-JSON vectors, update `docs/design/public-api-inventory.txt`, and document CLI/config keys in `docs/guide/reference.md`
