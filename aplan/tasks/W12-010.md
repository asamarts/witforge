## Why

GitHub Pages for `asamarts/witforge` is currently configured as `build_type: "legacy"` publishing raw Jekyll from `/docs` on `main`. Deploying the new Astro + Starlight site before retiring Jekyll (`W12-009`) guarantees zero downtime and zero 404s. This task adds a pinned, least-privilege GitHub Actions workflow (`.github/workflows/docs.yml`) that verifies the site on pull requests and publishes `site/dist/` to Pages on `main`, switches GitHub Pages to `build_type: "workflow"`, and adds weekly npm Dependabot updates for `site/`.

## Why it is untestable

GitHub Actions workflow execution, OIDC Pages deployment, and repository Pages settings (`build_type: workflow`) live outside `.aplan.yml`'s Cargo test runners. No `cargo test` can fail if `.github/workflows/docs.yml` or the Pages setting is reverted; verification runs through `actionlint`, `shellcheck`, `ci.yml`'s `workflows` job, and a green live `docs.yml` deployment run on `main`.

## Decision

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Sequence `W12-010` **before** `W12-009` so the live site switches cleanly to Astro + Starlight (with all `/guide/*.html` redirects active) prior to deleting `docs/_config.yml` or changing `README.md` links.
- Mirror witforge's existing workflow security posture (`.github/workflows/ci.yml`) and `asamarts/ayaml`'s proven Pages workflow:
  - Pin every GitHub Action (`actions/checkout`, `actions/setup-node`, `actions/upload-pages-artifact`, `actions/deploy-pages`) to an immutable full commit SHA with a version comment. Omit `actions/configure-pages` (not needed when `astro.config.mjs` explicitly declares `site` and `base`, and avoids unnecessary Pages API calls on fork PRs).
  - Set top-level `permissions: {}` and grant `contents: read` on `build`; grant `contents: read`, `pages: write`, and `id-token: write` ONLY on `deploy` (`environment: github-pages`).
  - Gate BOTH `actions/upload-pages-artifact` and the `deploy` job on `if: github.event_name != 'pull_request' && github.ref == 'refs/heads/main'` so neither fork PRs nor manual `workflow_dispatch` runs from feature branches can publish to production Pages.
  - Trigger on `push` to `main` and `pull_request` for paths `site/**`, `docs/**`, `examples/**`, `Cargo.toml`, and `.github/workflows/docs.yml`, plus `workflow_dispatch`.
  - Concurrency: `group: docs-${{ github.ref }}` with `cancel-in-progress: ${{ github.event_name == 'pull_request' }}` so PR builds never block `main` deploys and in-flight `main` deploys are never cancelled.
  - Use Node 24 LTS (matching `action.yml`'s `node24` runtime and npm 11 lockfile compatibility) with `cache: 'npm'` and `cache-dependency-path: site/package-lock.json`, running `npm --prefix site ci`, `npm --prefix site run test:scripts`, `npm --prefix site run build`, and `npm --prefix site run check:links`.
- Add a grouped weekly `npm` Dependabot entry for `/site` in `.github/dependabot.yml` (Monday schedule, matching `cargo` and `github-actions`).
- Update `ci/README.md` (including changing "over both workflows" to cover all three workflows: `ci.yml`, `release.yml`, and `docs.yml`, and documenting the Pages workflow).

## Approach

1. Author `.github/workflows/docs.yml` using verified full commit SHAs for all referenced actions.
2. Add the `/site` `npm` update group to `.github/dependabot.yml`.
3. Update `ci/README.md` to document `.github/workflows/docs.yml` and `site/scripts/check-links.mjs`.
4. Validate locally with `git diff --check` (plus `actionlint` / `shellcheck` if available) and push to `main`, confirming `ci.yml` (`workflows` job + `ci ok`) passes cleanly.
5. Switch `asamarts/witforge` Pages configuration from legacy Jekyll to GitHub Actions workflow via `gh api -X PUT repos/asamarts/witforge/pages -f build_type=workflow` and confirm a green `docs.yml` deploy to `https://asamarts.github.io/witforge/`.

## Edge cases

- `ci.yml`'s `workflows` job runs `actionlint` and `shellcheck --enable=check-extra-masked-returns` across EVERY file in `.github/workflows/`; any quoting error or masked command substitution in `docs.yml` will break `ci ok`.
- Switching GitHub Pages to `build_type: workflow` must happen right as `.github/workflows/docs.yml` lands on `main` so the live site has zero downtime.
- Fork PRs must execute only the read-only `build` job without touching `pages: write`, `id-token: write`, or artifact upload.

## Out of scope

- Post-deploy live visual, accessibility, search, and SARIF redirect audit (`W12-011`).
