## Why

Audit findings B1 (high) and B9 (medium). The glue emitter predicts the identifiers prost
will generate from the `.proto` names, and the prediction is wrong whenever a WIT name has a
one-letter word or an upper-case word. `witforge` exits 0 and the consumer's build fails.

Re-run 2026-11-18 against prost 0.14:

```text
enum x-kind { foo }            proto TYPES_XKIND_FOO; prost TypesXKind::TypesXkindFoo;
                               glue uses ::Foo                              → E0599
record x-y, get-x-y: func      glue ApiXY, ApiGetXYRequest; prost ApiXy     → E0425, E0422
record r { foo-BAR: u32 }      glue foo_BAR; prost foo_bar                  → E0560, E0609
enum e { HTTP, other }         glue ::HTTP; prost ::Http                    → E0599
```

Reviewer-run: oneof modules (`types_xkind` and `types_x_kind`), one-letter interface names,
the method enum's zero value (`AMETHOD_UNSPECIFIED` next to `A_METHOD_PING`), `api-x/r` and
`api/xr` both becoming `ApiXr` (E0428), plain Rust emitting `pub URL` and `mod HTTP_api`
with `non_snake_case` warnings, `interface API` refused by `rust` only, and
`interface error { enum error }` refused because of the empty generated trait.

Code: `proto.rs:1728-1747`, `347`, `503-504`; `glue.rs:1101-1109`, `1140-1144`, `1285-1304`,
`1503`, `1938-1952`; `emit/mod.rs` (`snake_case`, `pascal_case`).

## Decision

Decided by the owner on 2026-11-19: the `.proto` names stay as they are. Glue,
proto, and plain Rust take their identifiers from one conversion module. That
module reproduces the rule prost applies to the `.proto` names, and it is tested
against prost-build's output, not derived again by hand. Two WIT names that map
to one generated identifier are refused by `check`.

The alternative, emitting proto names that prost maps back unchanged, was
rejected: it changes `.proto` message and enum-value names, and with them the
protobuf JSON strings, for contracts that have such names.

## Edge cases

- One-letter words (`x-kind`, `get-x-y`), upper-case words (`HTTP`, `foo-BAR`),
  and digits inside or at the end of a word (`foo2-bar`, `a1`), in a type, a case,
  a field, a function, a parameter, and an interface name.
- prost's enum-value rule: it strips the enum's name from a value when the value
  starts with it, and it compares after its own case conversion. That is where
  `TYPES_XKIND_FOO` in `TypesXKind` becomes `TypesXkindFoo` in the reproduction.
- Oneof module names (`types_xkind` against `types_x_kind`) and the zero value of
  the method enum (`AMETHOD_UNSPECIFIED` beside `A_METHOD_PING`).
- Two WIT names that become one identifier: `api-x/r` and `api/xr`, names that
  differ only in letter case (`W10-055`), and a name against a reserved name of
  the same parent.
- A new minor that adds a name colliding with one already in the major's shared
  proto file. Refused at that minor.
- The conversion is tied to prost-build's default naming. The supported
  prost-build range is documented and each release in it is built by the compile
  matrix (`W10-068`). Options a consumer must leave at their defaults are named in
  the adopter guide (`W10-091`).
- Plain Rust identifiers change for upper-case words (`pub URL` becomes `url`,
  `mod HTTP_api` becomes `http_api`). The per-version modules of released versions
  change with them: a generator-release change, listed in the migration section.
- `--serde` keys follow the Rust spelling, so they change with those identifiers.
  The migration section says so, and `W10-071` specifies the keys.
- JSON Schema names are the WIT names and do not change.
- `interface API` (refused by `rust` only today) and `interface error` with
  `enum error` (refused because of the empty generated trait, which `W10-074`
  removes).
- A dependency's names go through the same module.

## Acceptance criteria

- [ ] glue, proto, and plain Rust take identifiers from one conversion module
- [ ] a compile test against prost covers one-letter words, upper-case words, and digits in
      type, case, field, function, and interface names
- [ ] two WIT names that map to one generated identifier are refused by `check`
- [ ] plain Rust output has no `non_snake_case` or `non_camel_case_types` warnings
- [ ] no `.proto` name of an existing fixture or example changes, and the changelog's
      migration section lists the plain Rust and Serde names that do
