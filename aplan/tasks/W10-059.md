## Why

Audit findings B1 (high) and B9 (medium). The glue emitter predicts the identifiers prost
will generate from the `.proto` names, and the prediction is wrong whenever a WIT name has a
one-letter word or an upper-case word. `witforge` exits 0 and the consumer's build fails.

Re-run 2026-11-18 against prost 0.14:

```text
enum x-kind { foo }            proto TYPES_XKIND_FOO; prost TypesXKind::TypesXkindFoo;
                               glue uses ::Foo                              → E0599
record x-y, get-x-y: func      glue ApiXY, ApiGetXYRequest; prost ApiXy     → E0425, E0422
record r { foo-BAR: u32 }      glue foo_BAR; prost foo_bar                  → E0560, E0609
enum e { HTTP, other }         glue ::HTTP; prost ::Http                    → E0599
```

Reviewer-run: oneof modules (`types_xkind` and `types_x_kind`), one-letter interface names,
the method enum's zero value (`AMETHOD_UNSPECIFIED` next to `A_METHOD_PING`), `api-x/r` and
`api/xr` both becoming `ApiXr` (E0428), plain Rust emitting `pub URL` and `mod HTTP_api`
with `non_snake_case` warnings, `interface API` refused by `rust` only, and
`interface error { enum error }` refused because of the empty generated trait.

Code: `proto.rs:1728-1747`, `347`, `503-504`; `glue.rs:1101-1109`, `1140-1144`, `1285-1304`,
`1503`, `1938-1952`; `emit/mod.rs` (`snake_case`, `pascal_case`).

## Decision recorded here

(a) Emit proto names that prost's conversion maps back unchanged (word-boundary-stable names,
lower-cased words). This changes `.proto` message and enum-value names, and so protobuf JSON
strings, for contracts that use such names. (b) Keep the proto names and make glue reproduce
prost's conversion exactly. Recommendation: (b) for names that exist in released contracts,
because proto names are part of the wire-adjacent surface, with the conversion implemented
once and tested against prost-build's output rather than re-derived; refuse names that
collide after conversion.

## Acceptance criteria

- [ ] glue, proto, and plain Rust take identifiers from one conversion module
- [ ] a compile test against prost covers one-letter words, upper-case words, and digits in
      type, case, field, function, and interface names
- [ ] two WIT names that map to one generated identifier are refused by `check`
- [ ] plain Rust output has no `non_snake_case` or `non_camel_case_types` warnings
- [ ] the changelog states any generated name that changes
