## Why

Audit finding C3 (high, re-run in the first audit pass). The guard that stops a generator
from writing into the WIT root compares lexically normalised paths
(`emit/output.rs:289-311`). With `witlink` a symlink to `wit`,
`witforge rust wit --out missing/../witlink/v0.1` writes generated files into `wit/v0.1`,
next to the contract and its lockfile, and the next run's cleanup can remove files there.

## Edge cases

- The reproduction: `..` after a component that does not exist, through a symlink
  to the WIT root.
- An ancestor of the output directory that is a symlink, an output directory that
  is itself a symlink into the WIT root, and a WIT root that is reached through a
  symlink.
- An output directory that does not exist yet: resolve the deepest ancestor that
  exists, then refuse a `..` in the part that does not.
- Output inside `deps/`, inside a version directory, equal to the WIT root, and a
  WIT root inside the output directory.
- Case-insensitive file systems (`WIT` against `wit`), and on Windows drive-letter
  case, junctions, and verbatim (`\\?\`) paths.
- The guard runs before anything is created, so a refused run leaves no directory
  behind, and it runs for `--check` as well.
- Not covered, and said so: a symlink that is swapped between the check and the
  write. The guard prevents mistakes; it is not a boundary against a local
  attacker.
- Released directories: an output root that is, contains, or is inside a
  directory listed in `released`.

## Acceptance criteria

- [x] the guard compares canonical paths, resolving the deepest existing ancestor when the
      output directory does not exist yet
- [x] tests cover `..` after a missing component, a symlinked ancestor, and a symlinked
      output directory
- [x] the same guard protects `released` directories
