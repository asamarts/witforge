## Why

The v1 lockfile is stringly typed and cannot represent member kind, canonical
types, functions, or parameters. A strict key/entry grammar is the foundation for
all later lockfile behavior.

## Acceptance criteria

- [x] type-member, method, and parameter keys parse into typed scopes
- [x] kind/type matrix is enforced
- [x] v2 header, sorting, and canonical rendering are implemented
- [x] malformed keys, duplicate keys/numbers, and bad types are rejected with line numbers
- [x] v1 files are rejected rather than migrated
