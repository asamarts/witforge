## Why

Audit findings E8 and D5 (medium). The `wit-package` target feeds arbitrary UTF-8 to the
WIT parser, and almost no input gets past it. Read 2026-11-18: `fuzz/corpus` is ignored by
Git, there is no seed corpus or dictionary, and the local corpora from the recorded runs
hold 18, 29, and 5 files of at most 4 bytes. The model, the lockfile reconciliation, and
the four emitters named in `fuzz/README.md` were therefore not reached. The target also
discards emitter results (`let _ = …`), so only a crash would be a finding, and it never
runs automatically.

The property tests generate valid contracts but only with lower-case multi-letter names in
one file, which is why they did not find `W10-059`, `W10-060`, or `W10-077`.

## Edge cases

- The corpus is in the repository, so it stays small: seeds derived from the
  fixtures. `fuzz/corpus` is ignored today; track a seed directory and leave the
  working corpus ignored.
- Keep the raw-text target. It tests the parser's robustness, which the
  structure-aware target never reaches.
- The depth and size limits of `W10-058` come first. Without them the first
  finding is the known stack overflow.
- Invariants: a contract that passes the subset check generates (`W10-067`); two
  runs give identical bytes; a lockfile renders to a fixed point (`W10-053`);
  `diff` of a version with itself is empty; `lock` run twice changes nothing; two
  identical versions convert.
- The target writes a file per input until a contract can be loaded from memory
  (`W10-096`). Its scratch directory is under `TMPDIR` and is removed.
- A crash that the scheduled job finds becomes a test in the stable suite before
  it is fixed.
- The stable-suite property test uses a fixed seed and a bounded number of cases
  in CI, and its regression file is tracked.
- The scheduled job has a time bound per target and uploads the crashing input.
- The nightly toolchain that `cargo fuzz` needs is pinned.

## Acceptance criteria

- [x] a tracked seed corpus built from the fixtures and a WIT keyword dictionary
- [x] a structure-aware target that builds contracts inside the supported subset, including
      one-letter and upper-case words, several files, and dependencies
- [x] the targets assert invariants instead of discarding results: a contract that passes
      the subset check generates without error, generation is deterministic, the lockfile
      re-renders byte-identically, and `diff` of a version with itself is empty
- [x] the same invariants run as a property test in the stable suite
- [x] a scheduled job runs each target for a bounded time and uploads any crash
