## Why

Audit findings E8 and D5 (medium). The `wit-package` target feeds arbitrary UTF-8 to the
WIT parser, and almost no input gets past it. Read 2026-11-18: `fuzz/corpus` is ignored by
Git, there is no seed corpus or dictionary, and the local corpora from the recorded runs
hold 18, 29, and 5 files of at most 4 bytes. The model, the lockfile reconciliation, and
the four emitters named in `fuzz/README.md` were therefore not reached. The target also
discards emitter results (`let _ = …`), so only a crash would be a finding, and it never
runs automatically.

The property tests generate valid contracts but only with lower-case multi-letter names in
one file, which is why they did not find `W10-059`, `W10-060`, or `W10-077`.

## Acceptance criteria

- [ ] a tracked seed corpus built from the fixtures and a WIT keyword dictionary
- [ ] a structure-aware target that builds contracts inside the supported subset, including
      one-letter and upper-case words, several files, and dependencies
- [ ] the targets assert invariants instead of discarding results: a contract that passes
      the subset check generates without error, generation is deterministic, the lockfile
      re-renders byte-identically, and `diff` of a version with itself is empty
- [ ] the same invariants run as a property test in the stable suite
- [ ] a scheduled job runs each target for a bounded time and uploads any crash
