## Why

A non-defaulted added required field makes `rust` conversion generation refuse, but `diff`
only reports `added` and does not state that generation consequence. Conversely, the
conversion-impact note says “generated adapter” even when another change in the same pair
would make generation refuse. Reviewers should see both consequences consistently.

## Acceptance criteria

- [ ] `diff` reports a note when a non-defaulted required addition will make conversion
      generation refuse
- [ ] conversion-impact wording says “when the emitter can generate it” or suppresses notes
      when generation would refuse
- [ ] human, `--json`, JSON diagnostics, and SARIF paths remain consistent and do not change
      compatibility counts or exit codes
- [ ] behavioral tests and the full suite pass
