## Why

The current published Action is pinned to a retired runtime. A patch release must make the
repaired Action and the dependency hardening available before external 1.0 validation.

## Why it is untestable

Publication is proved by the tag workflow, crates.io records, release assets, and a hosted
`uses: asamarts/witforge@v0.4.2` run; no repository-local test can publish or observe them.

## Acceptance criteria

- [ ] versions, changelog, README status, and Action example agree on 0.4.2
- [ ] main CI and the release workflow are green for the release commit and tag
- [ ] both crates, release archives, checksums, docs.rs, and cargo install are verified
- [ ] the published `v0.4.2` Action runs check and configured generation on a hosted runner
