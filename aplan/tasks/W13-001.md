## Why

Implementing five built-in language emitters (TypeScript, Python, Go, Java, C#) without a shared specification and shared Rust helper utilities would duplicate case conversion, keyword escaping, version-module naming, comment-style ownership headers, and decode-profile semantics across emitters.

## Decision

Owner decisions recorded on 2026-11-26:

- Target modern LTS zero-dependency plain baselines: TypeScript 5+/6+ strict ESM, Python 3.11+ stdlib frozen slotted dataclasses, Go 1.22+ stdlib, Java 21 LTS+ records and sealed interfaces, C# 12+ / .NET 8 LTS+ sealed records.
- Target official standard protobuf runtimes for opt-in checked glue: `@bufbuild/protobuf` (TS), `google.protobuf` (Python), `google.golang.org/protobuf` (Go), `com.google.protobuf` (Java), `Google.Protobuf` (C#).
- Roll out Wave 1 (TypeScript, Python, Go) then Wave 2 (Java, C#), delivering plain types + interfaces + checked protobuf glue first per language and cross-version `convert` adapters in `W13-010`.

## Acceptance criteria

- [ ] Publish the normative `docs/design/polyglot-emitters.md` specification (linked from `docs/design/emitters.md`) covering CLI subcommands, `witforge.toml` sections, per-version directory layout, ownership comment headers, keyword/identifier escaping, `deps/` resolution, stability annotations, `GlueError` shapes, and full WIT-to-language mapping tables for TS, Python, Go, Java, and C#
- [ ] Implement shared Rust helpers in `crates/witforge/src/emit/polyglot.rs` (case converters, reserved keyword guards, multi-language ownership header formatting, shared version/dependency path resolution)
- [ ] Add unit tests proving deterministic identifier mapping, collision detection, and ownership-header classification across all five target languages
