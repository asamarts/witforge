## Why

Implementing five built-in language emitters (TypeScript, Python, Go, Java, C#) and the `W11-001` plugin protocol requires two shared foundations that `witforge` does not yet provide:
1. `crates/witforge/src/emit/output.rs` currently rejects nested file paths (`components().count() != 1`) and recognizes only `//`, JSON `$comment`, and `<!--` ownership headers, whereas plugins, Go (one package per directory), Java (nested package dirs), and TypeScript/Python (`v0_1/...` trees, `#` comments, empty PEP 561 `py.typed` marker files) all require nested trees and multi-language header styles.
2. Shared identifier/case converters, keyword collision escapes, `DepLayout` mapping rules, and two-tier CI verification contracts must be defined once instead of duplicated across five emitters.

## Decision

Owner decisions recorded on 2026-11-26:

- Target modern LTS zero-dependency plain baselines: TypeScript 5+/6+ strict ESM, Python 3.11+ stdlib frozen slotted dataclasses, Go 1.22+ stdlib, Java 21 LTS+ records and sealed interfaces, C# 12+ / .NET 8 LTS+ sealed records.
- Target official standard protobuf runtimes for opt-in checked glue: `@bufbuild/protobuf` (TS), `google.protobuf` (Python), `google.golang.org/protobuf` (Go), `com.google.protobuf` (Java), `Google.Protobuf` (C#).
- Keep plain and checked-glue outputs in distinct output roots (matching Rust `rust` + `glue` and `ensure_distinct_output_roots`) so ownership headers stay single-purpose per directory.
- Extend `output.rs` additively (preserving existing `0.7.0+` `GeneratedFiles::insert` flat-file SemVer behavior) with nested POSIX relative-path support, multi-language ownership header styles (`# @generated by witforge ...`, Go `// Code generated by witforge ... DO NOT EDIT.`), case-insensitive/prefix/reserved-name collision refusal, and explicit marker-file allowlisting (such as empty `py.typed`).
- Default `witforge check` must never start rejecting valid `0.9.0` contracts for target-language keywords; every polyglot emitter escapes target keywords deterministically.
- Enforce a two-tier verification contract for `W13-002..W13-013`: (a) offline pure-Rust golden/unit/error tests always run in `cargo test --workspace --locked`, and (b) each language glue task adds an incremental SHA-pinned polyglot CI job in `.github/workflows/ci.yml` compiling and running `W11-034` conformance tests.

## Acceptance criteria

- [ ] Publish the normative `docs/design/polyglot-emitters.md` specification (linked from `docs/design/emitters.md`) covering CLI subcommands, `witforge.toml` sections, plain-vs-glue output roots, per-version and `DepLayout` (`shared`/`per_major`/`disambiguated`) directory layout, ownership comment headers and `py.typed` marker handling, keyword escaping, stability annotations, `GlueError` shapes, two-tier CI verification, and full WIT-to-language mapping tables for TS, Python, Go, Java, and C#
- [ ] Extend `crates/witforge/src/emit/output.rs` additively with nested-tree write/`--check`/diff support, multi-language ownership header classification, marker-file handling, and cross-platform path-safety guards without breaking any existing `0.7.0+` `GeneratedFiles` API
- [ ] Implement shared Rust helpers in `crates/witforge/src/emit/polyglot.rs` (case converters, reserved keyword escaping per language, version/dependency module path helpers) and update `docs/design/public-api-inventory.txt`
- [ ] Add unit tests proving nested-tree write/`--check`/prune/collision/symlink guards, multi-language header classification, and deterministic identifier escaping across all five target languages
