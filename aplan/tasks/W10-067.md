## Why

Audit findings B12 and parts of B9 and B10 (medium). `witforge check` passing does not mean
the generators will accept the contract, so a contract can be locked and released and then
turn out to be ungeneratable.

- Re-run in the first audit pass: a dependency with an unsupported type nothing refers to
  passes `check`; `rust`, `proto`, and `schema` then exit 2 with "named type
  `types/unsupported` is not in the model" (`model.rs:596-599`). Reviewer-run: across two
  dependency packages the generators exit 0 with a dangling Rust alias and a dangling schema
  `$ref`.
- Re-run 2026-11-18: `package example:service@0.1.0;` passes `lock` and `check`; `proto`
  exits 1 with "proto package `service` is a reserved word". protoc accepts `service`,
  `message`, and `option` as package segments (reviewer-run).
- Reviewer-run: `interface API` is refused by `rust` only; proto-name collisions between a
  type and a generated request message are found by `proto` only.

## Acceptance criteria

- [ ] every refusal a generator can make for a contract that passed the subset check is
      either moved into `check` (exit 1, with a code) or removed
- [ ] unsupported dependency items that nothing reaches are skipped by every emitter, never
      an internal error
- [ ] package segments protoc accepts are accepted
- [ ] a property test asserts: `check` passes ⇒ `rust`, `proto`, `schema`, and `glue` exit 0
