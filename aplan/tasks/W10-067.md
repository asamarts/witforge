## Why

Audit findings B12 and parts of B9 and B10 (medium). `witforge check` passing does not mean
the generators will accept the contract, so a contract can be locked and released and then
turn out to be ungeneratable.

- Re-run in the first audit pass: a dependency with an unsupported type nothing refers to
  passes `check`; `rust`, `proto`, and `schema` then exit 2 with "named type
  `types/unsupported` is not in the model" (`model.rs:596-599`). Reviewer-run: across two
  dependency packages the generators exit 0 with a dangling Rust alias and a dangling schema
  `$ref`.
- Re-run 2026-11-18: `package example:service@0.1.0;` passes `lock` and `check`; `proto`
  exits 1 with "proto package `service` is a reserved word". protoc accepts `service`,
  `message`, and `option` as package segments (reviewer-run).
- Reviewer-run: `interface API` is refused by `rust` only; proto-name collisions between a
  type and a generated request message are found by `proto` only.

## Decision

Default chosen while documenting the task on 2026-11-19, not an owner decision.

- `check` does not depend on the target. When it passes, every generator accepts
  the contract, whichever generators a consumer uses.
- A refusal that reflects a real constraint of a target moves into `check` with a
  code: two names that become one identifier, a wrapper collision, an accessor
  collision. A refusal with no such constraint behind it, such as a package
  segment that protoc accepts, is removed.
- An unsupported dependency item that nothing reaches is skipped by every emitter,
  together with every dependency item that refers to it.

## Edge cases

- A refusal that needs more than one version directory cannot come from a
  single-directory `check`: a conversion that cannot be generated, a pinned
  dependency graph that differs, a lockfile that does not continue its
  predecessor. Those are reported by `check --against` (`W10-051`, `W10-057`) and
  by the whole-root check (`W10-084`). The property is therefore stated twice: for
  one version, `check` passing implies that the four generators exit 0; for a
  root, `check --against` passing for every neighbouring pair implies it.
- The inventory comes first: every place an emitter or `emit/versions.rs` returns
  a contract error, each marked as moved, removed, or cross-version. It is kept
  where the next added refusal will be noticed.
- Known cases, each with a test: an unsupported dependency type that nothing
  refers to (exit 2 today); two dependency packages where the generators exit 0
  with a dangling alias and a dangling `$ref`, which is worse than a refusal;
  `package example:service`; a type against a generated request message
  (`get-request` beside `get`); two dependency packages that map to one module
  (run 2026-11-19: `rust` and `glue` refuse, `check`, `proto`, and `schema`
  accept); the collisions of `W10-050`, `W10-059`, and `W10-063`; and the limits
  of `W10-058`.
- Package segments that are proto keywords (`service`, `message`, `option`,
  `enum`, `package`, `import`). Once accepted, the Rust module path that glue
  writes for such a package needs the escaping of `W10-063`.
- An error caused by an option is not a contract refusal and is outside the
  property: a bad `--plain-root`, or a `--serde` restriction.
- After this task an exit 2 from a generator on a contract that `check` accepted
  is a bug. The property test counts it as a failure.
- The property test needs contracts with dependencies, worlds, one-letter words,
  and upper-case words. It shares its generator with `W10-089`.
- A released directory that today's `check` accepts and the extended one refuses
  is frozen. The cases are those of `W10-045` and `W10-047`, and the migration
  section names them.

## Acceptance criteria

- [x] every refusal a generator can make for a contract that passed the subset check is
      either moved into `check` (exit 1, with a code) or removed, and the inventory of
      those refusals is recorded
- [x] unsupported dependency items that nothing reaches are skipped by every emitter, never
      an internal error
- [x] package segments protoc accepts are accepted
- [x] a property test asserts: `check` passes ⇒ `rust`, `proto`, `schema`, and `glue` exit 0
