## Why

Real WIT projects import packages from `wit/deps`; the current subset refuses foreign types
and interfaces, limiting witforge to self-contained contracts.

## Acceptance criteria

- [x] package identity and foreign type references are modeled explicitly
- [x] `wit/deps` packages resolve through the standard WIT dependency layout
- [x] generated Rust/protobuf references distinguish local and dependency packages
- [x] lockfiles, canonical types, and release freezes define foreign-package behavior
- [x] tests cover a local package importing a pinned dependency and a missing/ambiguous dependency
- [x] the design records that multi-package workspaces and registries are separate later work
