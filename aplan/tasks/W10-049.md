## Why

Audit finding A5 (high). The `# witforge order v1` section is what makes a reorder of a
released record's fields or a function's parameters a detected source-breaking change. The
reader accepts a lockfile whose order lines are missing, and `check --first` skips the
comparison (`lock.rs:478-485`, `565-567`, `295-301`, `627`; `main.rs:495-515`).

## Reproduction (re-run 2026-11-18)

```wit
// wit/v0.1/c.wit (released)
package ex:t@0.1.0;
interface api {
  record r { a: u32, b: string }
  get: func(x: u32, y: string) -> r;
}
// wit/v0.2/c.wit: fields and parameters reversed
//   record r { b: string, a: u32 }
//   get: func(y: string, x: u32) -> r;
```

Copy `wit/v0.1/wire.lock` to `wit/v0.2/`, delete the `# order ex:t/api/r …` and
`# order ex:t/api#get …` lines, and run the default `witforge check wit/v0.2`,
`witforge rust wit`, and `witforge proto wit`: all exit 0, and the generated trait is
`fn get(&self, y: String, x: u32)`. Only `check --against` (exit 1) and a direct `diff`
(`reordered`) notice.

Also re-run: `check --first` passes with a stale order section that the default `check`
rejects. Reviewer-run: an order line rewritten to a subset of the members, to names that are
not members, or for a parent that does not exist is accepted when its fingerprint is valid.

## Edge cases

- Which parents have a line: a type, an interface, or a function with at least one
  live member, including a parent with exactly one. A parent whose members are all
  reserved, a function without parameters, and an interface without functions have
  none (`lockfile.md` section 16).
- A released lockfile without any order section stays accepted and is not
  rewritten; the section did not exist when it was released. A released lockfile
  that has the marker and an incomplete or wrong section is refused.
- An unreleased lockfile without the section fails `check` with "run
  `witforge lock`". Today it is canonical; this is the behaviour change to state
  in the specification and the changelog.
- A line for a parent that exists, with a valid fingerprint, naming a subset of
  the members, a non-member, or the members of another parent.
- A line for a parent that does not exist, and two lines for one parent.
- The reproduction's path: delete the lines, reorder, and run each of the default
  `check`, `check --first`, `check --against`, `rust`, `proto`, `schema`, `glue`.
- `diff` on direct endpoints deliberately accepts a stale order so that it can
  report `reordered` (`diff.md`, "Selecting the compared versions"). Keep that. A
  section that is structurally wrong (a non-member, an unknown parent) is refused
  there too.
- A released lockfile checked out with CRLF line endings.
- Order discrepancies are reported together with the other discrepancies of the
  run (`W10-052`), and the syntax of a parent is the reader's (`W10-053`).

## Acceptance criteria

- [x] a lockfile must carry exactly one order line for every parent that has ordered members,
      naming exactly that parent's live members; a missing, extra, or wrong line is exit 1
- [x] `check` runs that validation in the default, `--first`, and `--against` modes
- [x] the generators refuse a lockfile that fails it
- [x] tests cover a deleted line, a subset, a non-member, and an unknown parent
