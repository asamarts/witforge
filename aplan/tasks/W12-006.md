## Why

The site refresh is only as strong as the guides behind it. An audit of the 17 published Markdown files under `docs/` (`docs/index.md`, `docs/quickstart.md`, and 15 files under `docs/guide/`) found 31 em dashes across seven guides (`docs/quickstart.md`: 3, `docs/guide/ci.md`: 1, `docs/guide/evolution.md`: 6, `docs/guide/json-projections.md`: 3, `docs/guide/migration.md`: 14, `docs/guide/reference.md`: 1, `docs/guide/wiring.md`: 3), plus incremental additions from 0.1.0 through 0.9.0 that benefit from a cohesive readability pass so every guide reads clearly, directly, and naturally inside Starlight.

## Why it is untestable

Prose clarity, readability, and natural human tone cannot be verified by `.aplan.yml`'s Rust Cargo runners, though every executable command and code excerpt embedded in `docs/` stays regression-tested by existing Rust and Node suites (`docs.rs`, `distribution.rs`, `diagnostics.rs`, `reference_doc_tests`, `action/test.js`, and `ci/check-version-references.sh`), and the mechanical zero-em-dash check is enforced in `W12-008` and `W12-009`.

## Decision

Decided by the owner on 2026-11-25:

- Optimize all documentation content for clarity, readability, and intuitive coverage of witforge's core use cases, features, and functionality.
- Remove every em dash and eliminate any AI-generated prose patterns or clichés so all text sounds natural and direct.

Default chosen while documenting the task on 2026-11-25, not an owner decision:

- Leave `docs/design/*.md` and `docs/aplan-pilot.md` untouched because they are internal/normative design specifications excluded from the public site, traced by existing closed `aplan` tasks (`APLAN018`), and parsed by `crates/witforge-cli/tests/diagnostics.rs:1164`.
- Keep legacy Jekyll YAML frontmatter (`layout: default` / `title: ...`) in `docs/*.md` during this task so legacy GitHub Pages never breaks before `W12-010` switches Pages to workflow deployment (`W12-002`'s `sync-docs.mjs` already strips frontmatter for Starlight; `W12-009` removes the frontmatter cleanly after cutover).
- Replace table-cell em dashes (such as `docs/guide/wiring.md:34-36`) with `n/a` or plain text, and keep all numeric/range punctuation clean and readable.

## Approach

1. Audit and polish all 17 published Markdown files under `docs/` plus `README.md`:
   - `docs/index.md`, `docs/quickstart.md`, and all 15 files in `docs/guide/` (`index.md`, `choosing-witforge.md`, `contract-authoring.md`, `generation.md`, `wiring.md`, `generated-output.md`, `evolution.md`, `ci.md`, `migration.md`, `non-rust.md`, `json-projections.md`, `component-model.md`, `examples.md`, `reference.md`, and `diagnostics.md`).
2. Ensure every 0.9.0 feature is clearly integrated and easy to find across the guides (not merely listed in the migration table): `char`, `list<T, N>`, `map<K, V>`, `witforge doc`, `--eq-hash`, `--try-from`, `diff --git-base`, `[project.<name>.policy]`, `deps sync`, `witforge inspect` JSON IR, `witforge-build`, `no_std`, Draft 2020-12 JSON Schema, and static `musl` archives.
3. Rewrite all 31 em-dash occurrences into natural English using periods, colons, parentheses, or commas as appropriate, and tighten any dense paragraphs into clear, scannable prose with zero AI clichés.
4. Run the full suite of existing doc-coupled tests and `sync:docs` after editing to guarantee zero regressions before closing.

## Edge cases

Respect every strict automated parser guardrail in the repository:

- `docs/quickstart.md` (`docs.rs:232-300`): splits on `\n## Non-Rust consumers`, requires `\n## Supported WIT subset`, allows only `wit` (exact 2), `toml` (exact 1), `sh` (>= 20 witforge commands, zero standalone `#` comments), and `text`, and requires `cargo install witforge-cli --version 0.9.0`.
- `docs/guide/evolution.md` (`docs.rs:351-416`): panics on any fenced block language other than `sh` or `text`, asserts exact counts (`ran == 9`, `edits == 1`, `major_edits == 1`), and matches exact `# Edit wit/v0.2/contract.wit: set the package version to 0.2.0, then change the contract` and `# Edit wit/v1.0/contract.wit` comments.
- `docs/guide/wiring.md` (`docs.rs:464-585`, `ci/check-version-references.sh:128-130`): splits on exact headings `\n## Empty crate to compiling round trip` and `\n## Module roots, dependencies`, asserts exact block counts (`2 toml`, `3 rust`, `1 wit`, `4 witforge`, `1 cargo run --manifest-path my-contract-crate/Cargo.toml`), and requires `cargo install witforge-cli --version 0.9.0`, `VERSION=0.9.0`, and `witforge-build = "0.9.0"`.
- `README.md` (`docs.rs:303-348`, `distribution.rs:180-220`, `ci/check-version-references.sh:124,126,132`): allows only `wit`/`sh`/`rust`/`proto`/`yaml` fences, asserts exact counts (`1 wit`, `1 rust`, `1 proto`), and requires `Current release: **0.9.0**`, `cargo install witforge-cli --version 0.9.0`, and `asamarts/witforge@v0.9.0` with no older matches of those patterns.
- `docs/guide/generated-output.md` (`distribution.rs`): asserts exact fenced excerpts (`4 rust`, `1 proto`, `1 json`) matching `examples/`.
- `docs/guide/diagnostics.md` (`diagnostics.rs`): asserts a 1-to-1 `### WFxxxx` heading match against `witforge::diagnostic::CATALOG`.
- `docs/guide/reference.md` (`reference_doc_tests`): asserts every CLI subcommand (`### \`witforge <cmd>\``), flag, and `witforge.toml` key.
