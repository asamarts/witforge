## Why

`main` is ahead of the published 0.4.4 line. The unreleased work includes a generated
`convert.rs` whitespace fix, the W11-037 stale-lockfile fix, the W11-036 conversion-impact
notes and additive `diff` API, and documentation/CI updates. The public docs and examples
now describe `main` while `cargo install` still produces 0.4.4. The owner must choose whether
this is a 0.4.5 output-alignment patch or a 0.5.0 minor that also publishes the `diff`
improvements, then run the release checklist.

## Decision

Publish **0.5.0** on 2026-11-17. The minor carries the W11-037 stale-lockfile fix, the W11-036
conversion-impact notes and additive `diff` API, the generated `convert.rs` whitespace alignment,
and the documentation/CI updates. Wire numbers, protobuf output, JSON Schema output, and the
generated Rust type/trait surface are unchanged.

## Acceptance criteria

- [ ] record the chosen version and why: 0.4.5 for the generated-output alignment only, or
      0.5.0 for the diff bug fix, notes, and additive API as well
- [ ] align the workspace and CLI versions, `Cargo.lock`, the dated changelog section,
      README/docs status, quickstart, and release checklist
- [ ] run the full release gates, including semver against 0.4.1, historical-generator
      protobuf compatibility, generated output, release freeze, security, MSRV, and aplan
- [ ] require the exact release commit's hosted `ci ok`, then tag, publish both crates,
      archives, checksums, docs.rs, and the published Action smoke
- [ ] update main CI's pinned published Action and record the release run in the changelog
- [ ] move alint to the released version if its generated Rust output changes, and record
      the upstream commit/PR

## Why it is untestable

Release coordination is proved by the tag workflow, crates.io records, release assets,
docs.rs, and hosted Action runs; no repository-local cargo test can publish or observe them.
