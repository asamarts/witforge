## Why

`GeneratedFiles::write` removes stale generated files and then calls `fs::write` directly
for every expected file. A crash or write failure can leave a truncated generated file, and
stale files may already be gone. A truncated file that lacks the ownership header can then
block the next generation run.

## Acceptance criteria

- [ ] each expected file is staged and renamed atomically, so a failed write never leaves a
      partial generated file
- [ ] stale generated files are removed only after all expected writes succeed
- [ ] existing ownership, symlink, non-regular-file, and stale-file checks are preserved
- [ ] a failure-path test (for example an unwritable expected file on Unix) proves previous
      output remains intact
- [ ] `ci/check-generated.sh` and the full workspace suite pass
