## Why

Audit finding C2 (high, re-run 2026-11-18). The CLI prints with `println!`
(`diagnostics.rs:89`, `103`, `107`; `main.rs:723`, `729`), which panics when stdout is
closed, and `lock` prints its `added …` lines before `lock.write_atomic` (`main.rs:567-599`).

```text
witforge diff wit/v0.1 wit/v0.2 | head -0         exit 101, panic message      (5 of 5 runs)
witforge lock wit/v0.1 --first > /dev/full        exit 101, no wire.lock written
witforge lock wit/v0.1 --first | head -1          400-member contract: no wire.lock in 30 of
                                                  30 runs; 6-member contract: 0 of 30
```

A script that pipes `lock` through `head` or `grep -q` gets no lockfile and, without
`pipefail`, no failure.

## Acceptance criteria

- [ ] `lock` writes `wire.lock` before it prints anything
- [ ] a failed write to stdout ends the process with a defined exit code and no panic;
      a closed pipe is not an error for a command whose work is already done
- [ ] tests cover a closed pipe and a full device for `lock`, `diff`, and a generator
